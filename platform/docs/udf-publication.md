# UDF编译与集成的独立执行和发布

本批实现与隔离验收完成。原本UDF编译直接写入源码目录，集成在启动求解前修改工作副本controlDict；失败或取消仍可能留下配置修改与半成品。本地文件存储入口现接入`udf.build@1`和`udf.integrate@1`，输入封存、编译/加载/求解在独立副本执行，验证成功后才发布结果与controlDict。S3路径保留原流程，仍需迁移。

## 当前实现

固定Windows worker通过所属`udf_run`原生子执行启动WSL非root进程，绑定发行版、OpenFOAM环境、模式、UDF名称、运行路径、执行标识与代码摘要。Linux目录按执行UUID独立创建。完整用户输入被复制，运行元数据排除；复用MPI原生文件校验函数时单独记录并验证该依赖文件的摘要。

构建在本次Linux副本中清理旧库、当前WM_OPTIONS对应的Make缓存及lnInclude，再真实调用wmake libso。这样复制输入产生的新时间戳不会让旧对象文件误判为最新。检查本次生成的本地ELF库，并使用对应OpenFOAM预加载库实际执行ctypes.CDLL，记录工具、库及日志摘要。用户工作副本的旧库在本次发布成功前保留。

集成封存已有库，在副本中动态加载后，仅按预先生成的文本修改controlDict，再实际执行icoFoam。原有functions块通过既有解析器插入，不重新序列化或提前修改工作副本；重复类型/名称仍拒绝。检查加载错误、求解结束日志、最后输出时间及VTK读取的实际内部/边界场。编译和集成的成果分别使用按模式/名称/运行路径区分的发布通道。

发布验证原始源码、工程输入、动态库与控制文本，并将文件变化/删除纳入不可变版本及哈希条件覆盖计划。来源、旧库、controlDict或结果目标被用户修改时不覆盖。后续作业可以引用当前或历史结果。已创建Job在启动身份验证失败时仍返回Job ID，保留原始准备身份和实际停止证据。

幂等重放在当前文件和写入占用校验之前返回原Job。真实持久校验占用期间，即使源码/库已缺失，原构建和集成请求仍可重放；新请求保持validation_busy拒绝且不创建多余Job。
