## 先分配额度，再取得文件写锁

入口完成原有访问权限和路径检查后，在算例写锁与业务 SQL 写入之前取得账户额度。额度上下文覆盖写锁内的旧事务恢复、本次 before/after 副本、文件正文、caseDict 历史、逻辑 HEAD 和额度记录本身，并持续到原有 SQL 提交及 `finish_committed` 清理结束。所有这些 S3 PUT 仍通过逐笔长度检查和永久条件记录；失败、取消和进程退出沿用已有账户额度关闭与恢复协议。

只检查新正文长度不能保证操作可完成。例如剩余 64 KiB、保存 32 KiB 正文时，事务副本、HEAD 及恢复记录还需要额外空间。本次检查要求总物理占用不能突破限额，额度耗尽的操作保留必要证据，恢复额度后能够回滚到原内容。删除也可能需要 before 副本和新版本，因此同样受额度限制。

这里没有提前提交业务事务。正常保存后按原有顺序提交并清理；几何脚本的自动预览在文件额度结算之后才调用，避免把文件预留带入新的 Job 资源分配。预览交接检查使用受控 launcher 验证上下文已经退出，不将其计为真实求解器验收。

## 共享编辑计入实际所有者

`hold_case` 从算例的工作区读取所有者，再取得该账户额度。已有共享权限检查仍由入口完成；这个帮助函数本身不授予访问权限。普通保存与单次上传的正文预检也改为检查实际所有者，而不是当前编辑者。

因此，成员自己的额度为零而工作区所有者仍有空间时，已获授权的成员仍可保存；所有者额度为零时，成员保存被拒绝，不向成员账户借用空间。测试通过实际组织成员关系和共享配置访问原有 API，验证预留记录属于所有者。

## 验收与剩余范围

新增检查使用真实启用版本的对象存储和隔离 SQLite/PostgreSQL，逐入口验证额度拒绝不改变内容或物理用量、恢复额度后成功、持久预留结算，以及低空间失败后的恢复。另复用普通文件/caseDict 中断、提交响应中断、取消排空和正常上传/删除场景，检查原有事务行为。

- 本次账户额度只约束接入的 S3 写入。FS 文件事务的 before/after 副本、替换临时文件及节点峰值仍需接入；FS 兼容检查不代表其峰值额度已经实现。
- 读取 API 可能触发隐含恢复，Agent/工具调用、工作流推进、断点上传及其他文件服务也有独立入口，尚不能据此宣称全部写入已覆盖。
- ZIP 导出、备份和其他长文件操作的剩余节点/用户峰值仍属 RB-12。
- 同账户活动额度仍保守占用全部可用空间；锁内长 I/O、期限、公平扫描、未知可变请求和永久历史维护继续由 RB-14/15 跟踪。
- 入口每次都会形成 SQL 预留历史；本次没有增加 TTL 释放或删除恢复记录的捷径。
