# LaTeX 历史源文件下载

2026-11-22，N4-05 补齐 RB-12 和 RB-14 的历史源文件下载路径。界面上的历史源文件操作依然调用 `GET /api/v1/cases/{case_id}/latex/source`。选择发布 ID 可读取该版本留存的源文件，未指定版本时沿用当前发布记录。返回文件名和二进制下载格式与原接口一致。

请求在算例事务内确认访问权限、发布身份和原作业的成功状态。随后结束事务，在有期限的读取池中校验归档清单及成员摘要。服务端只给待发送的源文件正文申请下载暂存，通过已有的下载生命周期释放文件句柄和节点额度。认证 S3 读取固定的归档对象，新 API 的本地目录无需生成整套发布缓存。

## 实际验收

实际 `pdflatex` 编译包含 4,320,015 字节源文件的算例。发布后修改工作区中的可编辑源文件，历史下载仍逐字节匹配原发布。在同一发布上运行旧处理逻辑，源文件读取暂停时独立 SQLite 写入因数据库锁而失败。

| 场景 | 文件系统与 SQLite | 认证 SeaweedFS 与 SQLite |
| --- | --- | --- |
| 读取暂停后写入同一算例 | 通过 | 通过 |
| 历史源文件完整下载 | 4,320,015 B | 4,320,015 B |
| 下载暂存预留及最终关闭 | 4,320,015 B，关闭 | 4,320,015 B，关闭 |
| 实际读取超过期限 | 返回 504，关闭暂存，重试成功 | 返回 504，关闭暂存，重试成功 |
| 非法历史路径和原 PDF 下载 | 404，PDF 可读 | 404，PDF 可读 |

两组暂存都使用原有的 1 MiB 内存转存阈值。认证 SeaweedFS 使用新 API 的空缓存，从读取开始到下载完成，归档清单均未被复制到该 API 的本地目录。首次测试在 HTTP 正文到达后立即查询清理标记，复跑改为等待 ASGI 下载收尾。实际编译和存储验证没有模型环节。 [文件系统回执](../../tmp/N4-05-latex-source-20261122/fs.json) · [认证 S3 回执](../../tmp/N4-05-latex-source-20261122/s3.json)

隔离验收脚本默认运行本地文件系统，参数 `--s3` 另起真实认证 SeaweedFS。本轮正式验收边界是历史源文件下载。资源预算上的其他长读取和副本维护仍由 RB-12 和 RB-14 跟踪。 [复验脚本](../../tmp/N4-05-latex-source-20261122/check.py) · [阶段回执](../../tmp/N4-05-latex-source-20261122/validation.json)
