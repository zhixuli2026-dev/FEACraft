# 持久事件驱动的索引更新

2026-11-04。原作业收尾通过内存 `_last_reindex` 和尽力重建更新索引：同一算例30秒内第二次完成会被跳过；API退出或重建失败后没有持久重试。文件监听只在浏览器连接时运行，无法补上无人订阅时的遗漏。

现在已提交的终态 `jobs.updated`、文件 `files.changed`、产物发布/失效及兼容副本完成事件会先经过索引消费者，再确认outbox投递。索引未开启时继续保持未开启，后续手动重建读取全部当前文件。已开启时，重建和事件ID/载荷摘要的消费回执在同一个索引SQLite事务提交。API在提交前退出则一起回滚；提交后但outbox确认前退出，重投读到回执而不再重建。同ID不同绑定/载荷拒绝处理，失败不能被确认成功。

索引消费者不更改Job或工作流状态。业务状态、稳定事件ID/算例序号与outbox继续由原数据库事务提交；已经生效的状态不靠消息再执行一次。索引扫描不持有业务数据库连接。线程工作在取消/超时后排空，另一个消费者通过索引SQLite写锁等待并检查回执。文件读取发生在索引写锁内，与手动重建及增量更新串行，避免先扫描的旧结果晚提交覆盖新索引。缓存投影失败会回滚并让outbox按原策略重试，作业终态不被索引异常改写。

`case_write.coordinate` 在文件写入事务中补充持久刷新事件。提示路径最多256项、UTF-8总长8192字节，始终标记 `rescan:true`；`changes:[]`保留原WebSocket消息形状。它是要求消费者重新读取当前文件的通知，不是重放文件写入的命令，也不是文件补偿日志。文件树按当前存储重新加载，重复刷新不会重复创建文件。原WebSocket轮询仍报告准确的created/modified/deleted变化，并跟踪外部程序的写入。

## 验证

`event_consumer_smoke.py --postgres`最终SQLite/PostgreSQL各5项，另有索引事务5项：

- 无WebSocket订阅时真实完成作业，在投递前终止API；新API补投后能搜索原产物，Job及attempt不重跑。
- 文件写入事务留下待投递刷新事件，新API保存其消费回执。
- 注入索引写入后、提交前故障，索引和回执一起回滚，outbox保留pending；移除故障后重试成功。
- 同算例连续作业的产物均可搜索，不再因30秒内存节流漏更。
- 索引已提交、outbox仍delivering时真实终止API；等待原30秒租约实际到期，新API重新投递同ID，attempts加一而building UUID和单条消费回执保持不变。
- 并发消费仅一方重建；晚到重复事件不覆盖较新索引；相同ID更换载荷被拒绝；未开启索引不被自动创建。

最终故障结果为 `tmp/event-consumer-evidence-ycnhj22_/result.json`。此后产品源码只增加文件刷新载荷的空 `changes` 数组，由实际WebSocket创建/修改/删除与跨用户拒绝回归验证；消费者、数据库事务及投递实现未改变。首轮较小矩阵 `tmp/event-consumer-evidence-nfosclk0/result.json` 与最终矩阵重叠，不累加为额外完成项。

`workflow_state_smoke.py --postgres`验证状态/事件/序号/outbox共同回滚、投递重试/排他租约和状态机。另保留原真实API重启、Job终态、文件协调、索引锁、作业产物搜索和WebSocket兼容检查。一次文件协调测试因后台扫描器先获得Job claim而收到200，旧断言只接受请求自身领取时的409；现在接受这两个合法响应，仍检查取消持久化、门释放后不启动原生进程、输出日志不含载荷。所有原始失败证据保留。

## 边界

专业报告的准备失败发生在Job/attempt提交前，或由原事务回滚处理；没有新任务时不伪造一条失败Job。相应准备/取消/清理行为由文件协调中的准入检查覆盖。

文件与业务数据库之间的原子提交、兼容副本修复属于N2-06/N5-04；本批不能修复已写文件却未提交DB的崩溃。阶段回退、Agent checkpoint恢复属于N5-06。浏览器断线游标、乱序去重及跨API实时扇出属于N6-01；当前本地总线仍由领取outbox的实例通知自己的订阅者。多实例必须使用相同的索引目录才能共享本批的缓存与消费回执；跨主机本地索引副本的分发由部署/多副本任务继续验收。索引排除目录、文本大小及搜索语义保持原策略。

没有业务数据库迁移，也未修改开发数据库或端口8000。派生索引SQLite在打开时补建 `consumed_events` 表。完整53项主线和295项功能范围保持不变，正式OpenAI登录联调仍按用户决定暂缓。

## 2026-11-16 部署补齐

Compose 的 API/worker 现共用 `indexdata:/data/index`，统一 `VIBEFLOW_INDEX_ROOT`，不再依赖各容器的默认本地目录。恢复与实际验收方式见[共享索引部署](shared-index-deployment.md)。上文测试名称属于历史证据，不授权执行未经当前源码审查的旧集合；本次使用独立真实模型入口。跨主机独立索引副本不因共享目录配置而自动完成。
