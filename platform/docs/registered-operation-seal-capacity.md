# 独立工程作业的输入封存

2026-11-22，独立 MPI、UDF 编译与集成、FloTHERM 转换与辅助库编译的入口共用输入封存。实际来源读取、文件复制和对象上传安排在数据库写事务外。最终事务重新核对权限、作业额度和已封存版本，接着绑定作业、专业处理器、成果发布记录和投递。客户端原有的幂等键、作业响应和输出目录规则继续适用。

原实现的本地 SQLite 对照中，MPI、UDF 编译及两条 FloTHERM 入口均在实际复制 40 MiB 时占用写事务，同算例保存返回 409。计算、编译或转换随后成功。新版的本地 SQLite 实测在 40 MiB 复制时，同算例三次保存均返回 200。改动使已准备的输入失效，提交返回 409，原键重试完成 UDF 编译、集成及双进程 MPI。三个已提交的原键均回读原作业。MPI 目录不存在返回 400，UDF 源不存在返回 404，同键的不同请求返回 409。

认证 SeaweedFS 配 PostgreSQL 的三条 MPI、UDF 入口在实际物化 40 MiB 时均允许独立数据库写入，同账户另案保存均返回 200。文件系统配 PostgreSQL 通过绑定完成后源文件等长替换、四秒期限和实际 HTTP 客户端断开。三个失效请求都无需用户清理，超时返回 504，按原键重试完成 MPI。

本地 PostgreSQL 下，FloTHERM 转换和辅助库编译复制期间同算例保存均返回 200，旧快照拒绝后原键重试成功。认证 SeaweedFS 配 SQLite 时，两条入口的 40 MiB 材料准备允许同账户另案保存，转换和编译均完成。已存在的输出目录受到保护。UDF 本轮用例使用 `functionObject`。

认证 SeaweedFS 配 SQLite 在 MPI 的封存已绑定后等长替换实际源对象，提交返回 409，数据库未留下作业，按原键重试完成双进程求解。原批次入口复用相同的封存准备逻辑。
