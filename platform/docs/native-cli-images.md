# 原生图片输入与跨运行时历史：N4-03.g2b3f

2026-11-03。在已交付的[原生分叉](native-cli-forks.md)基础上，Windows/WSL 原生聊天接入图片选择、粘贴、移除、纯图片消息与图片历史。沿用 API / Sign in with ChatGPT 商业部署方向；图片由用户选择的模型配置处理，网站登录不充当模型凭据。

## 输入与存储

`POST /api/v1/codex/sessions/{id}/turns` 和 `turns:stream` 增加 `images: [{name,mime,data}]`，`content` 可空但正文与图片不能同时为空。支持 PNG/JPEG/GIF/WEBP，每条最多 3 张，每张解码后最多 4 MiB；校验 Base64、文件头/MIME 与整批数量后才准入。接口不接受调用者提供的本地路径、远程 URL 或额外图片字段。CLI 后续仍可能拒绝无法解码的损坏图像，文件头校验不等于完整图像解码。

沿用会话归属、凭据版本、权限、算例写入锁和配额检查。幂等摘要包括原正文、原有回合参数，以及每张图片的名字、MIME、大小、SHA-256；改变图片字节或名字后复用同一消息 ID 会冲突。没有图片的旧消息摘要格式保持兼容。

准入时写入两份数据：

| 位置 | 用途 |
|---|---|
| 算例 `.vibeflow/attachments/{随机ID}/image.{扩展名}` | 平台图片历史事实文件，经过现有算例权限读取 |
| `.private-cli/sessions/{session_id}/inputs/{turn_id}/{序号}.{扩展名}` | CLI 原生输入副本，按已选运行时转换本地路径 |

平台事件只保存文件引用、MIME、大小和哈希，不内联 Base64，不暴露私有输入路径。存储键独立于显示文件名，避免文件名脱敏改变历史引用。CLI 使用 `localImage`，所以约 3 MB 图片不需要扩大既有 1 MiB JSON-RPC 消息上限。每次当前回合尝试前核对私有副本路径、大小和哈希；路径替换或内容变化会在启动该回合 RPC 前失败。

图片与用户消息共同在准入流程中登记。明确的提交前失败清理本次新副本；数据库提交开始后若确认丢失，保留图片以免破坏可能已经提交的历史，并通过原消息 ID 查询，不自动重复推理。S3 使用受控存储适配的既有增量同步；在 CLI 快照之后上传的图片不会被旧快照清理掉。

## 线程、分叉与界面

- 纯图片消息在平台保留原始空正文；协议层提供中性的无附加文字说明并附真实图像输入。
- 显式恢复原生线程会继承原生图片历史；真实 WSL CLI 也验证了带图片上下文的原生 fork、无创建时自动推理、分支恢复与父子历史独立。
- 新线程的文字交接保留历史图片文件位置和哈希，明确标记没有嵌入视觉内容；当前消息新选的图片仍以图像输入发送。需要完整原生图片上下文时使用恢复或原生分叉。
- 浏览器支持文件选择与剪贴板图片文件、移除、空正文发送；超过数量或大小时拒绝该批。草稿图片只在内存中，不进入 localStorage/sessionStorage。响应丢失仅查询已持久接受的消息，找到后清空已发送草稿。
- 图片历史采用带身份验证的文件请求与可撤销 Blob URL。刷新后重新读取，API/原生聊天共用展示组件；原生状态轮询不重复下载相同图片。

私有输入副本需要保留，以供原生恢复和派生线程使用。本单元没有自动过期/清理这些副本；管理员持久对账、孤立图片回收与完整资源预算继续 N5/N4-05。共享 WSL UID 仍不构成不同租户之间的 OS 隔离。
