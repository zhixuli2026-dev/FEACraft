# 原生初始化节点预留与 API 退出后的保留

2026-11-08，接续 [初始化用户预留](cli-native-initialization-credit.md)。节点原有普通预留会在所属 API 出生身份已退出时回收；原生初始化可能在 API 退出时仍未完成，因此新增独立保留型节点记录。

## 实现与结清

`cli_node_capacity` 在用户预留和 CLI 会话已提交后、创建原生进程前，在同一节点 OS 锁内检查已有文件、所有预留及目标卷空间，写入会话专属节点记录。它绑定会话 ID、用户、冻结选择哈希、节点根和真实 API 出生身份。计量会完整保留该记录的字节，**不会仅因 API 退出或租约过期就删除**。初始化字节已物化时暂时双计，保持保守。

用户预留绑定升至 v2，增加节点根；原 v1 可只读核验，但不会凭空推断曾有节点预留。收到真实 prepared 回执并在 SQL 提交后，或存在匹配的已验证停止回执时，独立对账核对会话、桥接身份摘要、冻结 profile、节点记录完整字节，再释放节点记录。节点扫描和返回的候选数量均有界；失败、未知或绑定变化保留。

节点预留创建时不持有 SQL 事务，取消等待实际 I/O 排空。结清后仍有节点记录时，删除会话返回 409，避免删除唯一对账证据；核验清理后正常删除会话，私有文件保留。旧 worker 不认识新节点格式时会拒绝计量，因此部署需协调更新全部相关 worker，不能把格式不兼容当作零用量。

## 实际验证

显式入口 `live_llm_cli_node_initialization_acceptance.py --source-profile-id 26 [--postgres --s3]`。最终两套环境各复核 8 项初始化检查，并增加 4 项节点检查，共 **24 项实际基础设施检查**：节点记录在进程创建前已提交；实际终止 API 后不会回收；独立重启 API 继续保留用户及节点额度；正常 prepared 和可信停止均移除节点预留。

节点证据：[SQLite](../../tmp/live-cli-startup-n5jxeune/cli-node-initialization-checks.json)、[S3/PostgreSQL](../../tmp/live-cli-startup-so700icm/cli-node-initialization-checks.json)。每套实际执行一次 API TerminateProcess 和重新启动，重新登录原测试用户；前后节点记录哈希一致、reserved_bytes 都为 133。测试使用未声明算例的 prepare-only 会话，**尚未创建原生进程**。这证明该退出窗口的保留行为，不能替代已创建/已放行原生进程时的猝死恢复矩阵。

另有 **2 项实际文件系统故障检查**：重建与已结清会话精确匹配的残留节点记录，真实 DELETE API 返回 409；核验结清后再删除成功。这是明确的磁盘状态故障，不声称其本身由实际 API 猝死产生。纯协议模拟 0，模拟 LLM 0。

只读访问较早两份隔离 SQLite 的 5 条实际 v1 预留，核验绑定保持可读，未重放历史测试，未修改旧数据库。较早两套节点验收也保留，不重复计入最终检查数。

所有测试 API 已退出，正常/取消场景的实际桥接与 CLI 根核验退出；临时 PostgreSQL 已删除，真实对象存储已停止。每套刻意保留一份未知初始化的用户/节点证据；没有伪造停止回执或为清空统计而删除预留。测试目录与证据保留。
