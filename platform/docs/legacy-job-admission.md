# 旧执行入口与批量提交的持久准入

2026-11-04。此前 CalculiX、SU2、ParaView、MPI、UDF 构建/集成、Flotherm 库构建/转换、旧后处理、PPT 和 PDF 页码共11个入口先保存裸 Job，再直接启动。API 在提交后退出时没有完整规格供恢复；重复 HTTP 请求也可能创建第二个任务。

这些入口现在通过 `legacy_job_admission` 在同一事务中保存提交请求、Job、attempt、执行规格、投递意图和 outbox。提交成功后再投递，容量暂满时保留 queued，由已有恢复器继续检查。原生程序、argv、Windows/WSL 运行方式、输入格式/大小/覆盖限制均保留。MPI 仍选择 nobody 后再建立命名空间；其暂存路径使用独立随机标识。

所有入口接受可选 `Idempotency-Key`，范围为 case 和请求用户，摘要包含入口及完整请求参数。相同键与参数返回原 Job；同键不同请求返回409。查重和新请求准备由同一个 case 数据库锁串行，重放先于文件存在性、目标覆盖、配额检查及准备写入。PPT/后处理依赖 Job ID 的规格只在新分配事务内构造一次。旧后处理任务在算例后来采用注册发布处理器后仍能重放原请求。

批量入口同样接受该请求头。第一项持久请求保存整个批次的幂等键和参数摘要；各项仍分别保存 attempt 和相同的投递组。重放从原提交及投递意图查出批次，核对文件清单中的成员和并发限制，返回原批次，既不再建立成员也不重复写清单。清单缺失或与意图不符时拒绝重放；文件补偿恢复由 N2-06 承接。

## 验收

- `legacy_job_admission_smoke.py --postgres`：SQLite/PostgreSQL各16项。11个旧入口分别经双 API 并发提交，仅生成一个 Job/attempt/意图；重放不修改文件；参数冲突、非法键和跨用户请求拒绝；保留 MPI argv 和 Job ID 关联规格；覆盖处理器切换及批次并发重放。最后真实终止原 API，由新 API 恢复原 PPT attempt，读取实际生成的可编辑 PPTX，输出存在后重放仍返回同一成功任务。
- `job_claim_smoke.py --postgres`：两库各13项。真实双 worker 仅启动一个进程；重试分配新 Job/attempt 编号并保留旧终态和日志；陈旧/伪造回调不覆盖新尝试；回滚和取消不启动进程。
- 隔离 writes profile 的9套既有回归通过：UDF、MPI、PPT、PDF、CalculiX、SU2、ParaView、Flotherm库与转换。MPI实际两子域求解与串行速度场相对差异约 `1.14e-08`。另有最终批量、旧后处理回归各1套通过。专项中的三个软件定位函数只用于验证提交，不冒充求解器执行；实际程序由既有9套回归验证。
- 上一批真实 Redis/arq 重复消息与队列丢失恢复证据仍有效；本批没有更改投递、认领、所有者或 Redis worker 实现。

规范证据：`tmp/mainline-N1-admission-evidence/`。首轮测试误读取公开响应中未暴露的存储前缀，第二轮 MPI argv 断言切片偏移一位；均为夹具错误，原始失败保留。修正后先通过两库各14项，再新增批量/处理器切换检查并通过最终各16项，次数不叠加计功。

## 未包含的工作

本次不把旧输入文件变成不可变快照，也未解决准备文件写入与数据库回滚/崩溃之间的一致性。UDF controlDict、MPI字典、复制的库源码、PPT/后处理配置及批次清单仍须在 N2-06 完成持久补偿；已有未知 queued 记录不猜测命令后重放。专业 handler 的重试/重跑/续算、冻结输入及证据门禁继续 N5-05，工作流恢复继续 N5-06/07；完整调度公平、停机和收尾补交分别归 N4/N5 原任务。

开发数据库、端口8000均未修改，无新数据库迁移。正式 OpenAI 登录联调继续按用户决定暂缓。完整53项主线及295项功能范围保持不变。
