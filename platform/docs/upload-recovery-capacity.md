# 上传状态与显式准备恢复的额度结算

2026-11-06：上传状态读取和封存准备恢复接入工作区所有者的 S3 恢复额度，修复这两个入口在文件协调器中可能写入恢复记录却未申请额度的问题。

上传状态使用 `case_read_capacity.reading`，在范围内构造普通结果，结束读取事务后结算额度。后台 `session_status` 读取通过 `finish_before_cancel` 等待真实线程完成；取消请求不会先释放额度和算例锁，再让线程继续访问存储。已完成上传直接读取持久完成凭据，未完成上传读取远端进度，不修改未来上传字节预留。

显式准备恢复使用 `admitted` 包住协调器和数据库提交。成功恢复、部分记录需要保留等结果先结束数据库事务，再结算额度；没有使用只读范围的回滚语义替代恢复提交。原有封存证明、未知文件保留和条件删除规则不变。

## 验收证据

显式入口 `platform/server/upload_recovery_capacity_checks.py` 使用真实 SeaweedFS、隔离 API、SQLite 和临时 PostgreSQL。它复用已审阅的隔离服务、额度观察和临时数据库助手；不包含模拟 LLM 或 CLI 推理。数据库助手新增可传入验证函数的参数，原默认入口保持。

取消验证直接取消实际状态处理任务，并延迟其真实后台读取线程，确认额度不会提前结算；这不是浏览器断线或服务器进程崩溃测试。恢复验证调用真实提交/输入封存代码后提交或回滚 SQL，没有启动准备中的命令，也没有假造模型输出。外来文件只注入到隔离算例，用于验证不得错误删除的边界。
