# 暂存清理准备中断、提交丢失与并发取消

2026-11-07，接续[原始下载暂存清理](sandbox-staging-cleanup.md)。生产实现修复了准备清单和清理标记写入中断后无法继续的问题。没有改变清理范围，也没有删除未知内容。

## 持久顺序

原先在写完整清单之后才提交清理意图；API 在写清单途中退出会留下没有数据库绑定的半份文件。现在先对完整原暂存构造清单并提交其哈希，再写节点文件。重启时，仅当完整原暂存仍能重建出数据库绑定的同一个清单，才允许续写已有清单的精确字节前缀；不截断、不替换已有内容。文件身份在打开后复核，追加完成后 fsync；新增字节继续经过节点容量预留。

清理标记由已提交意图确定，同样只允许追加已知前缀。清单/标记含不认识的字节会拒绝并原样保留；已经删除部分文件后，损坏清单也不能用剩余文件重新生成。准备成功不等于删除完成；全部文件已删除但完成事件尚未提交时，管理操作仍拒绝，显式重试负责核验并补交一次完成回执。孤立完成事件失去原意图时也拒绝准入。

实际请求取消时，现有 `finish_before_cancel` 持续排空线程后才释放算例锁。本轮没有修改这一通用实现；真实两进程验证证明新清理入口使用了它。
