# 普通文件下载的一致性

2026-11-19，普通文件正文已改为有界分块暂存。首次发送前仍验证完整响应，准备阶段的版本冲突返回 409。[最新资源与兼容验收](raw-download-capacity.md)

2026-11-05，N2-05 的普通文件读取补充。本项不关闭 N2-05。

此前 `/cases/{id}/raw` 分别读取文件是否存在、大小和内容，多段 Range 又逐段重新打开文件。文件在这些操作之间被替换时，响应可能包含旧长度、新内容，或不同版本的片段。

现在首次读取固定单个文件的身份与长度。本地文件在每次打开后及读取结束时核对同一文件描述符的设备、文件标识、长度和纳秒修改时间/元数据时间；S3 固定首次 HEAD 返回的 ETag，每次 GET 都发送 If-Match，并核对响应 ETag、长度及 Content-Range。响应体完整组装后才返回；发现变化返回 HTTP 409，`detail.code=file_changed_during_read`，客户端应重新读取整个响应。第一次查找时不存在仍为 404。

单段与多段 Range 只读取请求范围，保留最多 16 段、64 MiB 总片段限制；HEAD 不读取正文。完整 GET 仍在内存组装，未增加大文件流式下载能力。原身份认证与算例权限继续生效。S3 正文流在成功或拒绝时都关闭，存储授权错误不被伪装成文件不存在。

验证入口为 `platform/server/file_read_consistency_smoke.py`，默认使用独立 SQLite/文件目录/API；`--s3` 启动并清理独立 SeaweedFS 4.52 实例。测试中的替换故障只存在于临时 API 启动模块，没有向产品增加故障开关。

- 文件存储 12 组：范围与边界、完整/多段 GET、HEAD、读取前替换、片段之间替换/删除、等长原地修改、完整旧版本已读取后的替换、缺失/越界路径和权限。
- 真实 S3 11 组：相同适用场景，采用真实对象条件读取，不包含本地原地修改场景。
- 另有 6 组模拟协议异常：忽略 If-Match、忽略 Range、错误范围、短正文、存储拒绝访问、缺失 ETag。模拟测试不冒充真实 S3 故障矩阵。

证据见 `tmp/mainline-N2-file-download-evidence/`。开发数据库和端口 8000 未修改；Redis 6380 本轮从 Windows/WSL 复查 PONG，AOF 已开启且最近写入状态正常。

边界：这是单次 HTTP 响应内的单文件一致性检查。多个请求、多个文件不能凭普通可变路径组成同一发布版本；发布消费者仍需固定 publication ID 并通过清单验证。未增加 If-Range/跨请求版本协议，也不替代 N2-06 的文件与数据库崩溃恢复。外部进程恶意修改数据并恢复所有文件身份元数据不在此检测保证内。N2-05 的跨版本/跨步骤/跨环境消费、旧路径审查，以及历史界面与多副本任务仍保留。
