## 当前交付

恢复对话框的“查看内容”内增加文件选择、筛选、分页、影响预览和确认。一次选择1至256个快照普通文件，预览逐项显示“新增”“覆盖当前内容”或“内容相同”。必须勾选确认后才能提交；没有自动选择、自动确认或自动重发。

这次交付明确为**选中文件的内容写回**。它不能作为完整目录树恢复的替代：目录创建/删除、文件与目录互换、POSIX权限、删除变化、caseDict专用恢复及超过256文件的整批事务仍待。UI、请求和回执均标明这个范围，快照ZIP仍保留完整文件与元数据。

预览比较恢复快照与当前项目。尚未提供以可信初始副本为基准的三方合并或自动冲突解决；已有同路径文件一律明确提示覆盖，用户可以取消选择。未来三方比较需要补齐初始清单的持久绑定及完整元数据基线，不能把保留目录中的未独立绑定文件当作自动覆盖授权。

## 接口与一致性

均位于 `/api/v1/terminal/sessions/{sid}/recoveries/{identifier}` 下：

| 接口 | 行为 |
| --- | --- |
| POST `/restore-plan` | 接收选中文件路径；检查快照及当前目标，返回影响和完整计划SHA-256；不写项目文件 |
| POST `/restore` | 必须提供计划SHA-256、UUID确认标识、`confirm:true`及`semantics:file_contents_only`；在算例事务内复核并写回 |
| GET `/restores/{request_id}` | 查询已经提交的确认回执；404表示尚无可查完成回执，不证明正在执行的请求已经失败 |

所有入口检查当前用户、算例所属工作区、原会话和快照绑定。写回先取得用户容量及算例写锁，再重新检查权限、来源、完成回执与清理证据，重新读取当前目标并比较整份计划；准备恢复字节后再次检查授权和快照来源。来源前缀变化、当前文件变化、目录目标、保留路径和caseDict拒绝处理。

快照文件读取时逐项核对实际长度和SHA-256。被选文件和当前目标各自的累计读取上限为128MiB，预览/准备有30秒检查期限，单进程最多同时两项；超过并发限制快速拒绝。底层单次存储I/O仍使用现有超时行为，完整全局队列和I/O期限要求继续在RB-14至RB-16跟踪。

实际发布复用FS/S3文件事务、用户/节点容量准入、文件来源失效和`files.changed`事件。确认回执与文件事务的SQL见证在同一个提交中保存。整批目标前提不符时不写入其中任何文件；中途失败依赖现有文件事务恢复协议，不能仅凭失败HTTP响应断言磁盘上没有待恢复状态。

确认UUID同时作为持久事件ID。同一UUID、同一计划和文件选择重试，只返回原回执；即使项目已被用户继续编辑，也不会再次覆盖。复用UUID提交不同意图会被拒绝。回执明确列出实际写入和内容已相同的文件，不把旧终端或旧导出记录伪造为成功。

浏览器在发送前将确认体保存到本地存储。结果未知时保留标识，可以查询或显式“重试同一次确认”。关闭重开后自动查询原回执；未确认期间每5秒只查询结果，不自动POST。已确认失败的特定前提错误会要求重新预览。浏览器存储不可用则不发送写回请求。

## 2026-11-20 认证 S3 文件与 caseDict 恢复

文件恢复预览先核验权限和快照绑定，在 SQL 事务之外分块读取选中文件，然后再核对来源和对象版本。确认后使用现有持久写入预约、4 个共享复制名额和事务日志。正文校验、前后副本与传输在 SQL 事务外完成。SQL 提交统一记录文件事务见证和恢复回执。caseDict 同时提交配置修订和工作流镜像，事件与来源历史沿用编辑器的原格式。原确认重放返回原回执并保留后续编辑。

使用 SQLite、认证且开启对象版本的 SeaweedFS、非特权 WSL 和真实重启后的快照。

| 场景 | 结果 |
| --- | --- |
| 40 MiB 文件预览 | 首次读取 1 MiB，SQL 写事务仍可取得。同算例保存 200，对象变化使原预览返回 409 |
| 40 MiB 确认写回 | 节点预留 40 MiB，正文传输在 SQL 事务外，同账户另一算例保存 200，同算例并发写入 409。完整长度和 SHA-256 一致，随后编辑在原请求重放后保留 |
