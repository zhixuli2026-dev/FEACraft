# 产物目录提交日志与中断诊断

2026-11-04，N2-06首批实现，尚未关闭。它为N5-04最终收尾恢复提供文件依据，不代替执行所有权、输入验证或数据库发布事务。

所有注册处理器的不可变产物复制现在先写入`.vibeflow/publications/.journal/{publication_id}/intent.json`。意图包含产物、case、attempt、kind、generation、完整文件清单、descriptor及最终manifest哈希；文件fsync后以无覆盖目录移动发布。该路径属于已有受保护publications命名空间，不可通过普通文件接口覆盖，也不进入v1算例复制/备份。

每个产物使用独立操作系统文件锁；锁随进程退出释放，另一个活进程不能同时接管同一准备操作。数据库所有权仍由原调用链验证，文件锁自身不授予执行权限。

准备中断后，持有相同验证意图的调用者可以再次准备：

- 完整目标目录：逐文件及完整清单核验后复用，既不覆盖也不更新时间。
- 完整临时目录：核验后无覆盖移动到原目标，无需重新复制。
- 不完整临时目录：保存在本条日志的`interrupted-{uuid}`目录，再从已经验证的输出重新复制，不重新运行求解器。
- 已有目标损坏、意图不同、符号链接或归属冲突：拒绝覆盖，保留证据。

目标提交后保存`ready.json`。如果进程在目标移动与回执之间退出，可从目标本身重新核验并补回执。文件证明不自动改变SQL head，不把prepared改成committed，不重放任务，也不扩大旧任务的控制权限。

`GET /api/v1/jobs/{job_id}/publication-recovery`提供只读诊断。先验证账户归属，读取数据库快照，释放连接后检查文件，再复验数据库和权限。结果区分无发布、旧无日志、复制未完成、产物完整、需检查、观察期间状态改变；返回SQL状态和活动指针信息。prepared的完整产物标记为保留等待收尾；只有正常发布事务决定对读者是否可见。

验证包括实际子进程在复制中途、目录移动前后、回执写入后退出，重新准备和重复准备不改完整产物，损坏/不同意图拒绝以及真实跨进程锁。双库真实Pandoc/API检查覆盖正常提交、DB提交失败、API在bundle完成后退出、新API读取与权限检查。既有几何专项保留迟到结果不得覆盖新head/别名的断言；旧测试先等待新提交再释放旧写者与现有排空协议冲突，已调整为新native到finalizing后释放旧写者。

仍需完成：通用文件/旧专业入口的补偿记录；兼容别名与删除的恢复；封存目录与孤立目录全量对账；提交后确认丢失、完整启动扫描和自动finalizing补交；S3及跨主机文件协议。此实现针对本地fs进程崩溃，未宣称硬件断电持久性已经验收。Windows使用文件fsync，POSIX另外同步目录；不据此宣称平台断电保证。
