# 恢复快照与原镜像读取依赖分离

2026-11-07。清理原沙箱镜像之前发现：已完成快照的读取、下载、文件写回还会校验原镜像目录实际存在。原镜像被移走后，独立保存的快照也不可用。

新增 `snapshot_profile` 只用于读取已保留快照；仍严格校验私有路径格式、快照目录、会话/用户权限、完成回执和 manifest/ZIP/选中文件哈希。原 `profile` 保持执行语义：创建、登记、释放和运行新的镜像恢复仍须核验原镜像目录。没有用读取许可代替执行许可。

实际隔离测试先运行真实 WSL、杀死原 API、生成快照和完成旧记录收尾，再将原镜像目录移至同一隔离算例的已校验保留目录。原登记路径确实不存在，测试结束后恢复原目录；**这是清理兼容性验证，不是自动清理已实现**。

| 验证 | 结果 |
| --- | --- |
| 原镜像登记目录不存在时读取 manifest、下载相同 ZIP、查询收尾凭证 | FS / 实际 SeaweedFS 均通过 |
| 从仍保留的快照预览、确认写回，查询写回回执 | FS / S3 均通过 |
| 原镜像缺失时破坏 ZIP，下载仍拒绝 | 两后端均通过，不放松快照完整性 |
| 原镜像缺失时发起新镜像恢复 | 两后端均拒绝，在登记原生执行之前失败 |
| S3 恢复内容交给真实 DeepSeek 读工具及续答 | 修复流式丢字后通过，2 次真实推理 |

新增兼容性断言共 4 项实际基础设施、4 项协议/故障；真实模型场景单独计数，详见[流式缺陷及所有实际调用](agent-stream-integrity.md)。共用的旧收尾检查本轮同时执行，但不重复计算为新增覆盖。

[FS 结果](../../tmp/sandbox-recovery-ui-retirement-_naiwyml/snapshot-independence.json)、[S3 与真实模型结果](../../tmp/sandbox-recovery-ui-retirement-0m1twn76/snapshot-independence.json)保留逐项记录。同目录 `cleanup.json` 各确认 7 个原进程身份已退出。首次 S3/模型运行因实际流式丢字失败的记录保留，不能算本功能完整通过，修复与复验见上文链接。

后续仍须实现镜像、恢复副本和 S3 暂存的有证据清理、额度结算和重启可恢复性。原镜像需受独占文件锁、实际卷身份/完整哈希和无 loop 挂载约束；清理与新恢复操作必须互斥，不能仅依据时间或目录名删除。原始基线/元数据与已确认保留快照需继续保留或有可验证替代，不能损害后续冲突处理。S3 暂存还需要持久清理意图、部分删除后重试及未知文件保护，完成后才能解除其管理操作阻塞。
