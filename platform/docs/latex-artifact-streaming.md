# N4-05 历史 LaTeX 原件下载

`GET/HEAD /api/v1/cases/{id}/latex/artifact` 在算例读取协调区内固定拥有者授权、发布 ID 和成功作业记录。文件校验及响应暂存在协调区退出后执行。历史版本、主文件通道、允许下载的产物路径与 `X-Vibeflow-File-Version` 继续绑定到原不可变清单。

目标文件沿用既有版本固定的分块读取，每次校验完整 SHA-256 后才返回响应。S3 还核对清单范围内的其他文件及对象清单前后的一致性。在一次完整目标读取中，只把请求的文件区间写入下载暂存。多段响应按请求顺序保留各段及 MIME 边界。HEAD 校验原件后返回头部。完整 GET 和 Range 使用普通文件下载的节点预留、响应线程与 ASGI 生命期清理。

40 MiB 复验使用经过 PDF 解析器严格验证的实际文件、生产发布封装和隔离数据库。测量包含服务端读取、摘要与响应准备。Range 仍需读取完整原件以证明归档摘要。复验范围是公开历史下载，编译与 SyncTeX 继续由其既有专项覆盖。[复验入口](../server/latex_artifact_streaming_smoke.py)

两组的完整 GET 正文与历史发布记录的 SHA-256 一致。HEAD、单段、乱序多段、无效 Range 416 和恢复后的历史 HEAD 均各用一个最多 65,536 B 的目标文件流。S3 每次只对目标做一次条件 GET，整个发布目录在本地始终保持冷状态。小 Range 的磁盘预留为 0。历史、当前版本和主文件通道的选择保持，错误的文件版本返回 409，其他账户与不允许的产物路径返回 404。

修改同尺寸 PDF 中请求区间之外的一个字节后，Range 与完整 GET 均返回 `evidence_invalid` 409。失败的完整请求释放了暂存额度。另一次完整 GET 发出首块时，两种存储均持有 41,943,700 B 预留，真实客户端断线后额度归零。两个 API 和隔离对象存储均确认退出。回归审查只选择该套件，结果 1/1，通过耗时 83.765 秒，真实及模拟模型调用均为 0。测试数据位于 D 盘，C 盘前后可用空间均为 22.22 GiB。[回归汇总](../../tmp/vibeflow-regression-all-20261119-122425-d9c47e/summary.json)
