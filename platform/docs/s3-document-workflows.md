# S3 文档处理器

本批接入两个独立组稿通道、LaTeX 编译、PDF 页码和 PPTX 生成。验收已完成，规范证据在 `tmp/mainline-N2-s3-document-workflows-evidence/`。正向16项按8+6+2分批完成、冲突11项、工程文档联动12项通过；本地普通文档23、PDF10、PPT10、LaTeX32项兼容通过。前一批工程主链路见 [S3 正式工程流程](s3-core-workflow.md)。

组稿从版本校验后的远端读取视图取得证据与原稿；生成器和独立重建显式读取封存目录，避免把本地尝试目录当作远端算例前缀。覆盖前复验原稿字节，原字节备份保存在不可变结果包中。两个输出文件分别使用独立发布通道；生成草稿作为 HTML/DOCX 的版本输入，手动编辑后的历史仍可按版本读取。

LaTeX 的资源选择、报告门禁、工具链探测、发布后状态和 SyncTeX 当前源码比对均支持远端文件。每个主文件仍独立发布；源文件副本从不可变版本读取。历史参考文献的清理沿用条件删除计划，用户修改过的旧 `.bbl` 不应被删除。

若编译本身有效但旧 `.bbl` 已被用户修改，新不可变版本可以提交，兼容输出的应用则记录冲突：旧 PDF 和用户文件都保留，查询返回 `aliases_applied=false`。这与“编译失败”不同；验收同时核对新版本 PDF 可下载及旧工作文件未被替换。

PDF/PPT 的 S3 路由改为统一注册处理器，输入、生成配置、产物和发布版本归属同一次尝试。目标已存在时拒绝覆盖；运行期间产生的新目标也由提交前检查和条件写入保护。纯文本 PPT 只封存生成配置，不要求虚构资源文件。文件存储保留同一实现和原有语义。

## 验收

- `s3_document_workflows_smoke.py`：真实组稿、Pandoc HTML/DOCX、PDF 页码、原生可编辑 PPTX、三种 LaTeX 配方、Biber、共享图片和宏选择章节、空缓存引用、历史 SyncTeX、失败编译保留上次 PDF。`--only latex-retirement` 验证编辑过的旧参考文献保护和未修改参考文献的条件删除。
- `s3_document_conflicts_smoke.py`：组稿/PDF/PPT 各自的源文件变更、目标变更、取消，以及无效 PDF 和损坏 PPT 模板。变更通过隔离对象存储写入，模拟绕过 API 的外部修改；不因此放松发布校验。
- `s3_document_engineering_smoke.py`：复用真实几何至报告链路，在同一算例增加独立组稿、生成稿构建及含后处理图表的 LaTeX，核对发布引用和几何变更后的递归过期；共 12 项检查，其中 8 项是工程主链路，4 项是新增文档联动。
- 本地兼容：`ordinary_document_smoke.py`、`pdf_publication_smoke.py`、`ppt_publication_smoke.py`、`latex_handler_smoke.py`。
- `case_read_view_smoke.py`：8 项覆盖远端版本变化、取消清理、本地原文件保留，以及真实 Windows 目录读句柄释放后的有限重试、持续占用时的有限失败。

失败日志保留：首轮夹具误以为创建算例响应包含 `workspace_id`，现从所属工作区接口取得；第二轮在手动编辑已使当前草稿失效后，错误地查询当前草稿，现显式读取历史版本并验证当前引用被拒绝。页码目标路径使用接口实际返回值。上述修正不改变产品的验收条件。

第三轮已通过组稿与 PDF/PPT 共 8 项，随后 LaTeX 的 SyncTeX 坐标误用了 `(100,100)`，实际映射第 8 行。改用既有验收的 `(134,157)`，仍要求准确映射第 7 行，并仅复验 LaTeX 部分。首轮参考文献测试误将兼容输出应用冲突当成不可变版本提交失败，现按上述契约核对两者及用户文件保留。每个失败记录与后续定向复验分别保留。

首轮工程联动暴露实际产品错误：Windows 临时目录短暂占用使 `TemporaryDirectory` 清理在 WinError32/5 之间递归，最终接口返回 500。读取视图改为显式创建独占临时目录，并使用项目已有的 `remove_owned`：逐次校验目录边界，最多重试 6 次，仅重试共享占用错误；持续占用仍抛出错误并保留目录，不报告成功。文件存储分支未变。首轮句柄夹具使用 access=0 的元数据句柄，实测并不阻止删除；改用目录读权限 access=1 后，真实占用两项和整个读取视图 8 项通过。

组稿/PDF/PPT/LaTeX 正向、冲突和本地兼容证据早于最后的读取视图清理修复；最终读取视图及工程文档联动专门复验该修复。分批验收不等于在最终源码上重新运行了所有历史测试。所有失败日志、复验记录及来源关系保留在规范证据中。

## 范围与后续

本批完成后，S3 正式处理器待接入数由 14 降至 9：旧算例后处理、CalculiX、SU2、ParaView、MPI、UDF 两入口、FloTHERM 两入口。主线 53 项和全功能 295 项的原始范围不变；处理器接线不能替代整个存储、恢复或交付大项的验收。

本批使用隔离 SQLite、SeaweedFS 4.52 和已安装的本机/WSL 原生工具。PostgreSQL/S3 组合、跨主机、全部资源/权限/工具链记录、远端孤立对象与未完成上传恢复仍需继续。远端同步递归校验的响应延迟仍按前一批性能记录保留；测试的有限等待不代表响应性能通过。默认文件存储和部分 S3 开关保留，未迁移开发库或重载端口 8000。
