# RB-12 部分验收：本地创建及恢复元数据的用户额度

后续更新：S3 创建、克隆与恢复的账户持久预留已在[后续阶段](owner-storage-admission.md)实现并验证。下文保留本阶段边界；当前剩余工作以资源工作清单及主线台账为准。

2026-11-06：本地创建、算例复制、工作区复制、ZIP 导入和备份恢复的公共写入入口，现按实际安装峰值检查用户空间额度。恢复时新增的历史回执同样检查。S3 创建/克隆和其他长文件操作仍待完成；主线仍为 33/53 完成、剩 20 项，资源预算阶段 11/17 完成、剩 6 块。

## 写入协议

`local_provision_budget.hold` 使用调用者的同一个 SQL 事务取得账户额度锁，记录该事务的身份。`case_provision.create_from_manifest` 和 `recover_owner` 在此上下文内执行；每次本地 `put_new` 在创建目录或文件前，检查 `2 × 内容长度 + 已编码安装意图记录长度`。它覆盖数字前缀占用记录、待提交创建计划、算例文件和最终恢复历史。

检查沿用统一的实际用量盘点及活动预留汇总，因此已有文件、回收站和其他写入预留共同消耗额度。安装阶段临时文件和目标硬链接分别计费，与现有物理扫描保持一致。用户额度通过后仍需通过节点空间准入；二者分别保护账户容量和本机磁盘。

额度锁贯穿写入并由调用者提交或回滚时释放，没有插入提前业务提交。线程把准入请求交回事件循环执行同一个异步 SQL 会话；不能在事件循环直接执行同步写入，不能跨账户、使用已关闭上下文或更换事务。取消通过既有 `finish_before_cancel` 等待文件线程结束后才退出锁上下文。进程退出后残留的文件、双链接及安装意图仍由用户用量扫描计费，随后依据原有创建记录恢复。

恢复历史写入额度不足时不会删除对应 pending 计划。腾出空间后可再次恢复。额度检查是逐次文件安装，不能保证整个克隆一定完成；如果中途拒绝，前面的实际写入与创建恢复记录仍会保留。使用历史回执恢复时，回滚文件和写回执也不是同一次文件系统原子操作，pending 计划负责保留重试依据。

## 当前限制

- 此实现仅用于本地文件系统。S3 的迟到请求及未知结果需要跨业务回滚的持久预留，不能把本地线程结束当成远端写入结束的证明。
- 复制与恢复仍持有调用者事务执行 I/O；逐笔准入也会重复扫描实际用量。这些锁持续时间、扫描成本和维护问题仍属于 RB-14、RB-15。
- 这是应用内协作准入；外部进程写入和操作系统级磁盘限制继续由 RB-17 跟踪。

## 验收证据

`local_provision_storage_smoke.py` 使用真实隔离 API 和本地文件，检查正常复制、零额度创建、正文可容纳但安装峰值不足、恢复回执额度不足、用量无法核验、独立进程竞争、进程退出、请求取消和无额度上下文写入。分别验证 SQLite 与 PostgreSQL 的实际锁行为：前者等待写事务结束，后者以 `storage_quota_busy` 拒绝竞争准入。

兼容检查覆盖原创建协议的正常、回滚、写入中断和提交后恢复，并核对四类构造入口在 SQL 提交成功但响应丢失后的恢复。具体通过数量、进程结果及源码版本以[本次验收记录](../../tmp/mainline-local-provision-storage-evidence/validation.json)和[源码绑定](../../tmp/mainline-local-provision-storage-evidence/source-binding.json)为准。本次没有新增数据库迁移，也没有改动开发数据库或运行中的开发服务。
