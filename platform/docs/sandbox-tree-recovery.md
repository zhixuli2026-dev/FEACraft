# 沙箱目录、类型与 Linux 模式位恢复

2026-11-16。承接 N4-05 / RB-12、FF-F58、FF-J16。主线仍为 48/53，剩 5 项；资源清单 11/17，剩 6 块；295 项完整交付状态保持。本文记录真实恢复增量，不代表所有执行入口、正常导出和资源维护均已完成。

终端恢复方式新增“恢复目录、文件和 Linux 权限”。使用已登记的初始清单、恢复快照和当前项目比较文件内容、目录、类型及 POSIX 模式位。选择目录会包含其中的沙箱改动；双方均修改的条目保持冲突。目录删除或改为文件时，项目后来新增的子文件会阻止提交，不能随目录一起丢失。caseDict 和两份配置历史仍由专用配置恢复处理。

预览摘要绑定当前完整目录树、权限描述、快照回执和目标树。确认时持有原项目锁重新核验；版本变化拒绝旧预览，重复请求沿用持久回执。网页取消冲突时也取消会再次纳入冲突的父目录递归选择。文件浏览器能够显示恢复的空目录。目录树、单纯文件内容、三方文件改动和 caseDict 专用恢复保持为明确的不同操作。

## 实现与边界

- FS 复用项目锁、额度准入与 SQL 提交见证，在同一文件系统内交换受影响的顶层子树。原树移动到日志保留区，再安装已校验的目标树；这两个重命名之间的缺口是明确的待恢复状态。SQL 未提交则放回原树，已提交则保留目标树。检测到外部未知内容时保留现场，不猜测覆盖。回滚不依赖递归删除。
- S3 复用原条件写入文件日志和提交见证，加入目录树作用域。文件与目录前缀互换可在同一事务内处理；空目录与模式位存入受保护的 `.vibeflow/tree-state.json`。备份、条件写入与回滚仍使用实际对象存储。
- Windows 和 S3 保存的是 Linux 模式位，不能称为 Windows ACL 或对象存储自身强制执行 POSIX 权限。后续真实 Linux 沙箱在执行命令前校验普通路径，恢复空目录并应用匹配内容的权限；源代码摘要包含该助手。FS 的 POSIX 实现另有实际 chmod 分支，但本轮 API 宿主为 Windows，未声称完成 Linux API 宿主矩阵。
- 沙箱启动不再把 `.vibeflow` 内部事务历史复制进 128 MiB 用户卷，只带入目录树权限描述；S3 下载暂存会保留并核对该描述，而普通暂存同步不允许改写它。用户可见文件、目录及恢复基线仍由实际原生快照核验。
- 完整树上限沿用 10,000 个条目及 128 MiB 文件内容。权限描述最多 8 MiB；FS 目录事务日志最多 16 MiB，S3 为目录树作用域预留额外一个权限描述对象。FS 准入计入新子树与日志峰值，原树通过重命名保留。历史日志及失败准备目录后续仍需原资源维护流程，不把持久保留称为已释放空间。

接口沿用 `restore-plan`、`restore`、`restores/{request_id}`，增加 `semantics: sandbox_tree_changes`；`GET /tree-changes` 返回目录、类型、文件和模式位改动。选择目录展开后仍受条目上限限制。缺少可信初始模式位的旧快照不能自动升级到本方式。

## 实际验收

入口为 `platform/server/live_llm_sandbox_tree_acceptance.py`。审查登记 v1 包含 588 个源码、Shell 启动器及传递辅助文件；运行前逐个核对摘要。FS 和 S3 后端验证期间源码相同。最终 v2 仅修正网页取消冲突时的父目录递归选择，随后重新构建并在实际浏览器验证；没有用 UI 修改后的摘要冒充重跑后端。

- FS / SQLite：`tmp/sandbox-recovery-ui-retirement-x4alo1kd/tree-result.json`。实际 WSL 内创建空目录、删除目录、执行两种文件/目录互换、改变模式位并写入随机证明。项目后来新增的子文件使删除目录整批拒绝。原 Ref 目录已移动到备份、目标尚未安装时实际退出 API（84），重启放回原树；同一请求重试成功。保留其他当前文件及恢复后的新编辑，重复确认不再写入。
- 实际 SeaweedFS / SQLite：`tmp/sandbox-recovery-ui-retirement-bc_qhtfy/tree-result.json`。同样的结构变化、冲突保护和幂等通过；第一个对象实际应用后退出 API（85），重启完成原 S3 日志回滚，再以同一请求成功恢复。这一轮具有独立的 S3 中途退出证据。
- 两种存储各启动第二个真实 Linux 沙箱，实际检查空目录、文件类型、删除结果，以及 `701`、`700`、`600`、`640`、`750` 五组精确模式位，然后正常退出。不是仅检查权限描述 JSON；本轮未覆盖所有特殊模式位、所有宿主/数据库组合或其他执行入口。
- 两种存储各 2 次真实 DeepSeek HTTP 200，配置及服务模型为 `deepseek-flash`。模型自主选择 `read_text_file` 并读回实际恢复的随机内容，提示词未包含答案；工具和回复已持久化。合计 4 次真实请求，模拟 0，证据见各目录 `live-result.json` 和 `live-model-events.json`。
- FS 实际网页曾复现：取消冲突子文件后，选中的父目录再次展开它。保留 `browser-conflict-counterexample.json`，修复后再次预览不再出现该冲突。人为移除隔离算例中已核验的一个空目录后，通过网页明确勾选并确认，实际恢复该目录，保留冲突子文件的 `USER_EDIT` 内容。关闭重开只查询回执，恢复 POST 仅 1 次，文件树将新空目录显示为目录。
- 390px 深浅主题和 1280px 桌面截图已目视核验，无横向溢出和 JavaScript pageerror。前端构建及最终 TerminalRestore detector 通过。测试 API、预览和自建 SeaweedFS 均已退出；FS 24 个、S3 12 个原进程身份独立核验不存在。
