## 启动与失败处理

在创建原生进程前提交 `attempt.launch_intended`，绑定 Job、attempt、原 worker、claim 摘要、输入摘要、启动 nonce、runtime 与启动工具摘要。同一 attempt 已有意图时拒绝再次创建启动，不能把提交响应丢失当作重新执行的依据。

真实进程完成受控握手后，先在事务外复验实际持有的进程，再提交 `attempt.launch_prepared`。此事件保存仍等待放行的完整进程身份；不把准备记录描述成已经运行。随后原有 running 登记必须与已准备的身份一致，最终放行继续使用原有取消/租约/所属校验。

启动异常时，只对本次实际持有的进程执行停止和退出核验。只要已获得完整进程记录，就不再依赖回调是否成功返回来决定是否保留清理证明。原 worker 在所属事务中核对启动意图及已提交登记，保存 `attempt.launch_aborted`；即使 running 没有提交，也能保留这次已停止辅助进程的身份。原始 running 事实另用 `running_registration_committed` 表达，不补造 running 转换。

实际停止回执仍经过既有验证，并由原完成流程保存。核验失败或数据库不可用时，保持不确定状态；没有把“辅助进程消失”升级成完整进程树已经停止。放行是否收到本地确认只记录为 sent/unconfirmed，unconfirmed 不代表命令肯定没有执行。

## API 重启后的行为

启动核对覆盖 starting，以及已经请求取消或报错但仍缺登记的已知启动。先取得短事务中的 Job/attempt/路径/原实例/输入/输出/子执行/检查点/head 和启动事件快照，再关闭事务观察原实例和已有进程身份；WSL 探测不占用算例写事务。活实例保留，由原实例完成工作。外机或不能验证的实例不触发同名本地发行版探测。

非活实例的登记缺口以 `attempt.registration_recovery_required` 持久审计。写回前重新加锁，核对完整快照及事件摘要；观察期间内容变化则拒绝写入旧结论。重复或两个 API 并发核对同一结果，只写一次审计。新的观察结果变化时保留新的历史事件。

本批恢复只观察与记录，不接管进程、不发送恢复停止信号、不生成停止回执、不重新认领或重放命令。完整已知身份可被读出；缺身份、损坏历史与不能核实的记录仍需处理。原作业/attempt 状态和有效产物保持原样，不因原实例退出就猜测任务成功或需要重算。

已授权的 `GET /jobs/{id}` 详情增加 `attempt.registration`：意图/已准备/已登记/异常结束阶段、已验证格式的准备身份，以及仍匹配当前记录的恢复提示。提示包含观察时间、实例/进程观察状态和 `automatic_restart_allowed=false`；不暴露 claim 凭据。跨用户读取仍走原算例权限校验。完整列表、页面提示和人工操作入口继续由 N5-07/N6 接入。

## 验收设计

- 实际 Windows/WSL 启动在登记提交前失败、提交后确认丢失、取消及错误身份时，业务命令不得放行；原始身份、停止回执和排空检查点保持可核验。
- 真实 API 在意图已提交或辅助进程已准备时退出；另一个 API 不误改活实例，退出后持久记录需处理，重复认领被拒绝。
- 双 API 竞争、审计提交前失败与提交后响应丢失必须保持事务结果和唯一事件。
- 原实例/进程观察期间修改 claim、输入、登记或准备事件，写入能够提交而旧观察不得落库。
- 既有原生登记、启动续租、取消放行、所有者启动及历史排空恢复回归。

测试只使用独立 API、临时 SQLite/PostgreSQL 和本次创建的 Windows/WSL 进程；不迁移开发数据库，不重载端口 8000。没有新增表或列；新信息使用原持久事件和既有身份字段。旧新混合部署、完整历史数据库迁移、跨主机接管和全量故障验收尚未据此完成。
