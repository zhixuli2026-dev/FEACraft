# 备份与恢复的跨worker准入及整次期限

2026-11-12 UTC。N4-05/RB-14、RB-16增量，主线48/53完成、剩5项；资源11/17完成、剩6块。此处完成备份/恢复这一组入口，不将其等同于全平台资源预算完成。

## 行为

原v1备份有单个文件清单/ZIP大小限制，却会同时保留文件Base64与ZIP；多个worker、不同用户可以并行持有多个大包。现在使用同一节点storage_fs_root下固定文件的非阻塞OS锁，每个共享节点根同时只准入一个备份或恢复请求，无内存等待队列。忙时返回429/archive_busy及Retry-After:2，不开始解析multipart或执行数据库/文件操作。

锁覆盖整个ASGI请求，从正文解析前直到最后响应发送后。中间件放在BaseHTTPMiddleware之外，避免业务函数返回后就释放名额。备份仍生成原manifest.json/v1 ZIP，响应按最多64KiB逐块发送并保留Content-Length/下载文件名，防止一次性向网络发送整个大包而提前丢掉并发约束。

默认300秒共用请求期限，包括正文、认证依赖、业务和发送。到期取消沿用排空式文件IO/SQL收尾；实际线程仍未结束时继续占有名额。未开始响应的超时返回504/archive_timeout；已经开始的传输中断，不拼接第二份JSON伪装完整ZIP。进程退出由OS释放文件锁，不删除锁文件、不按TTL猜测执行结束。

部署要求：同一节点的API worker使用相同storage_fs_root及支持本机文件锁的文件系统。Windows实现使用msvcrt，POSIX实现使用flock；本轮实际验收在Windows。多节点各自有独立内存，因此这是每节点并发上限，不冒充跨物理主机的全局用户额度。
