## 数据契约

本机已安装 CLI 生成的 `ThreadTokenUsageUpdatedNotification` schema 与[官方 App Server 事件文档](https://learn.chatgpt.com/docs/app-server#turn-events)共同作为协议依据。事件必须明确匹配已登记的 `threadId` 和当前实际尝试的 `turnId`；其他线程、旧回合、缺少归属的报告不写入当前回合。

沿用 `NativeCliEvent`，新增事件类型 `usage.updated`，不增加业务表或迁移。快照带 `source: native_cli`、`thread_id`、`native_turn_id` 和 `attempt`。对外只保留协议中的计数白名单，丢弃额外字段。

| 字段 | 表达的内容 |
|---|---|
| `last` | CLI 最近一次模型调用的用量视图 |
| `total` | CLI 当前报告的线程累计视图，可能包含恢复或分叉继承的历史 |
| `modelContextWindow` | CLI 报告的上下文窗口；未提供则为 null |
| 每组计数 | inputTokens、cachedInputTokens、cacheWriteInputTokens、outputTokens、reasoningOutputTokens、totalTokens |

所有数值必须是 0 至 `2^53-1` 的精确整数，拒绝布尔、负数、浮点、字符串和超范围数字。`cacheWriteInputTokens` 按协议缺省为 0；缺失窗口保持 null。零与未提供严格区分。一个平台回合可有多次模型调用，也可能包含多次容量续跑；平台不把相邻快照相加，不用线程累计值冒充该回合的费用，也不依据窗口值计算未经证实的上下文占用率。

相同尝试内连续相同报告只登记一次。更新快照仍保留之前的事件，可通过 SSE 游标回放。报告在当前会话执行归属锁下提交，使用既有事件数量和字节上限。已失败尝试的报告保留在历史事件中；进入新尝试但尚无报告时，公共回合记录为未知，不沿用上次尝试的数字。

`GET /api/v1/codex/turns/{id}`、会话回合列表以及幂等提交回执增加 `usage`：

- `reported`：含已校验的计数、归属和事件 `seq`。
- `not_reported`：当前尝试尚未报告，或旧历史没有保存报告。
- `invalid_report`：当前 CLI 报告不符合计数契约，隐藏旧计数；不会仅因此让已经成功的回复变为失败。
- `invalid_record`：持久快照无法通过读取校验，不展示不可信计数。

读取仅使用已提交事件，不启动 CLI，不向服务商重查，也不回放推理。读接口仍要求活动用户和回合归属。观察到的事件范围止于正常回合消费结束；不保证能收到服务商全部费用事件，不从模型文本长度推算未报告数字。

## 界面

原生运行记录中增加可折叠的 Token 用量区。默认只展示线程累计摘要，展开后并列展示最近模型调用和线程累计，含输入、缓存、输出、推理与合计。说明文字明确累计历史和分类项的关系。未报告、无效和明确零分别表达。切换历史回合与刷新后重新打开会话都能读取持久快照，已有 2.5 秒状态轮询更新显示。

沿用工作台的深浅主题、键盘焦点和可滚动历史区域，输入区持续可用；实测实际 340px dock 无横向溢出。极大数字的 UI 压力验证使用 HTTP 响应夹具覆盖，不声称该数值来自实际模型账单。整套工作台的移动端布局不在此单元验收范围。
