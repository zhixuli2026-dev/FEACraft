# ParaView 脚本独立运行与文件发布

本地文件存储的 `/paraview:run` 已迁入 `paraview.run@1`：pvpython 和 pvbatch 在作业自己的输入副本中执行，成功后生成不可变发布，再按原路径更新文件。调用参数、返回的 Job ID、backend 和原下载接口保留。发布描述为 `paraview.v1`，按脚本路径区分发布通道。

## 输入与执行

Python 脚本可能动态读取数据文件、辅助模块及运行参数，不能只扫描脚本文本推断依赖。因此本入口封存算例中的用户文件和目录，排除 `.vibeflow` 运行元数据，继承独立目录的大小、文件数量、路径、链接和配额检查。主脚本仍限制为 1 MiB 的 `.py` 文件；本次执行不允许修改主脚本自身。

私有配置绑定源文件清单、执行标识、脚本和 backend。固定 worker 通过所属作业的原生执行通道启动配置的真实 pvpython/pvbatch，保存进程身份和停止记录；子进程的 `VIBEFLOW_CASE_ROOT` 指向私有运行目录。执行文件及 worker 摘要、输入、输出、删除清单和日志摘要绑定在收据中。

这提供应用层输入和发布隔离，不是任意 Python 的操作系统沙箱。脚本使用绝对路径或外部服务的能力和隔离要求仍属于原生 sandbox、外部依赖及生产部署的既定任务，不能把本次文件副本当作完整安全隔离。

## 文件与历史结果

新文件、内容变化文件和本次重写的同内容文件形成发布清单；脚本删除的文件保存删除清单。封存副本中的其他旧文件不冒充新产物。仅打印日志的脚本可以正常成功，其不可变清单为空，不重新发布旧 VTK 或图片。目录用于保存文件结构，脚本只创建或删除空目录的动作不作为成果文件同步。

发布前核对全部封存来源及写入/删除目标，运行中修改依赖、新增输入、用户改写输出或待删除文件，均阻止覆盖和删除。原文件仍在封存副本和历史发布中。别名操作使用持久化的哈希条件计划，复制阶段 API 退出可续交原作业，不再次运行脚本。

后续作业可选择不可变的当前或历史结果；本次发布造成的输入覆盖和删除由本次摘要识别，避免把自己的输出误判为外部来源变化。由于依赖选择包含整个用户文件树，修改其中其他文件也会使“当前结果”引用失效；历史引用仍可明确选取。这个保守行为避免对动态 Python 的实际读取范围作无根据的推断。
