## 用户行为

打开 `E-report/build/report.html` 或 `report.docx`，阅读器的“历史版本”展开版本列表。选择已发布版本后，元数据与原件均使用同一个明确的 publication ID。显示与下载继续使用已打开的原字节，不会重新下载当前别名，也不会把历史内容写回工作区。

列表区分最新发布、历史发布、尚未发布和发布失败；未成功发布的记录不可选择。最新发布不直接等同于当前有效：打开后由结果接口复核来源，并在阅读器中显示过期说明。历史版本明确标为“不代表当前有效结果”。“重新读取”返回最新版本并重新核验。

历史选择遇到 404、损坏或权限错误会明确报错并禁用下载，不回退为最新版本或工作区文件。仅未指定历史版本、且尚无活动发布的普通工作区文档保留原有读取行为。切换文件/算例时旧读取被取消，旧版本的下载按钮不能短暂冒充新选择。

列表刷新失败保留已有条目与当前文档。“重试”重试失败的刷新或翻页动作。独立复核发现首版将刷新重试误当翻页，现已记住失败请求模式，并增加浏览器断言确认刷新重试不带旧页游标。

## 分页契约

`GET /api/v1/cases/{id}/report/publications` 保留原数组响应和默认 50 条，新增 `limit=1..100` 与 `before_generation>=1`。同一 case/report 通道 generation 唯一；下一页取小于末条 generation 的记录，期间新增发布不会移动旧页边界。界面每次请求 20 条，可继续加载更早版本，不再把前 50 条当成全部历史。

列表是发布记录索引，不承诺每条记录都已验证原件。只有选择版本并通过既有结果/产物校验后，阅读器才展示、允许下载。当前实现没有为历史选择新增数据库字段或迁移。
