# 同 case 注册 MPI 批次与实际文件查询来源

原多工况入口仍在同一个 case 内派生 C-run 目录。独立 case 工作流批次不能代替这条路径。本阶段在原 `/cases/{case_id}/jobs:batch` 增加注册 MPI 操作，沿用统一 Job/attempt、持久投递、批次和用户额度、取消及历史查询；没有另建执行器。

```json
{
  "operations": [
    {"kind": "mpi", "run_dir": "C-run/condition-a", "solver": "icoFoam", "subdomains": 2},
    {"kind": "mpi", "run_dir": "C-run/condition-b", "solver": "icoFoam", "subdomains": 2}
  ],
  "max_concurrent": 2
}
```

每批 1–50 项、并发 1–4；运行目录须规范、互不重叠，操作携带自己的注册类型和运行时。所有成员准备、封存、绑定及批次清单在同一事务提交后才允许投递。第二个成员非法时不能留下可执行的半批 Job。v2 清单的请求摘要、参数、成员次序和投递组会与原 Job/attempt 绑定复核。同键重试返回原批次，不因当前文件改变而隐式再算。

原 `commands/type/runtime` 形式继续使用 v1 清单；旧请求摘要不因新增可选字段改变。9 组旧请求的结构/幂等摘要对照属于纯协议检查，不能代替实际执行验收。

## 保留完整可见输入

只封存当前运行目录会破坏跨目录引用，所以原生进程仍能读取整份封存 case。`origin_source`、准备配置和原生凭据保留完整初始清单。新 `case_file_queries` 用真实 strace 跟踪字典检查、分解、两 rank 求解和重构，记录读取、缺失查询、目录枚举及进程工作目录；`source` 由这些实际查询构造。

同 case 的另一个工况产生未被读取的结果，不会仅因整份 case 改变而把本次成果判旧。实际跨目录输入变化、原先缺失的可选输入出现或已枚举的目录成员变化，仍会使来源失效。自身产生的文件按已核验输出还原为原输入后再检查；不能据此覆盖用户已编辑的目的文件。

原生跟踪最多 1024 份文件、64 MiB、500000 个事件，并有执行期采样监测；采样不承诺零超出。跟踪缺失、截断或无法解释的必要信息会拒绝验收。原始跟踪位于私有 Linux 阶段并随其清理，凭据保留各记录摘要、大小、事件数和查询投影，不声称保存了原始跟踪全文。外部运行环境的完整依赖闭包仍未声明。

正式 MPI 工作流继续固定不可变网格，并保留工程来源；新的运行时来源作为额外依赖参与校验。可变网格副本不能替代实际挂载的网格记录。兼容复制、旧产物清理和历史恢复继续使用完整 `origin_source` 的覆盖前置条件，不能把带缺失路径的查询投影当作完整原文件清单。
