# 阶段确认提交后的清理

确认接口先提交阶段、修订号和工作流步骤，再清理已提交文件事务。原路径可能在清理时遇到账户结算争用，向客户端返回 `storage_quota_busy`。客户端按准入忙重试原确认，随后因步骤版本已经推进而收到 `state_conflict`，掩盖了第一次确认已经成功的事实。

真实 FS/PG 反例位于 `tmp/live-cli-startup-e62xm46j`：实际 CadQuery 几何通过后确认 B，在提交后取得真实 PostgreSQL 账户 advisory lock。接口返回 409，但锁持有者读取的 SQL 状态已经是 B、修订号 1、确认步骤 succeeded。模型调用为 0，未替换模型或原生几何结果。

`finish_confirmed_stage` 只处理确认提交后的清理。它在原业务事务和账户作用域关闭后，为每次已知忙重试建立独立 Session；不重复阶段写入或原生派发。真实额度不足和永久冲突仍按原规则拒绝。等待继承可用执行预算，否则最多 30 秒；若已知争用仍未解除，返回 `confirmation_cleanup_pending` 和 `committed: true`，明确要求读取当前状态，不重复确认。
