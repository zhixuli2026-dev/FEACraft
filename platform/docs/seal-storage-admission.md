## 已复现的问题

本地准入原来仅估算两份输入数据，遗漏 manifest、封存计划、恢复历史和安装期间的临时文件。真实 HTTP 请求在剩余 2048 字节时获准封存 1024 字节输入，实际用量最终超过 1 MiB 配额。证据：`../../tmp/seal-storage-before-nbtx2_q5/seal-storage-observation.json`。

S3 来源原来在配额检查之前创建 `.attempt-sources` 并下载。拒绝请求虽返回 429，节点已承担下载和缓存分配。证据：`../../tmp/seal-cache-before-xovlgz85/seal-cache-observation.json`。

## 实现

`seal_storage_budget.estimate` 用实际序列化格式估算清单、计划和较大的恢复结果。本地计入两份输入、计划、恢复历史及其临时链接和写入意图；写入者身份的编码长度强制不超过预留的 1024 字节。S3 计入远程保留的一份输入、清单、计划和恢复历史。清单与恢复记录仍遵守原有大小限制。

普通 S3 来源先列出对象大小和 ETag，校验路径、数量、总量及文件/目录冲突。预检使用等宽摘要占位符估算元数据；它不会作为执行依据落盘。用户存储准入通过后才创建来源缓存，以条件读取下载，重新核对来源版本、清单和大小，并用真实摘要替换占位符。实际估算不得超过准入值，否则拒绝封存。生成输入和发布输入仍参与合并清单检查。

用户级准入沿用数据库事务锁。此次没有增加数据库迁移，没有调整开发服务。

## 验收及边界

`seal_storage_budget_smoke.py --postgres` 对 SQLite/PostgreSQL 各验证 3 项：元数据超额拒绝发生在分配前；实际封存及恢复安装峰值在准入范围内；真实摘要提交且恢复幂等。`--postgres --s3` 各验证 4 项，另验证准入后来源变化会在缓存分配前拒绝。此专项用真实 HTTP、数据库和文件/对象存储，故意不启动原生作业；原生执行兼容性由 `attempt_workspace_smoke.py` 和 `s3_attempt_smoke.py` 单独覆盖。最终回执索引：`../../tmp/mainline-seal-storage-evidence/validation.json`。

这里估算的是本次封存的用户计费字节峰值，不是文件系统块占用、节点磁盘硬限额或跨阶段持久空间预留。恢复历史未来安装期间的空间尚未以独立持久记录保留。重试输入恢复、发布依赖下载可能仍早于该准入点；不得将此次普通 S3 来源的改动描述为全部缓存入口已受控。
