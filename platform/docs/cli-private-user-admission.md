# CLI 私有写入的用户额度准入

2026-11-07，接续 [私有文件用户计量](cli-private-user-accounting.md)。此前已存在的宿主私有字节会进入用户用量，但平台初始化、秘密字段更新和图片副本尚未统一执行写前用户检查。本次把这些平台负责的写入接到既有用户额度锁，并让 S3 图片使用既有远端容量账本。

## 初始化和秘密字段

新增 `cli_user_capacity`：在父 SQL 事务内取得用户额度锁、验证活动用户，并兼容既有用户行锁下的秘密值合并。CLI 的宿主私有初始化先按已验证的 64 KiB 上界检查额度，再执行实际文件写入。线程工作通过 `finish_before_cancel` 排空，父事务在它结束之前不会因请求取消而释放用户锁。

缓存更新先在同一锁内校验账户路径所属用户、计算真实合并后密文和密钥字节，再检查用户额度并写入。写入时重新计算并要求不超过已准入的字节上界；完全不变化的合并不产生新写入。旧密文仍在现有用量中，新临时文件与密钥计入新增峰值。缓存读取、加密大小及节点预留继续使用前一阶段的保护。

本地写入采用与已有文件事务相同的父事务额度锁协议，没有另造可按 TTL 释放的本地预留记录。取消等待实际线程结束；API 进程退出后，已落盘字节仍由用户私有路径计量。进程猝死交错尚需本接入点专项验收，不能仅凭正常取消测试声称已覆盖全部故障。

## 图片与远端额度

图片新增用量按两份计量：私有输入计入操作用户，公共副本计入算例工作区所有者；所有者相同时合并为两份字节量。不同所有者按固定用户顺序获取额度锁。当前实际图片矩阵覆盖同一所有者，跨用户协作授权与图片结算仍待专项。

`Session.access` 新增显式容量选项。图片提交先取得算例所有者的 S3 容量 scope，再进入 case 写锁；若私有副本也由该所有者付费，为它在远端 scope 保留字节。物理 PUT 沿用既有永久 CAS 账本，公共副本及元数据不能用掉私有副本保留的空间。提交、线程排空和远端账本收尾的责任保持在同一 scope 中。

FS 图片仍由同一个父事务用户锁协调；原有节点预留继续覆盖本地副本。模型 turn 的 owner 分配、审批记录和启动流程继续使用既有路径；此次未用模拟模型结果去触发这些流程。

## 实际验收

显式入口 `platform/server/live_llm_cli_user_capacity_acceptance.py --source-profile-id 26 [--postgres --s3]`。FS/SQLite 与真实 SeaweedFS/PostgreSQL 各 9 项，共 **18 项实际基础设施检查**，纯协议/模拟故障 **0 项**：

1. 已安装的真实 Windows CLI 经用户额度准入后初始化并关闭，根进程真实退出。
2. 实际剩余额度仅 32 KiB 时，64 KiB 初始化上界被拒绝，未创建私有会话目录或 CLI 进程。
3. 剩余额度 128 KiB 时，实际平台私有初始化通过。
4. 剩余额度比实际缓存更新峰值少 1 字节时，拒绝且旧密钥/密文哈希不变。
5. 恢复额度后，实际缓存合并提交并可重新解密。
6. 用第二个真实用户对第一个用户的缓存计费时拒绝路径绑定。
7. 剩余额度比两份图片少 1 字节时，两份都在写入前拒绝。
8. 实际私有/公共图片内容相同；S3 路径真实容量账本最终 closed、pending 为空、SQL remaining_bytes 为零。
9. 实际初始化写入后暂停函数返回，连续三次取消调用方；用户锁保持到线程返回。SQLite 竞争事务等待后通过，PostgreSQL 竞争请求返回 409，原线程排空后新请求正常通过。没有替换文件写入结果或 CLI RPC 回复。

证据：[FS/SQLite](../../tmp/live-cli-startup-m4v062wu/cli-user-capacity-checks.json)、[S3/PostgreSQL](../../tmp/live-cli-startup-chogoh7i/cli-user-capacity-checks.json)。两套 API 已退出，两个 CLI 根重新核验退出，节点预留无残留，临时 PG 已删除，真实对象存储已停止。测试只修改隔离用户的套餐并在结束时恢复，开发数据库未修改。

## 真实模型与边界

两套平台 Agent 实际使用 `read_text_file` 读取验收摘要，流式输出和持久回答严格一致：[SQLite 回执](../../tmp/live-cli-startup-m4v062wu/live-result.json)、[S3/PG 回执](../../tmp/live-cli-startup-chogoh7i/live-result.json)。合计 **4 次真实 `api.deepseek.com / deepseek-flash`，全部 HTTP 200，17,196 tokens，模拟 LLM 0**，2 组模型读回通过。

CLI 内部推理、模型提出秘密问题及完整图片/审批/取消回合仍未验收。本轮图片直接执行生产容量 helper 和文件 publication，S3 通过真实授权 case 容量 scope；不能将它当作已经跑通原生模型回合。

此次初始化额度只覆盖平台宿主初始化函数负责的写入。稍后的 WSL 原生初始化、CLI 自行产生的日志/状态/临时文件仍须运行期用户约束；WSL 已有原生根尚不在用户和宿主节点总量库存内。因此原生全生命周期额度、硬资源边界、跨 worker 提交猝死、未知远端写入和协作用户专项继续，不能由本轮锁和正常账本结清推断全部通过。
