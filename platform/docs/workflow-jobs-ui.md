# JobsPanel工作流视图与验收

2026-11-11～12（北京时间）。对应原主线N6-04：展示流程、步骤、当前尝试、取消与失败原因；排队、运行、收尾和中断有明确提示，避免重复操作。原条件已完成，主线41/53、剩12；后续N6-05继续。本页记录实现、实际运行证据及边界，封存见`tmp/mainline-N6-04-closure-evidence/validation.json`。

## 用户可见行为

JobsPanel新增“工作流”和“作业与日志”视图。流程列表按状态筛选，每次20条，可继续读取更早记录；每3秒及算例对账事件后刷新。详情显示输入修订、运行目录、有序步骤、当前尝试、其他历史尝试、来源流程及错误诊断。单独提交的命令仍在原作业列表中。

步骤按后端核验的`active_attempt_id`选择当前尝试，不根据数组位置、最大尝试号或最新Job猜测。对应作业按钮打开实际日志和原恢复入口，“返回所属流程”恢复同一流程。记忆中的流程ID同时绑定算例ID；换算例后先显示未选中状态，不能把旧流程当作新算例的当前流程。

取消使用当前流程版本，提交期间及`cancelling`状态禁用重复操作。回执立即更新详情和列表，并用单调版本保护已接受的记录；旧列表响应后到不能把“正在取消”退回“运行中”。实际进程停止和输出归档未结束前保持等待提示，不把取消请求等同于停止证明。

收尾中明确说明输出正在归档和核验发布。失败给出中文原因和下一步日志入口，退出码保留，内部代码和原始服务诊断放在“原始诊断”中。未知原因保留核查提示，不猜测根因。输入检查成功说明无需启动作业；等待、受阻或取消的阶段确认明确显示尚未确认，只有权威成功状态使用已完成措辞。“前往算例阶段确认”只切换面板，实际确认仍由原阶段接口和用户明确操作完成。

读取失败保留最近记录，显示刷新错误并禁用取消；恢复连接后重新读取详情才恢复操作。既有输入恢复入口保留在可展开区域。新界面沿用`--vf-*`深浅主题、原字体和控件；小于600px的目标面板上下排列列表与详情，按钮最小44px，键盘可见焦点2px。

## 实现入口

- `web/src/panels/JobsPanel.tsx`：视图与作业/流程双向导航，选择绑定算例。
- `web/src/panels/WorkflowRuns.tsx`及`WorkflowRuns.css`：实际分页、轮询、详情、取消、诊断和状态提示。
- `web/src/utils/workflowRuns.ts`：类型、状态说明、确认步骤与原因文案。
- `server/app/services/workflow_execution.py`：详情在既有归属核验后返回明确的当前尝试ID。
- `server/workflow_jobs_ui_acceptance.py`：隔离FS/SQLite、真实CadQuery及浏览器分阶段验收；不启动开发环境8000端口或修改开发库。
