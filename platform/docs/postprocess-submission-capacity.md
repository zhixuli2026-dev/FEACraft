# 后处理提交的输入封存

2026-11-22，公开 `postprocess:run` 的两条提交路径在写事务外准备输入。直接读取算例文件时，准备范围包含运行目录、实际配置与参考文件，以及后处理输出的覆盖前提。引用已确认求解成果时，先核验归档、递归依赖与活动版本，再复制所选输入。提交事务重新授权，复核数据库中的成果归属、活动版本及物理文件或对象版本，随后绑定作业、成果和投递。

两条旧路径都用真实 OpenFOAM 导热算例复现了问题。复制 40 MiB 输入时，SQLite 的独立写入被阻塞，同算例保存返回 409；原提取仍得到了 350 K。修复后，直接读取算例文件的路径可以在实际复制期间保存同算例的无关文件，返回 200，提取结果仍为 350 K。

历史对照使用第一份已发布成果里的温度指标。实际替换了公开可见的旧 `metrics.json` 后，第二次提取仍从不可变归档读取原值，比较误差为 0，原键回读原作业。首轮对照的参数缺少明确的被比较指标，作业完成且读取了正确的历史归档，比较项仍显示指标不存在。修正算例配置后完成复验，首轮记录已保留。

认证 SeaweedFS 配 PostgreSQL 分别暂停在 40 MiB 运行输入已复制、33,834 B 已确认求解归档已验证的时点。同账户另一个算例的保存均返回 200，两次提取结果均为 350 K。首次提交返回成果 ID 和代数，原键回读原作业和状态。文件系统配 PostgreSQL 在复制中撤下活动求解版本，提交返回 409，数据库没有新增作业。恢复活动指针后，用原键完成提取，省略运行目录的同键请求也回读同一个作业。

本地测试在 40 MiB 实际复制期间触发四秒期限和真实客户端断开。两次均在复制排空后释放资源，超时返回 504，无作业落库，按原键重试得到 350 K。

SeaweedFS 配 SQLite 在封存已安装后写入等长源对象，提交返回 409，数据库没有新增作业。按原键重新准备后，提取得到 350 K。

本阶段使用真实 OpenFOAM、VTK 和存储，模型调用为 0。证据纳入 N4-05 的 RB-12 和 RB-14。 [专项验收](../../tmp/N4-05-postprocess-submission-20261122/validation.json)
