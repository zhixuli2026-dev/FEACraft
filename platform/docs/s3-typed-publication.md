# S3 类型命令发布与条件兼容文件

本批把 `/jobs` 中 `mesh`、`solve`、`geometry`、`pvpython`、`convert` 五种无固定 argv 的通用命令接入 S3 独立尝试和不可变发布。类型名称不代表已通过正式专业工作流证明；结果仍使用独立的 `case-command` 发布频道，不能冒充正式 geometry/mesh/solve head。

## 已实现的主流程

提交阶段检查存储端是否真正执行条件创建、更新和删除，再以 ETag 条件读取远端算例文件，复验所选对象集合，形成来源快照。随后封存远端输入并创建独立执行目录。输出仍先保存完整清单及远端上传回执，专业发布前同时核对远端私有输出和结果包内容。

成功发布继续使用现有数据库归属、当前代次、来源预留、事务和终态事件。来源读取现在支持远端，并能将已发布的输出和删除还原为原始输入进行新鲜度比较；S3 中删除一个目录的最后一个文件时，通过原输入路径重建目录关系，避免把没有空目录标记误判成来源变化。

兼容文件计划保存在远端不可变 `aliases.json`，绑定发布摘要、case/attempt/publication 与存储目标。执行前检查所有目标，再为每个目标重新获取当前 ETag：新文件使用 `If-None-Match: *`，覆盖与删除使用 `If-Match`。条件不满足就保留用户的新内容；没有使用无条件操作作为回退。写入后复验结果，全部完成才保存应用回执。部分操作已完成时，重试可识别原内容和目标内容，继续未完成操作。

不同命令具有独立发布频道。并发作业可能都从同一份输入完成不可变结果，也可能因为先发生的兼容文件更新而在来源校验失败。不能一概要求只产生一个成功结果；同一个兼容路径仍必须受条件写保护，冲突分支在完成记录中保留 `alias_error`，自身不可变结果不被覆盖。后续 `require_current` 引用还会重新检查当前来源。

`input_publications` 已允许使用经过远端清单、文件和数据库归属验证的缓存。新 API 使用独立本地缓存时，可以选择当前结果作为输入；来源变更后，当前引用拒绝，明确的历史引用继续读取原不可变版本。选择整个含执行元数据的结果包仍会拒绝，调用方需要选择实际产物路径。正式多步骤处理器的完整递归工作流验收仍属于后续范围。

## 存储端兼容性

旧 SeaweedFS 3.99 会忽略 `DeleteObject If-Match`：即使版本错误仍删除对象。应用在自己的随机测试键上检查三类条件操作，旧服务不会获准执行通用类型命令发布；普通私有 shell 作业仍可运行。每次应用兼容计划前也会检查，避免仅凭客户端接受参数就执行用户文件删除。

本批另外下载了[官方 SeaweedFS 4.52](https://github.com/seaweedfs/seaweedfs/releases/tag/4.52)，保留原二进制，使用独立临时服务验证。官方[条件操作说明](https://github.com/seaweedfs/seaweedfs/wiki/S3-Conditional-Operations)描述了条件更新及删除的原子语义；本机实测错误版本返回 412 且保留原内容，正确版本正常执行。下载归档 SHA-256 为 `8b538c22d47d0c3fb6792adaa6b0c735a967401270a53427d5a476dcaca9b7ae`，解出的 ELF SHA-256 为 `ce138fc99edc946ebd4d38589543f717e388bfe0b45186c06cff6ee6734ee8df`，路径 `third_party/seaweed-4.52-runtime/weed`，安装回执见 `tmp/seaweed-4.52-install.json`。

开发及生产 Compose 的可选 S3 镜像统一固定为 4.52。没有启动或升级现有 Docker 服务，没有迁移开发数据库或访问开发 bucket；生产默认仍为 fs，`allow_partial_s3` 限制保留。Compose 配置渲染验证不等于容器部署验收。

新版本首次分配卷时，测试夹具原来的 3 个卷上限与默认一次创建 7 卷不匹配，并且首次分配超过原 3 秒客户端超时。本批仅为临时测试服务写入每次分配 1 卷的 master 配置并调整有界超时；原失败日志保留，先检查旧进程确实退出，再重试，未重复启动仍存活的实例。

## 验收与余项

真实 S3 HTTP 验收分两次完成 17+7 项，涵盖五类命令、Windows/WSL、空结果、删除、失败、初始场保护、用户修改、取消、超时、并发私有输出、远端捕获输出损坏，以及独立缓存的当前/过期/历史引用。实际 `blockMesh`/`icoFoam` 场结果、求解证据和后续引用通过；伪求解与坏场文件不能替换原有效结果。独立条件操作验收为新服务 7 项、旧服务拒绝 1 项；本地同类命令 16 项、兼容文件日志 4 项以及 Compose 配置 8 项同时通过。最终执行分组和源代码归档见 `tmp/mainline-N2-s3-typed-publication-evidence/`。

保留了测试夹具初次使用简略 POST 响应、错误导入和 Windows 多行命令的问题，不将这些失败记为产品验收通过。并发命令最初仅执行了第一行，没有产生预期输出；后续增加逐一读取私有结果的断言，并通过单行十六进制载荷执行原多行 Python 测试代码。最终测试必须看到每个作业实际生成的独立内容，不能仅凭退出码或“成功”状态通过。

余项仍包括全部正式专业处理器的 S3 接线、正式步骤间递归依赖、完整工具链和外部依赖记录、跨操作系统来源权限语义、跨主机所有者恢复、丢失运行缓存的输出恢复、pending 上传补传、孤立前缀回收和完整 UI/CAE 消费验收。本批不关闭 N2-03/N2-05/N2-06，也不提前关闭 295 项中的整项要求。
