# 专业校验完成后的产物复制恢复

本批继续N5-04/N2-06：专业原生校验已完成，复制不可变产物包时API退出，或包已经复制完而原始写入排空检查点尚未提交。恢复保持原Job、attempt和发布代次，继续复制及最终提交，不重新运行求解、编译或专业artifacts校验。

原执行器只有在回调、证据、暂存同步、日志、专业校验及原生子执行都已完成后，才调用复制前准备记录。`prepare_bundle_for_finish`先确定最终generated_paths和求解结果退休清单，然后将确切manifest作为文件journal意图保存；数据库`bundle_preparation`绑定该manifest哈希、输入/输出/发布预留、worker与根/子进程身份，以及原始成功停止回执。同一事务追加`attempt.bundle_preparation_ready`。新记录不表示文件复制完成，也不提前暴露成功。

保存准备证明之后，本attempt不能再启动原生执行。文件复制仍在数据库事务外进行，继续允许普通编辑请求按既有协议进入；没有为了简化恢复而提前占用整个来源校验窗口。最终来源与依赖校验仍会识别期间的输入变化。

重启时，后台恢复任务核验原worker的精确出生身份确实已退出，重新确认lineage、输入/输出/准备证明及原始持久事件。缺失或损坏的证明、活owner、未知owner及变更的原始输出都不授权重算或覆盖。对尚未完成的副本，重新核对封存输入和原产物哈希后使用已有journal继续复制；部分副本保留在journal的interrupted目录，完整副本直接核验复用。复制计划在诊断后再次读取时也重新核对数据库绑定哈希，不能把被替换的journal当作新的可信来源。

恢复进程完成自己的复制线程后写入**v3写入排空检查点**，明确区别于原owner的v1和历史终态恢复的v2。v3保存原始准备事件ID/哈希、原停止回执、原owner观察、恢复观察者出生身份和时间；`attempt.bundle_copy_drained`与该检查点同事务。不得将新观察伪装为原进程创建的停止或排空证据。

随后复用[提交前收尾恢复](prepared-finalizing-recovery.md)与[提交后兼容文件恢复](publication-alias-recovery.md)。两条路径都复核v3对应的原始准备事件和复制排空事件。准备证明、复制检查点、最终提交之间再次退出时，下次启动仍可继续；已经完成的bundle不重复改写。最终成功/失败、发布指针及outbox继续由原事务负责，不增加Job/attempt或计费终态。用户离线修改了当前来源时，保留已生成的bundle并按原来源失效规则失败。

验收使用真实Pandoc报告：复制前、部分复制、完整复制、恢复复制后再次退出、v3检查点后再次退出、检查点历史损坏、原产物修改、来源修改、准备证明缺失/损坏、双API竞争及活owner。另验证真实LaTeX PDF/SyncTeX的部分复制和检查点后退出，并保留原文件journal进程故障与复制/取消/心跳/提交失败断言。

此批尚不关闭N5-04/N2-06。证据生成、暂存同步或专业原生校验还未完成的更早中断，需要各自的持久阶段证明与恢复策略；旧无证明记录不能凭文件存在推断成功。通用文件写入/删除、旧专业准备文件、封存目录、S3和跨主机协议仍按原计划交付。主线53项和全功能295项范围保持不变。
