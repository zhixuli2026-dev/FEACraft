## 实现与成功条件

`TerminalSession` 在返回 WebSocket ready、接受输入之前，登记独立的 `terminal.export` NativeRequest。外层受控启动门核对实际终端进程身份并打开其 tmpfs 目录；目录描述符传入导出进程自己的 PID 命名空间。导出进程与终端拥有独立的进程范围和退出证明，不会随终端关闭一起被清理。工作副本仍是 128 MiB tmpfs，仍使用 user/mount/net/PID 隔离和 nobody。新终端模式不挂载共享项目到 `/output`，也不执行旧的直接复制。

取得完整终端退出证明后，导出器核验同一进程范围的回执，再读取保留的目录。导出拒绝符号链接、硬链接、特殊文件、跨挂载点、路径碰撞和扫描期间修改；限制总数据 128 MiB、10,000 条目、32 层目录和 4 MiB 清单。导出过程保留节点磁盘预留，失败副本继续计入实际磁盘用量。

本地文件通过现有 SQL 见证的文件事务发布，逐个核对开始时的内容哈希；S3 通过私有 staging、远端写入占用和条件事务发布。并发修改目标文件会拒绝整批发布，不覆盖另一方的数据。新增、修改、删除文件均已实际验证。成功后记录 `terminal.export_published` 事件；终端 `process.export` 必须指向匹配的已提交事件和成功导出请求，才能记录 closed。进程退出和文件保存是两个独立条件。

启动脚本改用挂载命名空间私有的 `/tmp`，避免不同沙箱的 PPID 都为 0 时互相删除目录。该目录随命名空间释放。原有 Job 的正常退出复制模式保留；本次没有证明该旧 Job 模式的强制关闭数据保留。

迁移 `f3d8fa4179bc` 增加 `terminal.export` 请求类型；存在导出历史时禁止降级。开发数据库未迁移。已有终端历史仍按旧协议读取，不追认其文件保存已验证。
