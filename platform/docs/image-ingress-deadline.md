# 镜像清理路由的入站与认证期限

2026-11-07，接续[业务入口共享期限](image-request-shared-deadline.md)。此前默认 300 秒从清理服务开始，慢请求体和认证依赖不在该预算内。本次将同一个期限提前到镜像清理 POST 路由的处理器入口；请求体解析、登录用户查询、业务准备、原生执行与最终提交都继承剩余时间。

## 实现与边界

`ImageCleanupDeadlineRoute` 包裹 FastAPI 的请求处理器，覆盖读取请求体及依赖解析。仅镜像清理 POST 使用该路由类，查询和其他接口保持自己的现有生命周期。清理服务自身仍设置同一默认预算，供非 HTTP 调用使用；嵌套范围取更早期限，不能重置已经消耗的时间。

期限到达后返回现有 `409 / image_cleanup_incomplete` 协议，并提示查询记录确认结果。处理器尚未发送响应，因此不会在已开始发送的响应上追加第二个错误响应。受保护的线程、预留和提交继续实际收尾；已提交的完成记录仍是查询和重试的依据。处理器返回前再次检查期限，避免受保护操作迟到返回被报告为未超时成功。

本次期限从应用路由被选中开始，不包含代理排队、TCP 建连和 HTTP 头尚未交给应用的时间。FastAPI 的依赖退出和响应传输在处理器返回后由框架完成，不声称覆盖慢客户端响应下载、不可中断系统 I/O 或整站请求预算。请求体大小、全局队列和其他业务入口仍需各自的资源约束。

## 验收设计

显式入口为 `platform/server/live_llm_ingress_deadline_acceptance.py --source-profile-id 26 [--postgres]`。执行前审查了它导入的真实模型适配、退休算例、共享期限算例、隔离服务器、迁移和实际进程退出核验辅助代码。模型适配继续调用实际 `httpx` 发送函数，只记录响应身份和用量；不替换模型回复、流、工具选择或 CLI 推理。

- 实际 TCP 连接发送 HTTP 头和不完整 JSON，再发送少量字节，验证读请求体不能刷新期限，也不能进入清理服务。
- 实际数据库用户查询完成后暂停认证回调，验证取消发生在进入清理服务之前。PostgreSQL 另由独立事务持有真实 `users` 表锁，验证正在等待的认证 SELECT 会到期。
- 慢请求体先消耗预算，再完成输入；记录清理服务收到的绝对期限及剩余时间。实际归档读取结束后的受保护回调跨期限等待，必须恢复后才能响应，不能丢弃收尾责任。
- 正常缺失认证和不满足确认条件的请求仍分别返回 401、422，不创建清理记录。
- 继续实际八位置业务矩阵：数据库锁、归档、节点准入、配置、owner 提交、原生放行前归档、最终提交前、提交后。验证唯一完成、旧请求记录不被改写及实际进程退出。
- 最后由真实 DeepSeek 自主选择文件读取工具，读取实际恢复的随机证明并流式回答。基础设施检查不能代替此项模型验收。
