## 实现及适用边界

S3 输出清单必须与 SQL 保存的实际输出及对象回执一致，校验 attempt/case/run 归属、完整文件集合、大小及 SHA。续算时创建独立、带进程所有权记录的 `.attempt-sources` 临时视图，流式下载并校验实际归档输出；重新读取归档清单后才交给检查点验证。下载前整体预留节点空间，文件日志先 fsync，复制后再次验证大小和哈希。不会将只恢复了原始封存输入的初始 run 目录当作实际计算结果。

组合新封存输入时，原始输入来自原封存，检查点场来自已校验的输出视图，派生控制与检查点清单明确标记为生成输入。视图绑定原输入及完整输出清单；复制、配额、计划与 SQL 见证仍走正式封存流程。取消必须排空检查及复制后再清理临时视图，不跳过归属或内容验证。

已提交的相同幂等请求在授权及请求摘要核对后，先返回持久结果，再考虑新写入准入。新增请求仍必须取得真实用户存储写入额度，并在额度内复核；不会因为旧请求正在写入就重复执行。

## 性能修正与冲突保护

- 整个已知读取视图一次预留数据和日志空间，替代每个文件重复扫描节点库存；仍逐文件保存哈希日志。
- 不可变内容校验只并发执行最多 4 个只读流，先构造实际 S3 client；每项大小/SHA 必须吻合，发生错误后不再提交新读取，并排空已发出的读取。依据 [Boto3 官方 client 并发说明](https://docs.aws.amazon.com/boto3/latest/guide/clients.html)，不并发执行可变对象提交。
- 发布计划继续核对所有不可变成员的实际字节，包括不作为兼容别名的文件。兼容文件的不可变内容准备完后，通过一次条件 HEAD 提交整组引用；当前目标变化或 ABA 拒绝，只有无关路径变化可有界重试。
- 旧的已编辑退役结果保留；其余当前产物仍可发布。实际提交后丢失响应时，以持久引用及后续校验辨认，不能凭超时推断没有提交。
- 网格/求解的当前输入检查只下载 `0-caseDict/caseDict`、选定运行目录的 system，以及可选 constant、0、0.orig。缺少必需输入仍拒绝；检查前后都检查可选范围，新增初始场不会漏检。生成时间目录、日志和报告从未参与这个输入指纹，无需复制进输入检查视图；输出内容与数值验证保持完整。
- 冷发布缓存使用同一次真实对象流同时验证大小/SHA 并写入独占缓存，复制前后复核完整远端清单；存在缓存时仍完整读取远端内容。先由主线程创建及验证公共父目录，再并发读取独立成员；任何读取失败都排空后清理部分 stage。其他读取者恰好安装缓存时，本请求仍需独立完成远端内容验证。
- 逻辑 S3 paginator 每次迭代只组装一次完整列表，用稳定排序及游标切片返回后续页，避免每一页重新扫描所有物理私有对象。独立的下一次迭代仍重新读取状态；case 输入检查前后的版本比对保持。物理对象底层分页仍使用实际 S3，不宣称外部对象服务提供了全局原子快照。

完整算例仍为 400 单元 icoFoam、固定步长 0.0005、终点 0.5、每 10 步写出；未缩小真实计算或输出规模。作业预算仍为 120 秒。S3 原生验收单独使用拥有者独立创建、16 个 32 MiB 卷上限的本地 SeaweedFS；此前 3 卷测试夹具实际耗尽，这一修改不改变生产配额。
