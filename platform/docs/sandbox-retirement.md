# 异常沙箱会话收尾与真实模型读回验收

2026-11-07。原 API 猝死后，已退出的终端和导出请求可能仍为 active、没有正常停止回执，因而持续阻止算例校验。本次增加独立收尾凭证、确认接口和界面：验证保留快照及所有原进程身份已退出，再原子地封住旧记录。原进程日志、子进程状态和未知退出码保持原样。

## 已实现

- `GET /api/v1/terminal/sessions/{sid}/retirement` 查询经过完整校验的持久结果；`POST` 要求 `recovery_id` 和 `confirm: true`。
- 核对快照完成回执、真实 ZIP 全量哈希、原记录指纹及当前权限；实际观察原 API 所有者、终端宿主/native/gate 和导出子进程身份，必须全部为 exited。未知身份、PID 身份不符、活动进程均不获准收尾。
- 持有算例控制锁后再次核对来源与记录。旧终端和未成功导出记录改为 failed（原 cancelled 保持），递增版本，指向与状态更新同一事务提交的 `terminal.sandbox_retired` 事件。成功且已核验停止的导出保持原样。
- 凭证绑定收尾前后记录指纹、实际退出观察、原退出码、恢复请求和回执。没有把未观察到的退出码填成 0，也没有改写正常 stop/children 日志。
- 算例校验检查整组凭证后可放行；移动等管理操作仍要求原暂存已处理，S3 留存暂存不能被这一步默默丢弃。每进程最多两个收尾操作并行，归档验证有既有限额和期限。
- 同一会话、同一快照的重复确认返回已有结果；另一快照不能替换原凭证。浏览器先保存确认、结果不明时只轮询 GET，重开继续查询；POST 重试必须由用户操作。
- 新迁移 `b5f0cd6391de` 增加两个外键及状态/类型约束；存在收尾绑定或收尾事件时拒绝破坏性回退。只迁移了隔离测试库，开发数据库未改动。

真实模型算例完整经过 WSL 写入随机内容 → API 猝死 → 只读快照 → 旧记录收尾 → 确认写回 S3 → 模型调用 `read_text_file` → 流式回复与会话持久化。随机完整验证串没有进入提示词，只有实际文件读取能提供它。上游观察器仅记录真实请求状态、响应 ID、model 和 usage，不替换请求结果或生成回复。开发凭据只读解密，在隔离 vault 使用，不写入报告。

模型正确读回完整随机串，但附带额外说明，并未完全遵守简短回复要求。因此本次证明恢复后的真实工具读回和续答链路，**不证明严格输出格式或全部 Agent 能力通过**。整个单元模拟 LLM 调用为 0。真实模型运行中重复的基础设施检查不再次累加到上表 12+6。

前端构建和限定范围 lint 通过；新组件无 lint 告警，原恢复组件保留三处 effect 告警，既有大 bundle 告警仍在。截图在最终会话状态文案改为“异常结束”之前拍摄；最终构建已在浏览器重新核验文案与持久收尾结果。
