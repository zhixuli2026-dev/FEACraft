# LaTeX 停止后的编译副本回收

编译副本位于所属尝试的 `.latex-compile-<32 位十六进制>` 目录。作业正常退出时由编译工作进程回收。取消可能结束工作进程，使其退出前的清理无法执行。此前在认证 SeaweedFS 算例中实测进程范围已经清空，算例所属节点仍保留编译副本。[修复前回执](../../tmp/FF-E04-absolute-resources-20261122/validation.json)

作业内容写入完成排空后，回收流程核验持久停止凭据、算例及尝试归属和本地输入清单。随后用既有目录清理逻辑逐项回收，和数据库写事务分开执行。回收完成后只记录一次 `attempt.latex_compile_cleanup_completed`。遇到 Windows 共享冲突时保留待处理目录，进程停止及取消结果仍按正常流程记录。同节点的启动恢复和工作进程对账均可继续清理。

清理范围是该尝试下的编译副本。封存输入、作业运行目录、日志和历史发布仍由各自既有流程管理。完成清理前，目录中的受控阶段仍可通过本地物理路径核对。已提交的停止凭据也能供 API 在两次启动之间接续清理。

恢复取消终态时同时核验原所有者进程已经确切退出、原写入排空事件、父子进程停止记录和取消请求。提交前在算例协调锁内复核同一份绑定，再使用正常作业收尾流程提交 `cancelled`，保留原停止凭据。

## 实测

- 认证 SeaweedFS 算例用实际非特权 WSL pdfLaTeX 打开绑定文件，第二个 API 随即取消。父子进程停止范围为空，编译目录当场回收。封存输入、运行目录、旧 PDF、冻结源文件和旁边的其他目录通过独立读回。回收事件只有一条。[认证 S3 回执](../../tmp/FF-E04-compile-cleanup-20261122/s3.json)
- 本地文件系统组在编译副本里实际持有 Windows 独占文件句柄。取消终态正常记录，文件仍可定位。释放句柄并退出两套隔离 API 后，重启回收了剩余目录，历史 PDF 仍按原字节读回。[Windows 锁与重启回执](../../tmp/FF-E04-compile-cleanup-20261122/fs-restart.json)
- 第一次在写入排空提交后终止原 API，发现重启回收了副本但尝试处于 `cancelling`。修复后在同一窗口再次真实退出原 API，重启将同一尝试收尾为 `cancelled`，保留原停止凭据，记录一次恢复事件。另一 API 启动时也核验了正在编译的副本依然可用。[修复前尝试状态](../../tmp/FF-E04-compile-cleanup-20261122/owner-exit-baseline.json) · [实际退出与恢复](../../tmp/FF-E04-compile-cleanup-20261122/owner-exit.json)
