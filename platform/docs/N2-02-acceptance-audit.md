## 原条件与当前入口

| 入口 | 当前实现与冲突边界 |
|---|---|
| 普通文本、整文 caseDict | `files.py` 在 `coordinate` 内刷新 Case 并核对 revision/hash；编辑器保存打开时的基线，仅用提交回执更新基线 |
| 块、扩展、错误表单及 LaTeX 插入 | 相同协调器与结构化 409；`useCaseDraft` 保留草稿和旧基线；LaTeX 插入按读取 hash 更新并单独保留备份 |
| Agent 批准及全权限提案 | `ToolExecutor.apply_proposal` 在锁内核对持久提案的基线；普通文件进入文件事务，字典走同一镜像/阶段规则；SSE 保留失败结果 |
| 普通上传、删除与分块上传 | 普通入口使用版本/不存在条件；分块会话保存开始时的目标基线，完成时重新核对；恢复回执不覆盖后续修改 |
| 阶段推进及失败回退 | `engineering_stage.advance` 在锁内核对必需 revision、用户确认及专业证据；修改通过字典事务；不能通过普通保存绕过阶段规则 |
| 专业直接写入 | CAD WS、几何修复/预览、网格质量、UDF 模板、批次清单、图片、memory 均在协调器内；文件事务统一拒绝执行版本路径 |
| 专业作业与工作流 | 已注册 25 个处理器通过独立输入/运行目录、来源复核、发布保留和受控别名更新；18 个提交调用点的原核对继续有效 |
| 终端、viz、Agent Shell/CLI 的 S3 同步 | `staging_sync.collect` 排除受保护命名空间；同步前比较原目标版本，持久占用与 SQL 证明协调发布，不能把旧 staging 中的伪造封存对象写回 |
| 创建、复制、备份与回收站 | 创建使用独占暂存及提交证明；读取源受协调保护，复制/备份不移植原 attempt 所有权；成员与回收站在锁内复核 |

这里的“同一协议”指相同的 case 控制锁、基线复核、封存路径保护和可识别冲突，不要求 HTTP 与 WebSocket/SSE 使用相同传输格式。普通工作副本保留历史客户端的无条件写入兼容；执行输入始终使用另一个不可变副本。再次提交创建新 attempt，重试使用原封存输入。没有把旧客户端的工作副本编辑偷换为对既有执行版本的修改，也没有宣称任意外部原生命令已受数据库锁约束。

`file_transactions.write` / S3 对应实现要求协调上下文并检查 `assert_mutable_path`；普通 storage、上传、Agent 同样检查。封存命名空间及 Windows 大小写/尾点别名拒绝写入。已提交的专业运行结果不通过用户可指定路径直接覆盖封存输入。原生进程在应用协议之外的访问能力继续属于 N4/N7。
