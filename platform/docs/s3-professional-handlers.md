# S3 专业处理器与结果保护

本批接入余下 9 个正式入口：旧算例后处理、CalculiX、SU2、ParaView、OpenFOAM MPI、UDF 构建/集成、FloTHERM 转换/辅助库。验收已完成，规范证据在 `tmp/mainline-N2-s3-professional-handlers-evidence/`。S3 和文件存储各37项分批完成；原始失败日志及分批来源均保留。前一批见 [S3 文档处理器](s3-document-workflows.md)。

## 实现

各入口统一使用注册处理器，移除 S3 的旧作业提交分支。准备阶段在同一个版本校验读取视图内取得输入配置、依赖选择及输出前置状态，再封存到独立尝试。原生工具仍运行在独立目录，产物通过原有实际内容验证后发布；没有把成功退出或输出日志当成完整结果。

CalculiX 和 SU2 保留依赖解析、可执行文件摘要、可变重启输入及输出覆盖前置检查。ParaView、MPI、UDF 与 FloTHERM 保留全算例文件变化校验，当前来源查询通过 `case_read_view.delta_source` 重建发布前的输入状态。S3 删除最后一个对象后不会保留空目录，因此只对 S3 从还原后的文件集合重建父目录；文件存储仍保留真实目录状态。

UDF 集成的 controlDict、MPI 自动生成的分解字典、FloTHERM 复制源文件均随结果发布，准备与运行期间不提前写回用户算例。MPI 状态查询和 FloTHERM 输入格式/bbox 检查也使用读取视图，支持无本地缓存的远端算例。

## 验收发现的修复

FloTHERM 首轮转换已生成有效产物，但提交前的空目录检查显式选择了尚不存在的输出路径，触发“Selected S3 input does not exist”。改为在完整读取视图中验证输出目录不存在或为空；原有拒绝覆盖条件不变。

旧算例后处理首轮冲突检查发现真实覆盖漏洞：外部写入结果指针后，别名计划把新字节当成了可覆盖基线，未记录冲突。新尝试在准备时保存 D-post 的原文件摘要，产物验证后检查全部输出目标，并在不可变别名计划中固定同一前置条件。运行中编辑会阻止提交，提交后的竞争由条件写入保留用户文件。已有持久描述符缺少该字段时继续按旧契约恢复，不伪造历史前置状态。

并行运行两个后端时，本地 MPI 原生执行在 `pmix_gds_shmem_fetch` 中段错误，远端 MPI 测试则在等待收尾时超时。本机 `ompi_info` 报告 OpenMPI 4.1.6、PMIx 5.0.1a1；`/dev/shm` 和 `/tmp` 容量充足。尚不能仅凭堆栈断言具体共享内存碰撞机制，因此保留原始失败，不把推测写成已证实原因。修复为每次 MPI 调用显式传入 `PMIX_MCA_gds=hash`，封存在准备配置并记录/校验原生步骤收据；仅影响该子调用，不修改系统环境、通信传输、认证或进程隔离。已有会话/共享内存临时目录仍按 UUID 分离。依据为 [OpenPMIx 的 GDS 问题记录](https://github.com/openpmix/openpmix/issues/1747)及 [5.0.1 共享内存实现](https://raw.githubusercontent.com/openpmix/openpmix/v5.0.1/src/mca/gds/shmem/gds_shmem.c)，是否修复以两后端真实数值复验为准。共享 `invoke` 的默认调用保持原行为，UDF 复验覆盖该默认路径。

## 验证范围

远端 MPI 的第二、第三轮超时经日志和数据库复核：原生求解及 reconstructPar 均已结束，输出清单包含149个文件，任务正在捕获/发布收尾。它们不是新的原生崩溃。专项夹具将有限等待从90秒调整为300秒，并保存 `settlement-timings.jsonl`；默认其他测试仍为90秒。没有重复提交同一个写请求，也没有把超时运行记为成功。远端文件发布性能仍是明确待办。

第四轮 MPI 的实测收尾等待为157.172秒。进一步检查发现条件别名计划在每个文件处调用单文件读取，而该读取会重新验证整个远端包，产生平方级重复读取。`publication_alias_objects` 改为每个准备/应用批次完整校验包与缓存一次，每个源文件仍从远端读取并按清单摘要校验，目标仍逐个执行条件写入/删除。`s3_alias_objects_smoke.py` 在真实存储上新增67文件的读取次数上界、应用前损坏、完整校验后源字节被改写三项检查，并保留原竞争/中断/拒绝旧后端检查；另定向复验真实 MPI 产物和空缓存版本消费。早先完整处理器矩阵不声称在此最后优化后重跑。

最后定向 MPI 验证通过，149文件算例完成等待为27.969秒，相比此前157.172秒是本机单次对比，并非完整部署性能基准。条件别名当前后端10项、旧后端拒绝1项通过。

第四轮在 MPI/UDF 构建8项完成后，UDF 集成的空缓存当前引用曾返回“当前输入不可校验”409。原始 API 日志没有底层异常，数据库仅保存 `input_stale`，不能据此确定原因。增加异常诊断后的定向集成4项通过，包含当前/历史消费及三类冲突，但单次复验不证明间歇原因已解决。`publication_inputs` 现将底层异常连同 case/publication 标识写入服务日志，客户端错误及拒绝条件不变；这条日志改动不改变验证结果。此未归因问题仍列入后续恢复/跨环境工作，处理器接入清单完成不代表可靠性交付完成。

`s3_professional_handlers_smoke.py` 在真实隔离对象存储和临时 SQLite API 中运行；`--fs` 用相同检查验证文件存储，支持按 `--group`、`--kinds`、`--modes` 定向复验。
