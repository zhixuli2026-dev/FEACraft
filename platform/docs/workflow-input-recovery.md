# 工作流输入恢复与新旧流程关联

2026-11-11，N5-07输入恢复子阶段。主线38/53完成、剩15项，N5-07尚未整项关闭；全部295项全功能目标保持。

## 用户操作

从作业的“恢复与重新执行”打开“在原流程中核对输入”。服务端核验作业、尝试、步骤与算例归属后，显示原流程、步骤、原作业及已有新流程。注册流程使用原重算接口，可核验的旧v1固定图使用原迁移接口；工作流作业不能走独立作业的输入替换入口。

用户明确选择目标、计算目录、几何/求解/报告方式及新预算，核对当前输入版本，再确认回到A阶段并创建关联流程。原流程、步骤、作业、尝试和原输入记录保留。新请求持久记录来源流程、来源版本、当前输入观察及用户确认的阶段重置。B/C/D/E仍需使用已有阶段入口分别确认。

界面提供原流程与关联流程、原作业与新作业的导航。选中流程按账户、算例与原作业所属流程保存在当前浏览器会话；刷新后重新选择算例和作业可以回到该选择。当前流程的继续派发和取消使用原版本校验接口。

## 提交不确定性

确认先保存请求正文、原流程ID、动作和固定幂等键，再发送原`:recompute`或`:migrate`请求。网络中断后保留原确认，继续时回读或完成同一次请求。

收到明确的400/409/422后，界面调用只读的`POST /workflow-runs/{id}/recovery-request`核对原键。已存在则读取原流程；确认未创建后才允许修改被拒绝的确认。该查询先重新核验写权限，再按账户、算例、键与完整正文摘要查找。网络超时本身不允许丢弃原确认。

## 核验边界

新增`GET /workflow-runs/{id}/recovery`返回当前算例版本、原流程、迁移/重算入口和关系。关联新流程的查询按事件序号分页，同时核对`workflow.created`事件与目标计划的来源，不能仅凭任意文本中出现的ID建立关系。损坏计划仍能显示原流程身份，但不给替代执行图。

重算现在复用迁移入口的原作业排空检查，在释放控制事务进行依赖检查之前、以及最终提交新流程之前分别核验。未领取但带有未知worker、进程、子进程、写入或输出记录的旧尝试也拒绝。流程终态不能代替停止或写入结束证明。工作流详情拒绝步骤尝试关联到其他算例作业的记录。
