## 已实现行为

- 主输入、递归 INCLUDE、`.rin` 重启文件、已有 `.eig` 及卡片声明的输入依赖进入封存清单；缺失、循环、越界路径在创建作业前报错。INCLUDE 相对作业根目录解析，保持 CCX 的原生规则。
- 生成的配置只存在于私有输入目录。工作进程通过所属作业的原生子执行通道启动固定 CCX 可执行文件；可执行文件摘要、输入摘要、执行标识、输出摘要及日志绑定到收据。成功发布要求原生进程停止证据和匹配的收据。
- 检查本次 DAT/STA/CVG/FRD、FRD 结束标记与原生日志；不把非零位移作为所有分析类型的成功条件，因此零载荷、热分析或模态分析不会因缺少静力位移而被统一误拒绝。
- CCX 的 Fortran 输出例程在第一个空格处截断作业名。路径含空白时使用私有安全文件名求解，再映射回原路径；原始输入及 INCLUDE 路径不被改写。
- 发布前重新验证输入和输出目标：计算期间改动包含文件、用户改写输出、取消、损坏配置或收据，都不能覆盖已有成果。发布后的 `.eig` 用本版本的摘要识别，避免把本次生成文件误判成外部输入变更。
- 不可变历史保留，后续作业可以显式选取当前版本或历史版本。复制阶段 API 退出后从已验证意图恢复，同一求解不会自动重复执行。

## 验证与边界

验收脚本：`server/calculix_publication_smoke.py`。使用真实 CalculiX 2.23，覆盖 C3D8 静力数值与约束、两层包含、实际重启读写、模态 eigenfile、含空格路径、幂等、历史引用、来源过期、空操作不复用旧成果、目标编辑、取消、收据/配置破坏及 API 退出后的发布恢复。SQLite/PostgreSQL 结果及实际运行目录记录于本批证据索引；没有把测试数量当作功能完成比例。

原 `calculix_scope_smoke.py` 继续使用 20,000 步真实求解输入，确认已有计算增量后取消、超时、终止 API，检查 CCX 实例确实退出、外部无关进程仍存活、用户输入不变。其检查位置现为私有运行目录及持久化子执行身份；原中断语义保留。

开发数据库和端口 8000 未参与测试。S3 仍使用原路径，尚未迁入该发布协议。矩阵装配、子模型、裂纹及视角因子的文件依赖按官方读写规则处理，但本批没有逐一完成这些物理分析的数值验收；本文件不代表 CalculiX 全部分析类型或 FF-C08 整项完成。

本批曾发现并修复：发布分支误插入导致 `row` 未赋值、CCX 空白文件名输出截断，以及新输出目标必须校验已有父目录而不能要求目标预先存在。失败日志保留。先通过的双库运行与新增空操作/来源过期检查后的最终运行分别记录。

共享原生监督回归另外发现一个未修复场景：`native_execution_smoke.finalizer_receipt_fail` 持续拒绝提交 LaTeX 子进程停止记录，作业停留 `finalizing`，90 秒内未达到原测试期待的失败终态。因此不能宣称原生监督整套回归通过。相关 `job_execution.py`、`job_write_checkpoint.py`、`publication_source_validation.py` 与前一验收归档内容相同；这只能说明相关收尾实现未在本批修改，不冒充对旧归档的实际复跑证明。该问题归入仍开放的 N5-04，后续必须完成可信恢复或明确处置；本批没有通过伪造停止记录强行变更终态。

继续执行原套件剩余场景后，累计 13 个完整场景通过；`finalizer_owner_death` 的真实子进程退出检查通过，但新 API 读取仍为 `finalizing`，未满足原测试期待的 `interrupted`。这是第二个未通过场景，同样缺少可信收尾记录，归入 N5-04。物理进程退出与完整恢复验收分开统计，原断言和失败证据保留。

后续状态：上述两个卡点已由[早期收尾状态修复](early-finalization-outcome.md)完成双库定向复验。保留本节作为发现时的历史记录；缺失物理停止证据的完整恢复范围仍未关闭。
