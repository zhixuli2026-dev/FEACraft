## S3 输出归档

`runtime_workspace(complete=True)` 先保存完整的本地输出清单，然后为远端运行目录和 `outputs.json` 取得持久用户额度预留，再执行上传。纯清单计算与实际上传共用 `attempt_objects.output_plan`，预留字节包含全部文件与编码后的清单。归属取自案例所在工作区的所有者。

新增 `OutputArchiveReservation` 绑定尝试、用户、案例、存储位置、封存输入摘要、输出清单摘要、写入进程身份和调用 token。它与上传、发布副本的预留共同计入 `storage_bytes_reserved`。额度不足在首个输出对象写入前拒绝；Job 的失败分类为 `resource_limit`，明细为 `storage_limit / archive`。

数据库事务不跨越实际上传。普通成功在远端完整核验后结算为 `materialized`；尚未开始上传的取消可以释放预留。已经开始上传后的错误、请求超时或 API 退出，均保留整个活动预留：客户端结束并不能证明服务端没有仍待完成的请求。

恢复只读取远端，不重跑命令，不补写缺失输出，也不把原任务改成成功。只有清单摘要、完整对象集合、每个对象的大小与内容全部匹配时，才能把预留结算为实际占用。完整匹配的不可变对象不再需要未来额度；原写入进程即使仍存活，后到的 `If-None-Match` 请求也不能重复创建同一个对象。因此完整核验允许结算已完成的归档，进程退出本身则不能释放不完整归档的额度。

启动扫描包含所有尚有活动归档预留的任务，包括已经失败且已有停止记录的任务。远端损坏、部分上传、存储绑定变化、无法核验时保留预留，继续其他任务的恢复。结算再次核对案例归属、输入和输出清单；原始任务状态、原有停止证据及原归档流程的 pending 记录保持原义。

同一原则也修正了 S3 成果发布副本：不能在未知远端写入或恢复额度不足后，仅凭客户端退出就释放全部未来额度。失败发布保留预留；完整 bundle 与 `ready.json` 的只读核验可以结算实际占用，但不授予发布权限。启动扫描同时包含这些活动发布预留。

## 文件存储发布副本的节点空间

`publication_storage.capacity` 在用户预留提交后，另外取得节点预留，覆盖复制意图、成果文件、成果清单、完成回执和锁字节。节点检查计入整个本地存储根目录的实际文件、其他活动预留及磁盘剩余空间。用户余额充足不再代表节点可以开始复制。

异步节点预留通过 `node_storage_budget.allocation` 跨越多个已排空的线程操作，释放数据库事务后才执行复制。取消发生在准入线程内部时，必须先取得线程实际创建的预留结果，再释放它；不能留下仍以当前进程身份占用的孤立预留。原进程退出后的旧节点预留由下一次节点扫描按真实出生身份核验并回收，实际文件继续计入用量。

节点空间不足分类为 `disk_limit`，无法核验分类为 `disk_unverified`。正常发布与 prebundle 恢复均使用此路径；恢复前拒绝复制也会持久化资源失败，不能无限留在“等待发布”。已验证完整的副本无需重新分配复制空间。S3 发布副本自身不在本地再次分配同份文件，其读缓存仍由已有的节点缓存预留控制。

## 剩余边界

未完成且无法核验的远端归档仍保留预留和现场；补传、受控放弃、历史记录扫描与安全回收还需要独立维护协议。这里没有通过 TTL 或“任务已失败”猜测可以释放空间。

远端 Job 日志及其版本增长、旧 staging/克隆和其他大文件操作、独立 native request/CLI、长 I/O 的期限/锁/心跳、跨节点全局并发和工作目录之外的强制资源控制仍在 N4-05 清单中。节点预留约束协作写入路径；任意原生进程的磁盘写入还需要运行监测和执行隔离，不能据此宣称操作系统硬配额已完成。
