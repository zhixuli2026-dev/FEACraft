## 远端格式和约束

每个结果包使用 `.vibeflow/publications/{publication_id}/files/` 存储产物，`manifest.json` 保存 SHA-256、大小、执行权限、描述符、case/attempt/publication 身份及代次。S3 清单还绑定 endpoint、bucket 和 case 前缀；复制对象到另一存储位置不能直接成为合法发布。

复制前将完整、确定的计划写入 `.vibeflow/publications/.journal/{publication_id}/intent.json`。对象通过条件创建写入，已有相同内容可复用，已有不同内容不能覆盖。所有文件上传后才写清单，再检查远端实际文件集合和逐文件内容，最后写 `ready.json`。未知写入结果或进程退出可以留下部分对象；重试必须继续使用同一份计划，不会另认一份输出覆盖旧数据。

准备日志描述的是文件复制事实。数据库所有权、成功作业、来源校验、当前代次及 head 事务仍决定发布可见性；仅有对象前缀、清单或 ready 回执均不授予提交权限。已提交记录的清单丢失会被诊断为需要检查，不能被解释为普通未完成复制。

读取先校验数据库绑定的清单摘要与身份，再检查远端对象集合和内容。需要文件系统接口的消费者会得到独立缓存目录；缓存从远端校验后创建，以不覆盖方式安装，同时校验已有缓存。远端被修改，即使本地保留完好的旧缓存也会拒绝读取；缓存被修改也不会静默继续使用。结果输入的文件选择层已能读取这些缓存，但完整 `input_publications` 提交及递归来源验收尚未开启。

路径在对象创建前检查，包括便携文件名、大小写别名、文件/目录冲突、数量与总大小。清单限制 16 MiB，文件集合沿用 10,000 文件 / 1 GiB 的尝试限制。远端集合多出文件、清单大小越界或内容不匹配均失败。空输出结果包合法。

## 验证与边界

专项使用本机已有 SeaweedFS 3.99，在 WSL `nobody` 下运行专用临时服务、随机端口和 bucket。子进程在第一个文件写入后、清单写入后直接退出，另一个进程读取日志并恢复；重复复制检查原对象的 ETag、时间和大小均未改变。测试覆盖独立缓存读取、远端/缓存损坏拒绝、错误数据库摘要与归属、复制到其他前缀的绑定拒绝、不同计划恢复拒绝、多余对象、已提交清单缺失、路径冲突和大小限制。

并发专项使两个进程同时到达同一个条件写入，随后使两个读取进程同时安装同一缓存；确认都可完成、远端未被覆写、临时恢复目录已清理。本地发布日志和两种原有 API 复制恢复分支同时回归。精确执行结果及源代码归档见 `tmp/mainline-N2-s3-publication-objects-evidence/`。

当前没有宣称 S3 发布的全链路验收完成：兼容路径的条件覆盖/删除、专业处理器来源快照、25 个处理器的远端接线、数据库发布和事件事务验收、递归依赖、上传 pending 的恢复、跨主机接管及孤立对象回收仍在原计划中。默认开发部署继续使用 fs。

实际能力探针发现 SeaweedFS 3.99 的 `PutObject If-Match` 正确拒绝错误版本并保留原内容，但 `DeleteObject If-Match` 即使版本错误仍删除对象。不能把客户端接受该参数当作服务端实现了条件删除。证据保存在 `tmp/s3-attempt-store-c1hzbh9w/alias-condition-result.json`；后续兼容路径删除需先解决这个存储端差异，当前没有使用不受条件保护的删除代替。
