# N4-03.f：viz 会话持久归属与退出核验

最终专项：SQLite/临时PG各33项，S3可控各9项，迁移各63项约束及有数据往返/降级历史保护；独立两个API真实kernel并发、坏journal只读验证8项、core14/14、兼容6/6和回收站控制7项通过。证据见tmp/mainline-N4-viz-evidence；本批不等同跨主机、远端S3或完整浏览器验收。

本增量把 trame/VTK kernel 接入实际进程归属，保留现有整数会话 ID、创建/列表/关闭接口及 iframe 代理。viz 是查看会话，不创建求解 Job；关闭查看会话不会取消独立工程作业。完整主线仍为 53 项、全功能仍为 295 项，N4-03 继续实施。

## 持久记录与启动顺序

新增 `native_viz_sessions`，迁移 head 为 `c64b21d5a0e7`，共 25 张业务表。既有 PTY `native_sessions` 和请求 `native_requests` 不改变结构。会话保存创建用户、case、owner 实际出生身份、令牌摘要、启动 nonce、固定解释器/输入/来源/端口及五个实现文件摘要、根进程出生身份、kernel 就绪身份、租约/活动时间、停止证明、实际退出码和错误类别。原始 owner 令牌不落库、不经 API 返回。

创建先在算例写边界检查权限、配额及输入，必要时复制 S3 暂存，然后在同一事务登记 `starting` 会话。PostgreSQL 同一用户的 viz 准入通过用户行锁串行；本机端口凭据同时覆盖独立 API 实例。提交会话后释放算例写锁，再创建等待启动门，独立核对并持久登记实际根身份。重新核对用户/case/来源及选中输入后才释放 kernel。

VTK reader 校验和首次渲染由所属 kernel 执行，不在 API 进程内加载用户结果。kernel 在 trame 已绑定预定端口并完成首帧渲染后，通过专用格式的标准输出行报告启动 nonce、profile 摘要、端口及自身出生身份。API 校验它属于已登记 Windows Job，再提交 `active`。错误身份、外部有效进程身份、错误 profile、未完成登记或租约过期均不能成为可代理的会话。启动就绪最多等待 30 秒，等待期间不持有算例写锁。

输入选择仍使用当前文件/求解目录；放行及就绪后复验来源绑定、解析后的路径和直接输入文件的大小/修改时间。本增量没有冻结完整 CFD 结果目录，也没有证明 series/XDMF 等全部传递依赖在求解过程中保持不变。运行中的场更新与 scenes.py 热重载保留既有行为，完整输入快照策略另行落实。

## 查看、关闭与历史

- `POST /api/v1/cases/{case_id}/viz:sessions` 仍接受 `run_dir` 或 `file_path`。缺省每 case 最多两个会话，保留订阅配额。
- `GET /api/v1/cases/{case_id}/viz:sessions` 缺省列出当前用户尚未收尾的会话；`include_closed=true` 包含历史。
- 新增 `GET /api/v1/viz:sessions/{sid}`，只读返回持久 phase、根/就绪身份、停止证明、退出码及活动信息。
- `DELETE /api/v1/viz:sessions/{sid}` 等待所属进程树退出、日志关闭、必要的暂存收尾和终态提交。并发关闭共用一个任务，已核验正常关闭可重复调用；清理失败返回 502，不伪造成功。会话创建者可以停止自己的资源；发布暂存仍须重新核对算例权限和来源。
- 代理只接受本实例中已经就绪、尚未开始关闭且实际 kernel 身份仍有效的当前用户会话；HTTP 每次复核算例访问权限。代理活动延长空闲时间，浏览器连接结束不会自动取消查看会话。WebSocket 任一方向结束即取消并加入另一个方向。

`phase` 为 `starting/active/closed/failed`；过期但缺终态的历史读取为 `recovery_required`，坏证据为 `evidence_invalid`。本实例不可控制的会话 `owner_available=false`，未经证据确认的 `alive` 保留 null。重新启动 API 只读取历史，不依靠旧 PID 发送信号，不重建 kernel，不补造停止回执。

显式关闭、空闲回收、kernel 自行退出、心跳失败和 case 监督取消都等待相同清理操作。Windows Job 包含脱离控制台的后代，停止证明要求所属范围清空。原始退出状态独立保存，非零自然退出为失败，未知退出码保持 null。停止证明提交失败时，持久会话仍未完成；本地已经观察到进程死亡也不能替代缺失的数据库回执。

启动中的会话与尚未核验的历史会阻止算例复制和移入回收站。保护读取持久记录，覆盖 API 重启后的未知 owner。API 的 viz 关闭钩子会等待所有本地会话；其他入口的统一停机、活动聚合和完整取消矩阵仍属于 N4-04/N4-07。

## S3 暂存与本机端口

S3 关闭先证明原生进程退出、关闭日志，再在新的算例写边界复核来源并同步，提交成功后严格清理暂存。同步等待期间本地 `alive=false`、`finalizing=true`，持久记录仍为 active 且没有终态停止回执。远端冲突、case 不可用或来源重绑均保留失败与副本，不把旧副本上传到新来源。

目录锁可限时重试；开始清理前写入已有的 cleanup-only 意图标记。若清理中断，通用 staging 同步会拒绝把已被部分删除的目录重新作为上传/删除快照。启动前复制取消或选择事务提交失败会清理没有可用 owner 的副本。该保护复用 PTY 的清理实现与标记格式。

端口选择使用本机占用凭据：Windows 为具有确定名称且不可继承的系统对象，Linux 为文件锁；随后检查端口能否绑定。凭据一直保留到实际范围核验退出，API 猝死由操作系统释放。本增量验证 Windows 本机两个独立 API 并发，未验收跨主机路由、Redis 会话共享或负载均衡。
