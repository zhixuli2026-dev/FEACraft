## 修复

目录树恢复及正常沙箱导出会保存 Linux 模式位和文件摘要。此前普通文件保存改变内容后，旧摘要不再匹配，下一次沙箱会失去已保存的模式位。

普通 FS/S3 文件事务现在先核对已跟踪文件的当前摘要，再把新摘要与原模式位写入同一份事务日志。描述文件与用户文件共同提交或回滚，不再额外进行无日志的元数据写入。caseDict 的配置和两份历史也走相同机制；原版本及阶段校验保留。

删除会移除原文件的权限关联；删除后重新创建按新文件处理。当前内容已经在事务之外变化时，不重新激活旧权限。没有描述文件的项目继续使用原文件写入路径，不扫描整个项目；未跟踪的新文件不强行扩张描述文件。普通文件写入不能替代已记录的目录，类型互换仍使用目录树流程。

内部事务作用域允许额外一份受保护的 `.vibeflow/tree-state.json`，其上限仍为 8 MiB。用户文件原数量、单文件和总量限制单独核验，不能借元数据额度提高普通文件限额。原日志保持可读。POSIX 本地替换增加记录和应用原模式位的分支；本轮 API 宿主为 Windows，没有把该分支的完整 Linux API 验收算作已完成。
