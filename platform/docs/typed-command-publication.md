# 通用类型命令的独立执行与结果发布

本批覆盖本地文件存储下 `/jobs` 的 `mesh`、`solve`、`geometry`、`pvpython`、`convert` 命令：没有显式输入选择时，封存算例用户文件，在本次 attempt 的独立目录执行，验证完成后发布不可变结果并更新兼容路径。新增 `command.*@1` 五个处理器，使用 `case-command:` 独立发布通道。用户指定的类型不能替代正式专业工作流的网格或求解证明，结果明确记录 `professional_workflow_proof: false`。

运行目录中的新增、修改、删除文件通过原输入清单和实际输出清单计算。发布前检查当前来源与目标；命令失败、取消、超时、来源变化、目标编辑均不能覆盖已存在的结果。原 `0-caseDict/caseDict`、`C-run` 下已有初始场和 `0.orig` 文件不能被这类命令的发布修改或删除。无文件输出的成功命令允许发布空结果。显式 `input_paths` / `input_publications` 继续保持原有的输入选择与私有输出行为。

带 `run_dir` 的旧 solve 命令保留其下游证据：进程退出后，将实际日志复制到私有目录，根据封存输入和实际输出生成求解证据，使用 VTK 校验网格和场数据，再将日志、证据和场文件纳入同一结果包。兼容 `.vibeflow/jobs/job-*-evidence.json` 随发布更新；后续编辑场文件会使旧求解门控和当前结果引用失效，历史包仍可读取。因为包内包含执行元数据，下游 `input_publications` 需用 `paths` 选择场文件；直接挂载整个含元数据的包仍按原规则拒绝。

提交和投递保持原职责：通用提交绑定处理器时不另建本地投递意图，由原调用方选择本地、Redis 或批次投递策略。批次中的每项拥有独立目录；本批验证了无文件输出的类型批次和幂等重放。多个命令修改同一活动算例时，完整来源校验可能使后提交的结果过期；不声称任意并行写入相互独立，也不自动重跑这些命令。

旧内部调度的兼容夹具包含固定 argv 和活动算例绝对路径，切换 cwd 无法改变它的实际写入位置。本批自动接入只适用于 `argv is None` 的通用命令，保留旧内部 argv 行为。当前公开工作流 dispatch 已要求注册处理器并拒绝直接执行旧计划；旧计划迁移与历史记录恢复继续保留，不能把内部兼容能力写成已迁移入口。独立目录同样不是操作系统沙箱，不能阻止任意命令主动访问绝对路径。

验收证据归档在 `tmp/mainline-N2-typed-command-evidence/`：

- SQLite、PostgreSQL 各 16 项：五种类型、真实 WSL、空结果、删除、失败、保护初始场、来源和目标冲突、取消、超时、API 退出后补交而不重跑。
- 真实 `blockMesh → icoFoam` 与旧求解门控等 4 项：场数据发布、当前引用与不可变历史、没有求解的成功退出不能发布、损坏场数据不能发布。
- 普通 shell 默认隔离兼容 9 项；类型批次独立目录、投递和幂等 1 项；旧内部调度兼容 20 项。

保留两类检查失败的原始记录。求解引用检查最初试图挂载含执行元数据的完整包，按既有接口要求改为显式选择场文件。旧调度检查暴露上述绝对路径 argv 边界，最终按入口限定迁移范围，未更改旧调度的验证断言。没有将这些首次失败写成已通过。
