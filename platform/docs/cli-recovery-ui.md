2026-11-21，Edge 实测冷打开后自动进入 Codex · WSL，点击恢复补回原模型回答，刷新后回读一次。使用实际非特权 WSL、认证 SeaweedFS 和授权 DeepSeek。 [FF-F41 完整验收](cli-turn-recovery-progress.md)

2026-11-16。接续 [S3 暂存恢复](cli-s3-staging-recovery.md)，在现有原生聊天面板接入正式 `:reconcile-staging` 操作。范围是用户可以从中断状态恢复文件和会话，并继续发送真实任务；不把后端接口存在当作完整用户流程验收。

当当前执行归属对应一个需要恢复的原生回合，或已结束但仍占用会话的回合时，显示“恢复会话”。操作使用当前活动回合，而不是用户正在浏览的历史回合。服务端核验原运行停止、同步未保存文件并释放执行归属。浏览器根据实际返回及后续状态查询决定是否允许继续发送，不能仅因为请求已发送就恢复输入。

恢复中禁用重复提交；文件冲突保留暂存与远端版本，并显示核对文件后重试的提示。请求响应丢失时显示结果未确认，继续只读查询；若服务端会话已空闲，提示可以继续发送。刷新不提交恢复操作、不重新发模型任务。需要恢复的旧回合不再显示可回应的审批或可用的停止按钮。窄聊天区整体可以滚动，恢复提示不再被压成只有文字、看不见按钮的区域。

## 真实验收入口

`platform/server/live_llm_cli_recovery_ui_acceptance.py --source-profile-id 26 --review <review.json> [--postgres]` 使用隔离 SQLite 或临时 PostgreSQL、实际 SeaweedFS、实际 WSL CLI、已授权 DeepSeek 和构建后的正式网页。模型先真实发起读取审批，实际退出 API；测试直接修改暂存文件并制造远端冲突，这些文件改动明确是故障输入，不是模型生成的结果。浏览器执行恢复、重试、刷新和新消息发送。最后要求真实命令读出提示词中没有的随机文件内容、模型精确返回、历史保存正确、会话空闲及各测试服务退出。PostgreSQL 复用现有本地服务，只新建和删除本次随机命名的测试数据库。

浏览器丢包只针对恢复 HTTP 响应：请求先由真实服务执行，再中断响应；不替换模型服务、工具选择或模型输出。浏览器步骤通过隔离目录中的 gate 文件与验收进程协作。不得把尚未执行的浏览器断言提前记为通过。
