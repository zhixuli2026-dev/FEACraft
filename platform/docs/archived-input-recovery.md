2026-11-08，N5-05 实施记录。主线仍为 34/53、剩余 19 项；本功能不改变全部 53 项主线及 295 项全功能范围。

本页记录显式重试和续算时为新尝试读取原归档的路径。原作业收尾时，已归档的同一尝试可通过独立接口恢复原缓存。 [原作业缓存恢复](attempt-output-cache-recovery.md)

## 行为与边界

显式重试及 OpenFOAM 续算现在通过独立的 `SealedInputView` 读取原封存输入。S3 下先校验数据库中的尝试身份、路径、存储绑定、文件和目录清单，再比较远端 manifest 与精确对象集合；按大小和 SHA 逐文件流式读取到进程自有目录，完成后再次核对远端清单及本地完整清单。新尝试从这个核验过的视图封存，复制时继续核对内容，使用现有节点空间准入和封存事务记录。

本地旧尝试可以同时存在缺失文件、损坏文件、损坏 manifest 和未知内容。这些内容均保留，不拿当前工程文件填补，也不在旧目录中覆盖或重建运行结果。续算的原输入视图与已验证输出视图共同持有，直到新尝试封存结束后清理；来源身份必须与原 SQL manifest 匹配。普通启动、运行结果捕获及完成验证继续严格核验实际封存目录，不能借显式恢复路径把损坏缓存当作有效执行证据。

FS 没有独立可信远端副本，继续拒绝缺失或损坏的原封存输入。S3 远端内容缺失、清单不一致或字节变化也拒绝；普通重试中的对象完整性错误归类为 `input_stale`。网络或空间不足不回退到当前输入。

进程自有缓存现在将显式目录（包括空目录）写入原持久文件日志，再创建目录。恢复先证明所有者实际退出、验证完整清单与字节；只清理已登记内容，未知目录或被修改文件继续保留。旧文件日志格式仍可读取。
