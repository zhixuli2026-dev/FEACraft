## 问题与范围

本轮只迁移应用规定不可变的文件校验。`storage.put_bytes/delete`、上传入口和 Agent 文件写入都会拒绝 `.vibeflow/attempts` 与 `.vibeflow/publications`；创建目录使用唯一身份且不得覆盖。算例移动、删除等管理操作还会检查运行作业和非终态尝试。已提交的封存输入与新准备的发布目录，没有正常的应用编辑入口。

可编辑源文件不具有上述边界。它们的哈希、发布依赖和 compose 目标条件仍在原事务内检查。此前讨论的跨实例内容锁／持久读取租约尚未选定或实现，本轮不增加新的锁、租约表或迁移，也不声称已经解决全部长事务。

## 实现

`job_execution.finish` 在原生 finalizer 排空、发布包准备完成后调用 `verify_files_for_finish`。短事务核对 claim、attempt、完整输入／输出／发布绑定、算例前缀及发布身份，随后关闭会话。工作线程执行原有的完整输入清单、文件 SHA-256、包清单和各产物 SHA-256 校验，保留路径、链接及所有权检查。

线程完成后生成进程内的 `verified_binding`，精确绑定准备对象中的输入、输出、发布记录身份、文件清单、descriptor 和包哈希；验证前后绑定变化会失败。正式提交仍重新取得算例锁，核对当前数据库身份与完整绑定，再核对这份本地校验证据。缺失证据或校验后准备对象变化均不能发布成功；不接受客户端提供的证明，不用文件大小或时间戳替代内容哈希。

心跳和跨实例取消可在这些不可变文件读取期间提交。重复任务取消仍须等待不可取消线程排空。准备或校验期间心跳失败时，原有成功提交检查继续阻止过期的本地成功状态写入数据库。取消、代数竞争、来源变化及提交失败继续沿用原有规则。

这里提供的是应用不可变目录的快照校验，不是持续监视文件内容，也不是原生文件系统隔离。直接修改这些私有目录的外部程序不遵守应用边界；数据库锁原本也无法阻止这种写入。读取已发布文件时仍按已提交清单复核内容。

## 验证设计

`publication_verify_smoke.py --postgres` 复用真实注册 Pandoc HTML／DOCX 发布及双 API 夹具，在 SQLite 和临时 PostgreSQL 上各执行 21 个窗口：

- 校验前篡改输入、包内容或 manifest，注入校验 I/O 异常，确认旧 head 和兼容别名保留。
- 两处重复后台任务取消必须先排空线程；心跳失败保留显式待恢复状态。
- 校验完成后取消、修改源文件、推进新代数、改变输出绑定或发布身份，仍重新判断提交权限。
- 校验后修改准备对象、移除本地证明或注入提交异常，不得产生新的成功发布。
