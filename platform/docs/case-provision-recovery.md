后续更新：导入、算例/工作区复制和备份恢复已接入本协议，四种存储/数据库组合的 60 组故障场景通过，详见 [构造入口恢复](constructor-recovery.md)。下文保留第八批的历史范围与证据；当前剩余为清理、旧目录诊断及原完整恢复要求。

2026-11-05：N2-06 第八批，先完成新建算例入口。主线 23 完成、11 进行中、19 待开始，剩 30；原 53 项与 295 项功能范围不变。导入、算例/工作区复制和备份恢复仍待接入，不据本批关闭整项。

## 已接通

`POST /api/v1/workspaces/{ws_id}/cases` 在写入脚手架前保存完整创建清单，包括账户、算例、工作区、存储绑定和每个文件的大小/摘要。清单位于该账户的 `workspaces/{user_id}/.case-provisions/pending/`，与数据库事务中的 `cases.provisioned` 持久事件对应。事件与算例元数据同时提交，不新增表、不迁移开发库。

首次占用的数字目录仍使用 `workspaces/{user_id}/cases/{case_id}`，同时永久保留这个目录的独立占用记录。如果目录已存在或编号曾被占用，使用 `workspaces/{user_id}/cases/{随机标识}/{case_id}`。SQLite 回滚后复用数字 ID、旧孤立文件或其他创建残留都不会被当成新的空目录。已存在算例路径保持原值；真实 Windows Job 在新格式目录已验证。

新建与恢复都先持有账户行锁，再进入工作区/算例锁，避免另一个 API 把仍在创建中的文件误判成回滚残留。文件操作在独立线程执行；请求取消时等待线程完成，之后才释放数据库锁。文件系统先在账户的专用暂存区写完并刷新，再以不覆盖的硬链接创建目标；S3 使用条件创建。提交前复核全部预期文件和内容。

下次新建会自动对账该账户的待处理记录。也可调用 `POST /api/v1/case-provisions:recover`，只处理当前账户的记录，返回每条的判定与待处理原因：

| 证据 | 恢复行为 |
| --- | --- |
| 数据库有匹配的创建提交证明 | 保留文件，不重新写入；即使文件后来编辑也不覆盖 |
| 无提交证明，也无引用该目录的算例行 | 核对全部现有文件，再仅删除清单中内容未变化的文件 |
| 文件有外部修改或额外文件 | 保留现场和待处理记录，报告 `recovery_required` |
| 清单、账户/目录占用、存储绑定或提交证明不一致 | 保留现场，不猜测归属 |
| 当前 Session 自己尚未提交的创建 | 不能把未提交事件作为持久证明或提前清理 |

完成判定后保存历史回执，再删除对应待处理清单。创建请求的数据库提交确认丢失也走同一证明，异常处理不再按目录递归删除文件。目录占用记录、历史清单、空目录和进程终止遗留的专用暂存文件尚未自动清理。

首轮 S3 夹具误用了默认 3.99，条件删除不受支持，创建失败；改为明确选择 4.52 后五组通过。产品对不支持条件操作的后端返回明确的 `409 storage_conditions_unavailable`，在写入算例文件和创建清单之前拒绝。历史算例仍可读取和运行原有普通作业；旧后端兼容测试使用测试专用入口模拟旧版本已创建的算例，没有在产品中增加绕过保护的入口。

原备份脚本用数字事件 ID 是否出现在整个导出文本中判断映射，可能误中日期或其他字段。本批改为核对导出会话的 `branch_head_event_id` 等于实际恢复后的回答事件 ID，并不等于原 ID，备份恢复通过。边界测试第一次读取了不存在的日志 `log` 字段，按真实接口改为 `chunk` 后四组通过。原始失败日志均保留。
