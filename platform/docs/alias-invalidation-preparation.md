## 已实现的行为

旧作业、终端、viz、Agent Shell 和 CLI 的共同 staging 同步入口，现在在持久存储占用下先读取发布头、发布身份和历史 attempt 的不可变快照，再关闭 SQL 事务。产物清单读取、远端包校验和所需缓存读取在可排空的工作线程完成。损坏历史包的路径推断沿用原有规则，使用已捕获的历史记录，不访问数据库或远端存储。

最终提交通过 `coordinate(..., prepared_aliases=...)` 复验同一个存储占用、算例来源、完整发布头集合、版本、代数、活动指针、发布身份/清单摘要/状态，以及历史记录绑定。检查通过才消费预读路径并使被编辑产物失效。出现变化时，SQL 提交回滚，文件日志执行原有补偿，保留 staging 副本。新增发布头也会使检查失败；只核对已有行会漏掉这个窗口。

普通写入调用者保持原有接口；它们的 `managed_paths` 仍有事务内存储读取，不由本批宣称解决。启动克隆、旧自动恢复和诊断路径也继续保留在 N2-06 范围。

## 已复现但未修复：恢复完成后的迟到写入

`tmp/staging-inflight-before.json` 保存一次真实实验结果：HTTP 代理已接收一个发往真实 S3 的条件 PUT，暂缓转发；随后终止实际 API owner 进程，并由另一 API 执行恢复。恢复观察到旧内容，返回成功并删除 pending 标记。此时转发先前请求，存储返回 HTTP 200，文件变为新内容，而 pending 仍不存在。

该实验没有伪造进程死亡或 S3 写入结果。HTTP 代理只控制已收到请求的转发时机；最初代理遗漏 HEAD 的 Content-Length 导致夹具失败，已修复后重新实验。成功的 before 脚本不得再次运行并覆盖证据。

结论限定于实测窗口：`exited` 能证明本地进程停止，不能证明已经发出的远端请求不会再生效。因此，既有进程死亡恢复测试通过，并不足以证明远端崩溃恢复正确。当前代码仍存在此缺陷，本批没有修复它；普通 S3 写入、上传和兼容别名的类似路径还需逐一审计。

## 下一实现单元：不可变内容与唯一提交指针

采用以下实现方向继续推进；这是内部技术选择，无需用户提供配置。实施前需对照现有读取/写入调用图落实兼容边界：

1. 保留逻辑文件路径，但新内容写入本次操作独有的不可变对象。延迟的数据 PUT 只会生成孤立对象，不能覆盖可见文件。
2. 用一个永不删除、每次转换都包含新随机版本号的远端指针选择文件清单。指针同时保存未完成事务身份，避免“数据指针”和“pending 指针”之间的新窗口。所有指针转换必须针对先前指针 ETag 执行 CAS。
3. 恢复先推进指针的唯一版本，即使未发现数据变化，也撤销旧请求携带的 CAS 条件。回滚可选择旧内容清单，但必须写入新的指针版本，不能恢复原指针字节或删除指针，否则会重新接受旧条件。
4. SQL 提交事件决定恢复选择前态还是后态。存储占用绑定精确操作/计划/提交事件；恢复未知提交时仍查询 SQL 见证，不按请求响应或超时猜测。
5. 逻辑读取、列举、Range、下载、staging 克隆、普通保存/删除、上传、字典及兼容产物均需经统一适配。旧对象显式迁移或作为有界基线读取；不得仅修改 staging 而留下其他写者绕过指针。
6. 验收必须重放本次真实 HTTP 时序，并覆盖迟到指针请求、回滚后的相同内容、删除/新建、初始化指针、恢复进程再次退出和 SQL 未知提交。并行用户编辑必须得到冲突或完整的新版本，不能被旧操作覆盖。

不能用增加 sleep、延长租约或把所有死进程永久标为 busy 代替最终方案。实施期间仍保留原来的缓存恢复、索引对账、UDF 单次 409 归因和跨环境部署验收范围；不据此删除既定任务或降低验收标准。
