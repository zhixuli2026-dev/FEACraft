# 专业作业批次的输入封存

2026-11-22，`POST /api/v1/cases/{case_id}/jobs:batch` 的专业 `operations` 入口将串行 OpenFOAM、MPI 和 UDF 的来源读取及输入封存移到数据库写事务外。各成员保留自己的运行目录、配置和封存。开始实际副本复制或上传前，按全部成员的合计峰值检查账户容量。本地另外预留整批节点空间，认证 S3 沿用算例存储租约和持久封存记录。

数据库短事务负责重新授权、核对文件或对象版本、绑定每项的作业与专业处理器、写入批次和投递记录。任一成员失效会回滚整批。相同请求键回读已经提交的批次，重试失败提交时重新读取当前输入。

本地 SQLite 对照中，旧版复制 40 MiB 输入时占用写事务，同算例保存返回 409。新版允许该保存返回 200，随后拒绝已经过期的批次。按原键重试完成两个真实求解。认证 SeaweedFS 配 PostgreSQL 在 40 MiB 材料准备阶段允许独立数据库写入，同账户另一个算例保存返回 200，两个成员也完成求解。

本地 PostgreSQL 混合批次通过串行 OpenFOAM、双进程 MPI 和 UDF，实际编译得到 ELF 共享库，三个速度场各含 400 个单元。MPI 与串行速度场的相对误差为 `4.21e-7`，UDF 与串行结果一致。重复请求回读同一个批次。 [速度场和 UDF 证据](../../tmp/N4-05-prepared-operation-batch-seal-20261122/native-fields.json)

本地 SQLite 将账户额度设为单个成员可用、两个成员合计超出的范围，批次在复制前返回 429。随后同一算例的单成员实际求解成功。四秒测试期限先等正在进行的 40 MiB 复制退出，再返回 504。未产生批次，原键重试成功。

认证 SeaweedFS 的额度对照使用 150 MiB 限额。三个成员在材料复制前合计超额并返回 429，单个成员成功求解和发布。首轮使用 100 MiB，两个成员的提交提前拒绝，单成员虽成功完成 OpenFOAM 计算，结果和日志归档仍超额，整轮失败留在凭据中。

认证 SeaweedFS 配 SQLite 在第一个成员完成绑定后实际替换了等长的源对象。原提交返回 409，作业和批次均未提交，原键重试完成两个真实求解。测试覆盖四种存储与数据库组合。工作负载调用真实 WSL、OpenFOAM 和对象存储，模型调用为 0。证据纳入 N4-05 的 RB-12 和 RB-14。 [专项验收](../../tmp/N4-05-prepared-operation-batch-seal-20261122/validation.json)
