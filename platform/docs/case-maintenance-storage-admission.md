# RB-12 部分验收：逐算例维护的存储准入

后续更新：8个纯文件编辑API的S3额度已在[文件编辑增量](file-owner-storage-admission.md)接入；下文保留当时范围，当前剩余入口以资源清单为准。

2026-11-06：本次补齐 S3 逐算例维护的账户额度，并解决没有待处理工作的算例在每轮维护时仍生成 HEAD 版本的问题。普通文件编辑及其他长文件入口尚待审查，RB-12 保持未完成；主线 33/53 完成、剩余 20 项，资源工作块 11/17 完成、剩余 6 块。

## 没有工作时只观察

维护先只读检查文件事务 pending、执行输入封存 pending、上传记录，以及没有对应 SQL JobAttempt 的本节点缓存。文件系统后端沿用原有维护流程。S3 如果没有这些候选工作，本轮跳过算例，不进入会刷新 HEAD 的恢复协调器，也不为该算例分配写入额度。

这次观察不授予清理权限，不释放任何预留。观察后才到达的新事务留给下轮处理。发现候选工作后，仍进入完整算例锁和恢复协议，重新核验提交证明、进程身份、对象版本和文件内容；真实恢复所需的 HEAD 隔离没有省略。

## 有工作时先预留再恢复

创建恢复及历史清理结束并提交后，逐算例在取得写锁之前持久预留账户可用额度，再检查工作区归属、运行原有恢复、提交，最后结算本次预留。正文、恢复记录、条件探测与 HEAD 版本都通过已有账户额度上下文计费。此路径只恢复既有上传或封存记录，不发放新的上传/执行额度。

额度不足会返回该算例需要恢复的状态，并保留事务证据。恢复进程退出后，下一进程按永久额度记录关闭旧写入身份，释放未使用部分；最后一笔结果不明的可变 HEAD 请求仍保留其长度，不根据进程退出猜测成功或失败。

## 验收范围

`case_maintenance_storage_smoke.py` 使用独立 API 进程、隔离数据库和真实启用版本的对象存储，检查未提交回滚、已提交保留、额度拒绝后重试、恢复进程退出后的残余预留、扫描后迟到事务，以及没有删除证明的本地缓存保留。`owner_storage_budget_smoke.py --modes maintenance_noop` 检查两轮空维护前后的物理存储字节不变。

另外复用维护兼容检查，以及封存输入/本节点缓存的 automatic 场景，验证只读候选筛选没有漏掉这些自动维护入口。最终通过情况及源码绑定见本阶段验收记录；失败的初始测试配置不计为通过场景。

## 剩余限制

- RB-12：普通文件编辑和读取时隐含的恢复、ZIP/备份等其他长文件入口的用户和节点峰值。
- RB-14：只读筛选与额度盘点仍有网络 I/O；等待、锁持有时间及队列有界性尚需治理。
- RB-15：空账户维护仍生成 SQL 预留历史；已知但无法清理的候选记录仍可能触发实际恢复与 HEAD 增长。永久额度记录、未知可变请求及公平扫描仍需维护协议。本次只保证没有候选工作的 S3 算例不会因逐算例维护新增远端对象。
