## 本批交付

普通保存、上传、删除、caseDict 三文件、Agent 文件提案以及阶段/重算/失败回退共用持久事务协议。远端 `.vibeflow/file-transactions/objects/<uuid>/` 先保存旧内容、新内容和不可变清单，再以条件创建发布唯一 `pending.json`。数据库提交证明与业务修改使用同一 SQL 事务。

新 API 在算例锁下读取 SQL 和远端清单即可恢复，不依赖原进程或本地缓存。没有提交证明时条件恢复旧内容；有证明时保留新内容。全部备份摘要和当前内容检查通过后才恢复；第三方修改、损坏备份或错误存储绑定会保留现场并拒绝继续写入。完成恢复后写不可变回执，按原 ETag 条件删除 pending；恢复中再次退出可继续。

写入、创建和删除分别使用 IfMatch/IfNoneMatch 条件，恢复也遵守相同条件。真实能力探测不通过的后端在修改工作文件之前拒绝请求；SeaweedFS 4.52 已验证支持，3.99 返回 422，不退化成无条件覆盖。旧后端的普通 shell 执行仍独立验收。

保留的元数据包括 ContentType、CacheControl、ContentDisposition、ContentEncoding、ContentLanguage 和用户 Metadata。实测本机 SeaweedFS 会把 ASCII 内容的 application/octet-stream 改为 text/plain；准备阶段因此保存服务端实际接受的元数据，私有新内容对象保留目标文件名，避免恢复误判。未声称恢复任意 ACL、标签、版本 ID 或加密属性。

S3 网络操作在工作线程执行，不阻塞 API 事件循环；取消请求先等待正在执行的存储操作结束，再释放数据库算例锁。SQLAlchemy Session 不进入工作线程。同一 SQL 事务内的嵌套读取不会把自己尚未提交的证明误判成已提交事务。

限制：单次最多 256 个目标，清单不超过 1 MiB。首批前后内容合计上限为 1 GiB；后续[S3 分块上传](s3-upload-transactions.md)改为流式校验与备份，单个对象最多 1 GiB、前后合计最多 2 GiB，以支持原上传大小范围内的覆盖操作。受保护内部路径仍返回 409；外部冲突不能靠删除 pending 或伪造提交证明绕过。
