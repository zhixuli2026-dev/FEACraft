# N4-05 S3 作业输入封存

普通 S3 算例的作业输入先按选定 ETag 和长度流式复制到拥有者来源缓存，保存真实 SHA-256，再核对所选版本。文件的可移植权限继续由同一份受摘要保护的树描述符表达。

上传大成员时，封存服务在已有串行写入区内申请一个本地暂存文件，核对内容后以流方式条件创建归档对象。已归档成员按块复核长度和 SHA-256，最多四路读取并发。真实条件冲突会先复核已存在的对象，摘要一致时复用。归档不完整或原版本发生变化会阻止继续提交新尝试。[实现](../server/app/services/attempt_objects.py)

复验入口使用隔离 SQLite、真实认证 SeaweedFS 和 WSL。先从公开作业接口封存 40 MiB 二进制文件和带可执行模式的脚本，再运行实际 `sha256sum` 输出摘要。首次脚本在产出摘要后按夹具条件退出 17，供后续原输入重试使用。[复验入口](../server/attempt_input_streaming_acceptance.py)

## 2026-11-19 实测

| 阶段 | Python 分配峰值 | 实际 S3 操作 |
| --- | ---: | --- |
| 已选来源的物化 | 2,192,133 B | 一次条件 GET，读取 41,943,040 B，每次最多 65,536 B |
| 初次不可变输入写入及核对 | 2,420,240 B | 流式条件 PUT 返回 200，随后按最多 1 MiB 读取并复核完整成员 |
| 相同输入再次写入及核对 | 2,367,986 B | 流式条件 PUT 返回 412，完整读回核对原成员，ETag 保持 |

旧尝试的归档输入分别被实际删除及替换为同尺寸不同摘要的对象。两次公开重试均返回 409 `input_stale`，未产生新作业，第三方写入的对象未被覆盖。恢复原字节后用同一操作键成功重试，真实 WSL 进程按原封存输入生成相同摘要，脚本模式描述仍为 `0755`。相同请求再次提交返回已存在的重试作业，来源缓存已清理。回执记录封存、远端内容及两次实际原生执行。[最终回执](../../tmp/attempt-input-streaming-ppfym13v/attempt-input-streaming.json)

首轮同尺寸篡改曾写进已命名的缓存文件，清理随后覆盖原错误并返回 400。已将归档重试读入私有暂存，只有完整摘要匹配才安装为视图成员。坏内容的暂存按自身身份和实际已写摘要删除，调用方收到原输入过期错误。[首轮记录](../../tmp/attempt-input-streaming-tokyw23n/attempt-input-streaming.json)

现有 24 个小成员的真实对象存储回归也通过，覆盖条件创建冲突、远端已有字节保护、本地来源变更、冷缓存恢复，以及有效热缓存下仍拒绝损坏远端对象。[既有回归](../../tmp/s3-attempt-store-9q2id4vd/input-upload-result.json)
