## V19 与 V20 发布故障验收

2026-11-18，两项都使用独立 PostgreSQL 数据库和两个本机 API 进程，在文件存储和 SeaweedFS S3 上分别执行。

- **V19 部分发布时服务停止。** 连续生成两个有不同内容的真实 Pandoc 报告。在第二版 DOCX 兼容文件已写入（文件存储）或 DOCX 对象已落盘、文件映射尚未切换（S3）时终止发布进程。另一进程通过公开报告 API 下载当前版 HTML、DOCX，并按第一版发布 ID 下载历史版。两版的正文标记、两个文件的 SHA-256 均与各自清单一致。重启后原作业成功，两个普通文件下载路径也与第二版清单一致。[文件存储](../../tmp/live-cli-startup-jtl7jurw/partial-publication.json) · [S3](../../tmp/live-cli-startup-vfx_coy8/partial-publication.json)
- **V20 旧作业晚于新作业结束。** 两个作业执行相同命令，向同名文件写入可区分的内容。旧作业在写入结束且停止证据已记录后暂停，服务 API 重启，另一作业先完成发布。旧作业随后完成，两种存储上的 PostgreSQL 记录均为第一代 `superseded`、第二代 `committed`。再次重启后查询发布指针，两份公开文件仍返回第二代内容。[文件存储](../../tmp/live-cli-startup-u9vm5bpm/publication-restart.json) · [S3](../../tmp/live-cli-startup-k_1h5cnp/publication-restart.json)
- 首轮 V20 在旧命令仍可写文件时暂停，触发算例的正常写入互斥，新作业等待超时。两份失败记录保留。复验将延迟放到旧写入者已退出的时点，沿用生产校验和发布逻辑。[文件存储首轮](../../tmp/live-cli-startup-wec07rkg/live-result.json) · [S3 首轮](../../tmp/live-cli-startup-83mfkdsh/live-result.json)

每轮故障证据生成后，真实 DeepSeek 通过文件工具读回该轮证据摘要。四轮共 8 次上游模型请求，两个首轮超时均发生在模型调用之前。[V19 文件存储](../../tmp/live-cli-startup-jtl7jurw/live-result.json) · [V19 S3](../../tmp/live-cli-startup-vfx_coy8/live-result.json) · [V20 文件存储](../../tmp/live-cli-startup-u9vm5bpm/live-result.json) · [V20 S3](../../tmp/live-cli-startup-k_1h5cnp/live-result.json)

## 历史实现记录

本批推进N2-06/N5-04，尚不关闭两项。它处理数据库已确认产物、兼容文件或完成可见性回执尚未完成的窗口；具有完整持久准备证明的提交前窗口现由[prepared finalizing恢复](prepared-finalizing-recovery.md)处理。

在已有可续租的case内容校验占用下，读取不可变bundle并生成`aliases.json`：每个目标路径、来源文件、允许的旧哈希和预期新哈希。原文档合成的备份与目标CAS、LaTeX的只读来源及PDF最后写入、旧结果的按哈希删除规则均保留。计划哈希属于来源校验证明，并与publication/head/Job终态一起写入attempt输出。

兼容写入核对数据库绑定的计划哈希，先检查全部目标，再逐文件确认。已是目标字节的文件跳过；仍符合旧哈希的文件更新或删除；任何不匹配都保留。全部应用后保存`aliases-applied.json`。因此文件移动后进程退出或数据库回执未知，都可以按同一计划继续；重复修复不会改写已经完成的文件。退休文件的旧哈希不能被用户修改后的字节替代，别名冲突仍作为修复错误，不能反转已经提交的有效产物。

启动对账先只读检查候选，释放数据库会话后核验原worker的精确出生身份已退出。仅凭租约过期不会接管。还须有匹配的执行lineage、原生停止与子进程记录、写入排空checkpoint和持久停止事件。第二个短事务重新锁定case、复验完整快照与历史后，才应用计划。

活动head仍为该产物时恢复兼容文件；若head已因用户编辑或较新结果改变，跳过旧文件，保留历史产物。完成状态、恢复审计和`attempt.completion_visible`事件同事务提交，原Job/attempt/发布代次不变，不重新运行求解器或重复创建计费终态。文件已完成但回执未提交时，下一次启动核验后继续完成。没有计划的旧记录、外部修改、缺停止证明及未知/异机所有者保留待处理。

当前仍保留原来的case协调事务来串行化兼容文件写入，尚未声称所有大文件I/O都已移出数据库事务。读取原worker状态时不等待其写事务；另外修复启动时无孤儿工具调用仍发出空UPDATE的问题，避免无工作的新API被SQLite写锁阻塞。有实际待迁移数据时的完整启动调度仍在原N4/N5/N7范围内。

验收范围包含真实报告子进程已经退出后，在别名写入前、单个文件后、全部文件后终止API，重启核对文件与SSE完成；用户原位改动、API编辑使head失效、重新生成较新结果、原owner仍活以及重复启动。文件专项还验证删除中断、全目标预检查、修改计划拒绝。普通报告/合成及LaTeX继续使用原专业验收断言。
