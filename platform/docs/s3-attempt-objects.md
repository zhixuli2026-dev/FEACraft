# S3 的封存输入与私有作业输出

本批实现 N2-03 中普通 shell Job、shell 批次和显式文件选择的 S3 独立尝试。输入和输出保存于算例自己的 `.vibeflow/attempts/{attempt_id}/` 前缀；本地目录是执行缓存，活动算例文件不会因普通 shell 作业而被自动覆盖或删除。后续已接通[通用类型命令发布及结果引用](s3-typed-publication.md)，正式专业处理器继续迁移；默认部署保持 fs，`allow_partial_s3` 限制没有解除。

## 已接通的行为

提交时枚举所选远端用户文件，排除执行元数据，检查路径、大小、数量和便携文件名冲突。下载使用对象 ETag 条件，并在封存前后重验选择；输入文件 SHA-256、目录清单、远端版本、存储目标与 case/Job/attempt 归属写入数据库清单。每个封存对象使用 `If-None-Match: *` 创建；已有相同内容可重试，已有不同内容不能覆盖。远端清单最后上传，只有已提交的数据库记录能够授权执行；孤立对象前缀不能成为作业。

另一 API/worker 使用独立本地目录时，会从数据库绑定的远端清单和对象重新构建封存缓存，逐一检查哈希。重试继续使用旧尝试的输入，当前编辑不会混入；已执行目录丢失时，不能把输入副本当作输出补交。缓存重建不意味着未知旧进程可以跨主机自动接管，进程归属规则继续生效。

原生进程退出后，先将完整输出清单和 `object_store.state=pending` 保存到数据库，再上传各个私有输出和最终清单。全部上传成功才记录 `complete`。成功终态提交前重新验证远端清单、文件集合和所有文件哈希；一部分上传成功、产物被改坏或远端清单缺失，都不能成为成功作业。失败和取消的部分结果仍留在私有目录；上传中断保留清单和本地证据，自动补传/恢复留待后续 N5。

作业日志上传到原 Job 日志路径，新的 API 能读取历史日志和私有输出。普通文件编辑接口继续拒绝修改执行版本。旧类型命令、终端等尚使用的 staging 适配器不再复制、上传或删除 `.vibeflow/attempts` 和 `.vibeflow/publications`，避免旧同步路径改写新版本。

## 实际验证与兼容问题

使用仓库已有 SeaweedFS 3.99 二进制，在 WSL `nobody` 下启动专用临时服务，使用独立随机端口、bucket 和数据目录；验证结束后核对进程出生标识、UID、cwd、可执行文件再停止。未访问开发 bucket、迁移开发数据库或重启端口 8000。

真实 SeaweedFS 验证了条件创建拒绝覆盖、非空对象条件读取、默认输入封存、显式选择、真实 Windows/WSL 执行、同名批次隔离、取消、超时、原输入重试、独立缓存 API 的历史读取、输入变化/损坏拒绝、部分上传保留，以及远端输出损坏不能成功提交。最终专项 14 项；fs 默认隔离、旧 staging 和启动续租兼容结果见 `tmp/mainline-N2-s3-attempt-evidence/`。

兼容核对同时修复两处旧问题：提交请求遇到另一事务已取消的作业时，刷新 Job 后再返回，避免 `status=queued` 与 `phase=cancelled` 矛盾；staging 删除不再忽略 Windows 错误，使用有范围检查的删除/有限重试，并在目录确实删除后才移除来源清单。旧续租夹具调整为允许“返回已取消的 Job”或“启动绑定失效被拒绝”两种实际响应；完成阶段的提交响应可能早于取消发生，所有实际进程退出、线程排空、原文件保留断言继续执行。

发现并保留了两次真实失败：该版本 SeaweedFS 对空对象即使提供它自己返回的正确 ETag，也会令条件 GET 返回 412，修改引号并不能解决。当前仅对已知大小为零的对象执行有界普通 GET，并检查响应 ETag、读取大小和封存前后远端清单。非空对象继续使用条件 GET；没有忽略输入变化。测试服务最初使用系统分配的高端口，SeaweedFS 默认 `port+10000` 的 gRPC 端口越界，后来为所有 gRPC 监听显式分配独立端口。
