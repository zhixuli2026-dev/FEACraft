# PDF 页码的独立执行与版本化发布

继续N2-03/N2-05/N2-06迁移旧专业入口。本地fs下`pdf:number`现在使用静态注册的`pdf.number`处理器，共有10个注册处理器。准入封存所选PDF，执行器在自己的attempt目录调用原页码工具；源PDF与活动算例不会被原生工具直接改写。S3路径仍沿用旧staging入口，未宣称已完成其迁移。

固定worker命令绑定输入、输出和唯一execution ID；准备记录原worker与页码实现文件哈希。worker完成时写入本次attempt/case/job、输入与输出哈希、页数及实际工具文件哈希回执。处理器独立读取真实PDF，核验页数、每页末尾的实际编号内容流以及封存来源，退出码0或旧输出存在都不足以发布。原始回执保存在不可变bundle清单中，私有运行回执不复制到活动算例。

每个输出路径有独立发布通道和代次，使用现有文件journal、最终来源校验、DB/head/outbox事务及别名恢复。页码输出仍保持原下载路径，原“不覆盖源文件或已有目标”的约束也保留。准备时拒绝已有目标，发布前在算例校验占用下再次确认目标不存在，兼容文件计划也只允许原目标为空；期间用户新写的目标受到保护。请求幂等摘要保持原endpoint/payload语义，重复请求返回原Job，不因输出已生成而重新启动。

输出不存在是**提交条件**，不是输入依赖。最初实现把它放入来源快照，使成功生成自己的别名后，该PDF被后续作业错误判作过期；真实publication输入引用请求复现409后，已将这项检查移到`before_publish`。最终双库验证发布的PDF仍可作为后续作业的当前输入，同时保留目标冲突拒绝。

故障验收使用真实PDF：正常发布、页数/元数据/标签/源字节保留、幂等及独占目标、后续当前版本引用、无效PDF、损坏worker回执、运行期间来源修改、目标修改、取消排空、API在复制前退出后继续原attempt与产物。SQLite/PostgreSQL各10项通过。原PDF页码套件也在隔离API重新通过，包括真实LaTeX生成的两页带文字源文件及原下载/覆盖/路径断言。首轮取消夹具提前读取`cancelling`状态的失败与后续原断言复验、错误来源判定的复现分别保留。

证据见`tmp/mainline-N2-pdf-publication-evidence/`。本批只迁移一个旧专业入口，不关闭N2-03/N2-05/N2-06；PPT、其余专业执行器、S3、全部工具链与跨步骤交付仍按原计划推进。主线20完成/14进行中/19待开始，剩33；295项全功能严格最终验收仍0。
