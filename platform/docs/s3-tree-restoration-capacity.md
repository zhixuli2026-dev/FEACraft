# S3 目录树恢复的内存与节点空间

2026-11-18，RB-12 已补齐 S3 目录恢复的批量正文读取和事务临时副本准入。原来每份修改后的快照文件都作为字节串保留在变更表里，直到整批进入远端事务。现在变更表保存路径、长度和 SHA-256。发布前逐文件预检，上传时重新打开并验证同一个文件句柄，上传结束后核对该句柄与源路径的文件身份。私有对象上传后还须通过远端摘要校验，才可发布事务。

替换原 S3 文件前，服务使用同一次 HEAD 得到的版本和长度申请节点空间，再按该 ETag 读取旧内容。安装新版本、对账或回滚时，临时文件使用配置的本地存储根，按目标对象大小预留到文件关闭。单个事务按顺序处理对象，系统默认临时目录不再承接这些副本。

| SeaweedFS / SQLite | 8 个 3 MiB 文件和 1 个空文件 | 2,122,080 B | 3 MiB |

这是预检的 tracemalloc 数据，整台机器的内存和远端存储用量另计。两组分别观察了 17 个实际临时文件，逐个核对创建目录、打开时的节点预留和关闭前的大小，最终预留为零。[SQLite](../../tmp/live-cli-startup-fohl0ft2/s3-tree-capacity.json) · [PostgreSQL](../../tmp/live-cli-startup-16l16azq/s3-tree-capacity.json)
