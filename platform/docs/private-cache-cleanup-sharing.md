## 行为变化

缓存写入和清理共用进程内互斥锁。清理先等待已启动的读写及读取线程池完成，再永久关闭该对象的写入口。当前 owner 清理需要原 Cache 对象、原 owner 记录、当前真实进程出生身份及关闭状态共同匹配；后台回收仍须核验 owner 已退出，不推断其他进程的写者已经停止。

清理复用完整日志/摘要预检，拒绝未知文件、目录、改字节或归属变化。先删除可核验数据，再处理 owner/journal。Windows 最后阶段通过实际 DELETE 访问句柄保护容器及两份元数据，核对同一打开对象的身份与字节，在删除前保留两份凭据。原递归删除没有这个顺序保证；修复前的本机共享锁反例中 owner/journal 实际仍在，不能把潜在顺序风险说成该轮已观察到的元数据丢失。

只有已验证 owner 后实际遇到的 WinError32/33 会有界重试并返回 retained。原目录和实际字节仍在，日志明确记录延后；不会称目录已删除，也不会仅因这类缓存删除失败把有效来源判成 input_stale。未知身份、内容和其他错误继续拒绝。原对象可在锁解除后重试；若对象已释放，后台回收继续等待原 owner 退出。因此长期持锁可能保留容量到 API 退出，不能声称后台会删除活跃 owner 的缓存。
