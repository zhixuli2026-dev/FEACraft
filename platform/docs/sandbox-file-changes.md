# 沙箱文件改动恢复

2026-11-16。承接 N4-05 / RB-12、FF-F58、FF-J16。原 53 项主线和 295 项交付范围保持；这一增量不代替目录、类型互换、权限及 caseDict 的完整恢复。

新沙箱在允许终端输入前，将实际初始清单的摘要、长度、来源、会话、镜像目录及原生身份登记到数据库事件中。清单包含文件内容摘要、目录和权限；恢复请求先核对已登记摘要，再将初始清单复制到独立恢复目录。读取恢复快照时复核数据库绑定与该副本，因此不能把事后补造的旧 `initial.json` 当作可信基线。旧快照没有已登记基线时继续提供原来的选中文件内容写回，不自动升级。

“比较并恢复沙箱文件改动”比较初始副本、恢复快照和当前项目。沙箱未修改的文件保留当前版本；当前项目仍等于初始版本时可应用沙箱改动；当前项目已等于目标版本时不重复写入；双方均修改且内容不同则返回冲突，整批不提交。用户可以取消选择冲突文件，再预览其余改动。删除也以同样的三方比较处理，不能根据快照里没有某个文件就删除用户后来新增的文件。

恢复仍需明确选择、影响预览、确认和持久请求标识。新文件改动模式单批最多 10,000 个文件，受快照 128 MiB、备份与目标合计 256 MiB、日志清单 8 MiB 等原有资源边界约束；普通内容写回继续保持 256 个文件的限制。大批量模式复用 FS/S3 文件事务及 SQL 提交见证，不拆成会部分成功的多次提交。重复确认返回原回执，不能覆盖恢复后的新编辑。网页文件列表和影响列表各按 20 项分页。

接口沿用 `/terminal/sessions/{sid}/recoveries/{identifier}/restore-plan`、`/restore` 与 `/restores/{request_id}`，新增 `semantics: sandbox_file_changes`；默认与原 `file_contents_only` 保持兼容。`GET /changes` 返回基线摘要、沙箱文件改动及目录/权限变化。`recovery_baseline_missing` 明确表示旧快照没有可信基线；`recovery_merge_conflict` 表示项目与沙箱修改冲突。回执明确列出删除文件，目录与权限恢复标志仍为 `false`。
