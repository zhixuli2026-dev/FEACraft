# 同主机共享索引与重建

## 配置

生产 Compose 的 API 与 arq-worker 都使用 `VIBEFLOW_INDEX_ROOT=/data/index`，并挂载同一个命名卷 `indexdata:/data/index`。它们同时共用业务数据库和 `casedata`。此前索引默认落在各自容器的 `/app/data/index`，消费者更新自己的索引不能代表另一个实例的索引已更新；本次直接补齐共享卷，不增加复制服务。

本机直接运行多个 API 时，让各实例的 `VIBEFLOW_INDEX_ROOT` 指向同一个绝对目录，同时使用一致的业务数据库和文件根目录。部署密钥与运行配置仍按各自说明共享。只统一索引路径、却连接不同数据库或文件库，不是有效部署。

本次范围是同主机、同一本地文件系统的共享索引。不要把该 SQLite WAL 目录挂到任意网络文件系统上就宣称跨主机通过，也不要把多个独立本地索引的 outbox 回执视为全部副本已更新。跨物理主机拓扑及独立副本仍需单独实现和验收。

## 使用与检查

算例索引按需开启。使用有权限的账户调用 `POST /api/v1/cases/{case_id}/index:rebuild`，随后通过 `GET /api/v1/cases/{case_id}/index/status` 检查 `indexed`、`entries` 和 `building_uuid`；`GET /api/v1/cases/{case_id}/search?q=关键字` 查询当前内容。

开启后，已有持久事件消费者在索引事务中一并提交当前文件投影和事件回执，之后确认 outbox。未开启的索引不会因为文件写入自动启用。业务数据仍是文件/对象及业务数据库，索引不是数据备份。

多实例核对时，应先查消费回执和索引内容，再发起搜索：现有搜索入口会主动对账，单凭搜索正确不能证明另一个进程消费了事件。

## 索引卷丢失后的恢复

1. 停止新工作，等待活动作业完成；停止共用该目录的所有 API/worker。保留数据库、算例文件、原密钥及运行配置。
2. 若旧索引损坏，先保留旧目录作为证据，再配置一个空的本地索引目录。不要在线只复制或删除 SQLite 主文件，遗漏 WAL 文件。
3. 启动使用同一业务数据库与原文件库的实例。索引尚未重建时，状态应为 `indexed:false`，搜索返回未就绪；算例原文件应仍可读取。
4. 对需要搜索的算例调用现有 `index:rebuild`，核对状态、文件内容及搜索结果，再恢复其他实例。

重建读取当前文件，不重放历史文件写入，也不恢复已删除的业务数据。丢失索引可以重建；丢失算例、版本对象或数据库必须走相应数据恢复流程。原存储版本保留、回收与混合版本运维仍是 N7-05 的单独交付内容。

## 验收入口

`platform/server/live_llm_shared_index_acceptance.py` 是显式真实模型入口，执行前要求审查清单逐文件 SHA-256 匹配。它启动实际隔离 API、使用实际文件和 SQLite，暂停写入端的后台投递以证明另一进程实际消费事件，再验证重启、索引重建以及真实 DeepSeek 工具回读。HTTP 观察器转发真实请求，不替代模型或工具结果。

Compose 检查通过实际 `docker compose config` 渲染验证两个服务的同名卷和路径；这不等同 Docker 整栈启动通过。实际运行结果见本次交付状态与对应 evidence 文件。

2026-11-16 最终整轮通过：`tmp/live-shared-index-s_98aggj/shared-index-result.json`。写入端与消费端实际同时运行，先查事件消费回执和索引内容，再检查两端搜索；消费端重启后继续消费下一次写入。全部实例退出后保留旧索引目录，用空目录启动、重建，原文件保持不变。四次实际 API 服务进程身份均确认退出。

最终真实 DeepSeek `deepseek-flash` 调用 2 次，HTTP 均为 200，8,493 tokens，实际选择 `read_text_file` 后回复提示词中未给出的随机内容。前一轮也有 2 次真实调用、8,559 tokens，功能通过但即时退出断言失败，故保留失败结果；首轮目录移动失败、模型未调用。三轮合计真实调用 4 次、17,052 tokens，模拟 0。修正仅在验收脚本：显式关闭 SQLite 检查连接、终止自身 API 树并等待实际服务进程退出；产品仅增加共享目录配置。

当前实证是同主机、共享 SQLite 业务库/文件库/索引的两个实际 API，以及生产 Compose 12 组配置检查。未将其表述为本轮 PostgreSQL、arq-worker 整栈或跨物理主机验收。N7-05 第一组“共享目录或跨主机副本”的共享目录分支完成；正式目标环境的整栈条件继续留在原部署验收项中。
