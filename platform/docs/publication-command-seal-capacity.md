# 作业引用发布成果的输入封存

2026-11-22，公开单作业入口 `POST /api/v1/cases/{case_id}/jobs` 的 `input_publications` 改为先核验归档、再绑定作业。可选整份成果或指定文件，可混合独立的算例文件。普通命令和类型化命令的显式成果引用沿用相同的归档规则。当前引用验证活动发布版本及递归依赖，历史引用只读指定的不可变版本。

准备阶段关闭原 SQL 会话的事务。文件系统复用两份作业副本的总峰值核算与节点预留。S3 在算例存储租约下复用已有对象封存、账户峰值检查和恢复日志。提交时重新核对授权、归档及当前来源的文件或对象版本，以及发布行、活动指针和依赖的数据库读取记录。相同幂等键可回读已提交的作业。

SQLite 对照使用非特权 WSL 生成 40 MiB 发布成果。暂停在实际摘要校验结束后时，旧实现的数据库写入被挡住。本地同算例保存返回 409，S3 同账户另案保存等待原请求释放。修复后，文件系统、认证 SeaweedFS 分别搭配 SQLite、PostgreSQL 的四组测试均允许独立数据库写入。本地同算例保存和 S3 同账户另案保存均返回 200。两个已发布版本在真实 WSL 中核对完整 SHA-256。路径重叠和跨算例引用返回 400，过期版本和等长归档替换返回 409。历史复用和原幂等键回读均保留原成果。两个 S3 初轮以 2 秒等待上限采样，正常另案写入超过探针上限，失败作为单独记录保留。首轮另发现 S3 租约仅附带算例最小身份，已补短会话读取完整算例记录。

本地 SQLite 通过实际读取期间达到测试期限和客户端断开。先等待存档读取线程退出，期限返回 504，断开后没有产生作业。按原键重试通过，私有暂存和节点预留已回收。实际封存两份 40 MiB 副本后达到 83,898,320 字节节点预留。此时另一个请求改变当前来源，提交返回 409，恢复源内容后原键的 WSL 重试成功。

S3 使用现有归档读取缓存，旧对象存储仍有原兼容入口。本次验收使用认证 SeaweedFS 4.52 和本机 WSL。模型调用为 0，相关故障场景只暂停真实存储阶段。回退时先排空在途提交，再用已有封存日志核对和收尾，随后撤回公开入口的准备接线。证据纳入 N4-05 的 RB-12 和 RB-14。 [验收记录](../../tmp/N4-05-publication-command-seal-20261122/validation.json)
