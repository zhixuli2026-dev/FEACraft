# 工作流分页、事件查询与读取完整性

2026-11-11，N6-03本段完成；整项仍在实施，主线39/53、剩14项。

| API（均在`/api/v1`下） | 行为 |
| --- | --- |
| `GET /cases/{id}/workflow-runs-page?limit=50&cursor=...&status=...&target=...` | 返回`items`和`next_cursor`，创建时间/ID倒序；每页1～100条，末页游标null |
| `GET /workflow-runs/{id}/events?after=0&limit=100` | 单流程已持久化事件，case序号升序；每页1～200条 |

原`GET /cases/{id}/workflow-runs`仍返回最近50条数组，已有调用保持兼容。新分页游标绑定case和筛选条件，包含UTC时间及UUID，不是授权凭据；先验证访问权限，再解析游标。相同时间的记录按ID稳定翻页，错误游标或变更筛选返回409 `invalid_cursor`，非法分页参数422。

事件读取先检查流程归属，再同时限制case和run_id，并复核原事件的step/attempt关联。返回稳定event_id、case序号、关联ID和原载荷，保留既有envelope。水位为case已提交事件最大序号，流程之间的序号间隔合法；读尽本流程已提交窗口后游标推进至该水位。游标超前返回409 `event_cursor_ahead`。

成功作业的完成可见性仍待核验时，事件页在该记录前停下，`blocked:true`，不跳过它推进游标；恢复原完成状态后可从原游标继续。损坏或非对象载荷、无法核验的关联及不允许公开的凭据字段返回409 `evidence_invalid`，不伪造空事件。

工作流详情对损坏计划、输入、步骤输出及尝试输入/输出返回明确409，而非500。计划步骤与数据库必须一致；当前尝试必须属于对应步骤及同case作业。相同归属检查也用于变更路径，先拒绝损坏关联，再进入派发或取消。恢复方案仍可显示无法核验原流程的身份，保持人工处置限制。
