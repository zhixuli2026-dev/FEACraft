# 旧算例后处理的独立执行与报告兼容

本地 fs 的 `/postprocess:run` 在没有 solve 发布记录时，使用 `postprocess.case` 处理器。它封存 caseDict、所选 OpenFOAM 运行目录和参考文件，由原数值执行器在自己的 attempt 副本内提取指标及图件。配置根据封存参数在私有目录生成，不再在创建 Job 前写入共享 `.vibeflow/jobs/postprocess-*-config.json`。显式 run_dir 覆盖保留。

处理器记录 case 文件来源，发布描述为 `postprocess-case.v1`；不为旧文件伪造已确认的求解发布。原 `postprocess.run` 处理器和工作流仍要求当前 solve/mesh 发布。旧文件来源包含实际输入场、网格和全部相关时刻目录的清单/哈希；字段修改、增加或删除时间文件都会使成果过期。算例建立 solve 发布通道后，旧文件来源失效，新请求必须使用对应的求解发布；已有幂等请求仍返回原 Job。

产物沿用已有独立数值重算验证、不可变 bundle、发布代次、head/outbox 提交和兼容路径恢复。指标、图表、配置、来源清单和工具链绑定本次 attempt。普通成功生成、诊断性的 report_ready=false、取消、失败和输入过期保持各自含义；诊断产物可以读取，但不能据此推进报告。旧结果按 Job 或 publication 查询时继续可读，当前状态明确标记过期。

报告消费者一起迁移：独立 compose、HTML/DOCX 和 LaTeX 可以引用 `postprocess-case.v1`，继续校验原工程证据并封存旧网格质量等文件。它们不会因为旧算例缺少新版 mesh 发布记录而被无条件拒绝。新编排工作流的 report 处理器依旧要求 `postprocess.v1` 和当前 mesh 版本，两种来源不能互相冒充。文档的引用记录会把后处理换版传播为过期。

验证证据保存到 `tmp/mainline-N2-legacy-postprocess-evidence/`：原完整后处理数值套件、原注册后处理工作流、双 API 幂等准入，以及真实热传导字段的新隔离/历史/报告链和故障场景。首轮新夹具要求报告显示字符串 `350`，但求解值实际为约 `349.999999944`；独立数值容差已通过，文本断言修正为保留原数值，未改写产品结果或放宽数值验收。

注册工作流的原 superseded 并发夹具还暴露了时序不兼容：旧原生进程一直被暂停，同时等待新作业成功；已有算例来源校验必须等待全部写者排空，导致旧作业先达到 120 秒预算，原“旧成功被取代”断言失败。与上批归档比较，来源校验、case 占用、停止证明和 Job 收尾代码均未变。夹具现在在真实进程停止、保存排空证明之后暂停旧终态提交，再让新版本完成；旧成功被取代和迟到失败不回退新结果的原断言保留。参考变更、配置变更和取消仍在原生执行阶段注入。
