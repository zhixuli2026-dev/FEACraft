## 实现与授权边界

`staging_sync.sync_checked` 共用分阶段执行流程；旧作业仍通过 `sync_job` 校验作业归属和状态，交互入口通过 `sync_authorized` 取得算例控制锁后调用各自授权函数。调用方不再保留跨越整个同步的数据库会话。

| 入口 | 每个同步检查点核对的条件 |
| --- | --- |
| 终端 | 用户/算例访问权、原来源绑定、当前终端 owner 和启动 nonce |
| 可视化 | 用户/算例访问权、原来源绑定、当前可视化 owner 和启动 nonce |
| Agent Shell | 取消信号、已领取工具调用、会话权限、命令参数/来源、原生请求 owner、可用时的会话执行 owner、工作目录 |
| CLI | 用户/会话/算例授权与已选配置、仍适用的启动保护、CLI owner/进程身份/选择摘要、工作目录和来源 |

初始事务会处理上一笔文件日志；正式写入前、每个文件开始前及 SQL 提交前再次核对上述条件。长传输期间其他控制事务可以提交，不能依赖最初授权无限继续上传。当前文件不可取消的 I/O 仍须排空，之后才可发布排空证明或释放调用方资源。

仍沿用已有的原生进程停止核验。同步完整提交并发布排空证明后才清理副本；各入口的会话终态记录按原收尾顺序更新。同步失败、归属变化、来源冲突和清理失败均保留相应副本与证明，不把失败关闭伪装成成功。

旧 `staging_sync.sync(db, case, stage)` 保留为事务协议兼容夹具入口。产品代码搜索已确认四类交互调用使用 `sync_authorized`，旧作业使用 `sync_job`，没有产品入口继续调用长事务版本。
