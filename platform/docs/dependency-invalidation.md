## 返回契约

`schema` 为 `vibeflow.dependencies.v1`。`channels` 包含 geometry、mesh、solve、postprocess、report 五个主线成果及算例中其他已注册发布通道。`publications` 包含当前版本与被其引用的历史版本。`recompute` 按生产者在前的顺序列出缺失或已过期的通道；`needs_inspection` 列出无法确认有效性的通道。这个结果描述整条主线的缺口，尚不是选择某一目标后立即执行的调度计划。

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `fresh` | 不可变文件、成功 Job 归属、活动版本、来源及要求当前的依赖均通过检查 | 可以保留此成果；实际提交仍重新校验 |
| `stale` | 来源变化、被新版本替代、运行目录不匹配，或要求当前的上游已过期 | 列入重算范围 |
| `missing` | 没有活动发布，包括手工编辑产物别名后清空活动指针 | 列入生成范围 |
| `unverifiable` | 文件损坏、归属/处理器不符、来源不可检查、依赖环或选择的文件不存在 | 列入待检查项，不声称有效或自动执行 |

失效原因采用稳定的 `code`；来源变化只返回顶层来源字段名，不返回来源原值、文件内容或凭据。上游已经失效时，跳过依赖它的来源门禁，保留 `source_check=skipped_invalid_dependency`。这避免把报告因上游过期而拒绝检查误报成未知损坏，同时明确未进行该项检查。

`require_current=false` 的引用只检查所属算例、成功发布和选定不可变文件；上游后来变化不沿这条历史引用传播。它不表示可以引用损坏文件或其他用户的成果。要求当前的依赖按发布 ID 递归检查，共用祖先只计算一次来源。旧祖先过期只影响引用它的消费者，已有有效的新活动版本不会因此被要求重算。

## 一致性与边界

开始时在算例控制锁下记录 revision、事件序号及活动指针，然后释放事务，执行文件/S3/来源检查。结束时重新获取控制锁、重新检查读取权限并核对完整观察结果；有提交的输入/发布变更则返回 `409 dependency_changed`，其他读集变化沿用 `input_stale`。并发编辑可以在来源检查期间完成。

响应带 `advisory=true`：它不是执行许可或跨任意外部文件写者的原子快照。直接绕过应用修改文件的进程不受算例控制锁约束；提交、启动、阶段确认和最终发布仍使用原有封存与复验协议。最多检查 128 个发布节点/通道，递归深度沿用 16；超过限制明确拒绝，不返回截断后伪装完整的图。

检查的是不可变发布及当前来源。活动兼容文件的手工编辑通过现有 `artifact.invalidated` 清空活动指针。允许原生 typed command 发布自身 `.vibeflow/jobs` 证据，但禁止把这些执行元数据挂载为另一个任务的发布输入；零输出的合法 typed command 不被误判为损坏。

`caseDict` 的工程指纹仍采用现有规则：工作流状态、provenance 等记账字段不影响工程指纹；处理器独立关心报告/后处理配置。几何生成器可读取整个工程配置，因此部分 caseDict 工程变更会保守地令几何也过期。只修改运行目录中的网格文件、初始温度场或热扩散系数时，可保留几何，重算网格及后续链路。当前没有声称达到数学上最小的重算集合。
