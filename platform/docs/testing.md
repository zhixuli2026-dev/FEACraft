## 6. SKIP、网络与外部服务

- `distributed_queue_smoke.py` 仅在 `VIBEFLOW_TEST_DISTRIBUTED=1` 且 Redis+两个 worker 已启动时执行，默认单进程 SKIP；真实通过记录来自独立 Redis/arq 环境。
- `s3_jobs_smoke.py`、`s3_terminal_smoke.py`、`s3_viz_smoke.py`、`s3_index_smoke.py`、`s3_range_smoke.py` 仅在 `VIBEFLOW_TEST_S3=1` 且 SeaweedFS 已启动时执行，默认 fs SKIP；本轮通过记录来自独立 SeaweedFS 4.48。`s3_staging_smoke.py` 是默认执行的离线可控测试，不需要该服务。
- `cite_smoke.py` 在公共文献源不可达时按自身规则记 SKIP；SKIP 不等于该提供方功能验证成功。最近一次 Crossref 和 arXiv 均返回有效结果；历史 arXiv SKIP 只是当时网络状态。
- `cite_semantic_smoke.py` 的 MockTransport 部分必须通过；公共 Semantic Scholar 单独打印 `LIVE_OK` 或 `LIVE_LIMITED`。本次为 `LIVE_LIMITED`（最终 503），不能据此宣称在线检索已成功。
- 真实 LLM 不属于默认测试前置；mock 通过不代表真实 provider 的模型名、配额、网络和内容行为已复验。
- 工具权限分类器超时、服务未启动、WSL 缺件和测试断言失败要分开记录，不能统一写成“测试失败”或“测试通过”。

## 7. 测试数据与清理

- 测试会在开发库创建用户、profile、conversation、job 和 case；多数套件追求可重复运行，但不是零副作用。
- PTY/viz 应由测试显式关闭；若中途失败，检查会话列表和空闲回收。
- FTS、补全和求解产物属于可重建/测试产物，清理前确认路径，不要删除用户 case。
- 修改测试后同时检查是否泄露凭据、是否依赖固定用户 ID、是否会把测试指向真实外部服务。

## 8. 常见排错

| 现象 | 先检查 |
|---|---|
| 间歇 401/新接口 404 | 是否有多个 uvicorn 同时绑定 8000；请求可能落旧进程 |
| LLM 连接失败 | mock 8990 是否唯一且正在运行，profile 是否指向 mock |
| OpenFOAM 命令不存在或版本不符 | v2406 测试先 source `/usr/lib/openfoam/openfoam2406/etc/bashrc`；不要假设系统默认 1912 已切换 |
| UDF 段错误/混入另一套 OpenFOAM 库 | Windows 调用 WSL 执行带变量的 Bash 命令时使用 `wsl --exec bash -lc`，避免默认 shell 提前展开 `$LD_LIBRARY_PATH`；核对 `command -v icoFoam` 和加载库路径 |
| 回环 SCNET/viz/mock LLM 空 502 | 检查 HTTPX 是否继承系统代理；注册本地 kernel、SCNET 与回环 provider 使用 `trust_env=False`，公网 LLM provider 仍保留代理支持 |
| 终端挂载但无回显 | 是否先激活终端页签、WS token 是否有效、是否同一会话所有者 |
| viz proxy 404 | session 是否存活、sid 是否属于当前用户、token 是否过期 |
| 中文输出乱码 | Windows GBK 控制台；不要根据乱码判断断言内容 |
| E2E 旧登录态 | Edge profile 中 token 可能过期；区分页面 API 与 iframe proxy 的 token |
