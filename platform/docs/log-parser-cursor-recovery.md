# 求解日志首行尚未写完时的增量续读

作业刚启动时，日志可能只有 `Time = `，还没有换行。旧版解析服务返回偏移 0 和空前缀的 SHA-256，但客户端原样传回这对值会得到 HTTP 400。现在原样续读会等待完整行。第一行写完后，客户端可以用同一游标读到第一条时间记录。

公开接口仍接受无游标的首次请求。偏移 0 只接受空前缀指纹；非零偏移须有正确的前缀指纹且指向换行之后。消费过的内容发生重写或截断时返回 409。实现复用同一个摘要状态验证旧前缀和计算新游标，避免为已消费前缀重复分配和计算摘要。

在独立 API、SQLite 和文件存储中，通过 HTTP 核验了半行续读、错误零偏移指纹、行内偏移、并发读取、不同账户访问拒绝、重写、截断以及 smoothSolver 和 DILU 残差。此轮没有模型调用。FF-H05 仍待完整界面和交付验收。[API 验收记录](../../tmp/log-cursor-boundary-v0mmnz29/checks.log)
