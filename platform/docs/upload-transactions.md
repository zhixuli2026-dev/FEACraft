# 分块上传完成的提交证明与恢复

2026-11-05，N2-06 第五批。本地文件系统分块上传完成已接入事务日志。53 项主线维持 23 完成、11 进行中、19 待开始，剩 30 项；原 295 项功能范围完整保留。

## 完成与重试

收到全部分块后，完成请求在算例锁下核对暂存长度、可选 SHA-256、创建上传时的目标摘要以及受保护路径。流式复制暂存文件到文件事务的不可变新内容备份，复制前后校验摘要和文件身份；暂存源仍保留，不再直接 `os.replace(data.part, target)` 后立即删除上传目录。

文件日志证明和 `files.upload_completed` 事件与业务变化在同一 SQL 事务提交。完成事件使用由算例 ID 和上传 ID 派生的 UUID，保存路径、字节数、摘要、时间戳及暂存元数据摘要。没有新增数据库表或迁移。

| 情况 | 行为 |
| --- | --- |
| 应用前、部分应用后、SQL 提交前退出 | 下次协调访问恢复旧文件；原分块仍在，可重新完成 |
| 数据库提交成功，但响应丢失 | 读取既有完成证明，保留新文件并返回原完成结果 |
| 用户随后又编辑文件，再重试旧上传 | 返回旧上传的完成回执，不重复应用文件内容 |
| 恢复时目标出现第三方内容 | 返回恢复冲突，保留目标、日志和暂存内容 |
| 文件日志成功，完成事件写入失败 | 同一事务回滚，下次访问恢复旧文件，保留上传会话 |
| 清理失败或清理前进程退出 | 完成证明仍有效，重试可继续整理；失败返回 `cleanup_pending` |
| 已提交暂存内容被外部修改 | 保留现场，不按旧证明删除新内容；完成结果仍可查询 |

`GET /uploads/{id}` 对已完成会话返回 `status=completed` 和原摘要，即使暂存目录已清理。完成请求可重复；继续写块或取消已完成会话返回 409。事件 ID 按算例隔离，不能把一个算例的上传回执用于另一个算例。

## 大文件、取消与内部目录

暂存源通过 `FileSource` 进入本地日志，按块复制与计算摘要，不一次读入整份上传。单文件仍限制为 1 GiB，本地前后备份合计允许 2 GiB，避免原来合法的 1 GiB 覆盖上传因备份预算而失效。清单仍限制 1 MiB、最多 256 个目标；S3 普通文件日志的合计预算未改变。

本地日志的准备、应用、核验和恢复 I/O 已放入工作线程；取消先等待正在执行的文件操作结束，再释放 SQL 锁。Session 不进入线程。文件应用后的变更通知仍在调用者任务记录。原四种上传操作的重复取消约束继续保留。

`.vibeflow/uploads/` 加入普通 API 的内部目录保护，不能通过普通文件保存、删除或上传改写会话元数据。读取元数据有大小、身份、字段和链接检查；复制算例/工作区排除上传暂存目录，备份原来已有同样排除。提交后的清理只删除仍与提交证明相符、且没有额外文件的暂存目录。

## 证据与边界

规范目录：`tmp/mainline-N2-upload-transactions-evidence/`。SQLite 12 组中断/回滚/响应丢失/冲突及重试验证，另 3 组复制隔离、容量边界和清理冲突；PostgreSQL 8 组核心恢复验证。新增暂存校验期间尺寸变化和文件缺失的 2 组验证，单独保存增量证据。

容量检查使用 1 MiB 的等比例边界夹具验证旧+新两倍预算，并禁止针对 data.part 调用 `read_bytes`；这是流式路径和边界验证，不声称本轮实际传输了 1 GiB。普通上传与多段 Range 原兼容套件通过，上传取消两库各 4 项、普通文件日志 14 项、字典定向 4 项、记忆定向 4 项和持久事件兼容通过。字典定向命令首轮参数误写，未达到故障屏障，作为测试驱动失败保留；改用现有场景名后通过。

S3 普通文件日志的提交前中断和正常入口另 2 组兼容通过。上述证据是增量验证，不是一轮全库/全平台重跑。临时 PostgreSQL 数据库均删除，开发数据库和端口 8000 未变。后台自动扫描、历史日志和暂存配额回收仍未完成，保留待办；不会自动补传没有可核验提交证明的上传。
