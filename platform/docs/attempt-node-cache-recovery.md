# 旧节点缓存与封存日志安装恢复

2026-11-05，N2-06 第十三批。完成两个具体恢复入口：其他 API 已回滚远端对象后，原节点重新上线清理未提交的本地执行副本；本地封存日志安装中断后，恢复临时文件及尚未解除的安装硬链接。

## 旧节点执行副本

恢复扫描本机 `.vibeflow/attempts`，批量排除数据库中仍有所属 JobAttempt 的目录，避免逐个下载已提交作业的历史回执。对没有 SQL attempt 的目录读取远端回执，并核对算例、作业、attempt、存储绑定和封存清单。只有明确 `rolled_back`、没有 SQL 提交事件或 attempt、远端执行前缀仍为空的缓存才允许清理。

删除之前预检完整本地目录，拒绝额外文件、额外空目录、链接及被改动的字节；删除时逐文件复核，只移除已知空目录。已提交缓存、损坏回执和远端对象重新出现的情况保留。GET 诊断返回 `node_cache_pending`，POST 恢复返回 `node_cache_removed`；启动/周期维护调用同一入口，重复恢复无副作用。远端回执与对象不由此入口改写。

原待恢复计划的回滚现在也会清理 S3 节点上的已知空目录；此前只删本地文件、跳过空目录。目录预检同时覆盖原回滚入口。

## 日志安装

封存 pending/history 日志在建立正式文件之前，先记录包含文件摘要、正式路径、存储绑定和进程出生身份的 writing intent。进程退出后，恢复先处理 writing 残留，再读取正式 pending 计划。

文件只有一个链接时，按摘要校验清理；有两个链接时，必须证明另一条正是记录中的正式文件、两者指向同一文件且总链接数为二，才能移除临时链接。第三条链接、错误路径、内容变化和不明进程身份均保留。正式文件始终保留，后续由原 SQL 提交证明决定回滚或完成恢复。这解决了安装完成、临时链接尚未删除时进程被终止，导致正式日志因硬链接检查而无法读取的窗口。

没有记录的旧 writing 文件、部分写入及损坏记录继续诊断保留，不据时间猜测删除。创建算例使用的另一套暂存安装协议仍需单独补齐同类窗口；本次没有把它算成已解决。
