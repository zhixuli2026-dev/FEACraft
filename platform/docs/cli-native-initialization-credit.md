# 原生 CLI 初始化的持久用户额度预留

2026-11-08。接续 [运行期用户额度](cli-runtime-user-quota.md)。此前原生初始化只能在文件写入后检查额度。本次在真实桥接进程创建及初始化许可之前，为初始化负责写入的文件提交持久用户额度。

## 准入与结清

新增 `cli_initialization_reservations`，以 CLI 会话 ID 为主键，保存用户、冻结选择的哈希、峰值、剩余额度和结清回执。在 `records.create` 的父事务内执行用户额度检查并插入预留，提交后才允许创建桥接进程。后续所有用户存储准入会把这份 active 预留加入已占用额度。

初始化器在任何目录/文件写入之前，先编码 config.toml 与 owner.json；配置和 owner 各有 16 KiB 上界，实际写入相同的二进制字节，预留为两者实际编码长度之和。现有目录仍按最坏新增两份文件保守准入；本阶段隔离默认配置为 133 字节。目录本身沿用逻辑文件字节计量，不将其等同物理文件系统块配额。

收到真实 `prepared` 帧后，现有启动门重新核验 owner、桥接进程及冻结 profile，在放行 CLI 前提交 prepared 结清回执。真实停止/未启动回执可结清尚未完成的预留；配额准入还会有界对账最多 100 个已终止的会话。缺少停止证明、租约过期、绑定变化或原生目录配置已切换时不释放。不按 TTL、磁盘上出现文件或进程 PID 单独推断初始化结束。

新增表会影响删除会话：现有明确删除历史的 API 现在要求预留已核验结清，先删相应已结清预留再删除会话记录，保留原生私有文件；未结清或证据异常时返回 409。此操作不清理用户私有账户目录。

## 实际验收

显式入口 `platform/server/live_llm_cli_initialization_acceptance.py --source-profile-id 26 [--postgres --s3]`，最终 FS/SQLite、真实 SeaweedFS/PostgreSQL 各 **8 项实际基础设施检查，共 16 项**：

1. 创建进程和原生文件之前，独立数据库连接能读取已提交的完整预留。
2. 实际填充隔离文件，使剩余额度比已提交预留少 1 字节，下一次准入返回 429，预留保留。
3. 将隔离会话租约实际改为已过期，没有停止回执仍保留全额。
4. 未创建进程的真实关闭回执使预留结清。
5. 已登记的真实 Linux 桥接进程在初始化前取消，核验其退出后结清，原生文件未创建。
6. 真实初始化文件字节量等于预留，prepared 结清已提交之后才启动实际 Linux CLI。
7. 重复对账保持 prepared 回执不变、剩余额度为零。
8. 通过真实 DELETE 会话 API 删除已结清历史及关联预留，原生配置文件哈希不变。
