## 行为

节点容量与用户远程配额分别检查。缓存数据虽然保存在本机，也必须计入节点的实际占用；不能因为用户的 S3 额度足够就无限下载。

新增 `node_storage_budget.reserve`。同一存储根目录的进程通过短期 OS 文件锁协调准入，将完整分配字节数、进程出生身份及根目录绑定写入 `.node-storage-budget/{uuid}.json`。准入检查整个本地存储根目录的文件字节、其他未结束分配的占用记录，以及磁盘剩余空间。文件扫描沿用条目数和时间限制，拒绝无法确认的目录、链接、未知占用记录。锁只覆盖检查和记录安装，不覆盖网络下载。

占用记录持续到实际 I/O 结束。进程退出后，下次准入核对其身份并释放记录；已写下的文件仍在磁盘盘点中，不会按零使用量恢复。身份无法确认或不匹配的记录保留；损坏的记录阻止新分配。不会按 TTL 猜测写入结束，也不会自动删除缓存文件。

已覆盖的入口：

| 入口 | 分配前计入的字节 |
| --- | --- |
| `.attempt-sources`、`.case-read-views` | 所有者记录、每个输入文件及对应追加日志；在调用网络 reader 前准入 |
| S3 新尝试的本地封存 | inputs、run 两份数据与本地清单 |
| S3 重试/验证时恢复输入 | inputs、run 两份数据与远程清单的本地副本 |
| S3 发布依赖/历史结果恢复 | 发布文件及清单；在读取发布文件内容前准入 |

完整占用记录与已经落盘的部分可能同时计入，属于保守准入。并发任务可能需要比最终保留量更多的余量。容量检查不负责清除已完成的缓存；现有恢复工具仍按所有权和一致性证明处理可回收文件。

## 配置与错误

`VIBEFLOW_NODE_STORAGE_LIMIT_MB` 默认 10240，限制本地存储根目录的计费文件字节及在途分配。`VIBEFLOW_NODE_STORAGE_MIN_FREE_MB` 默认 256，保留文件系统可用空间。两者已加入 `.env.example`；没有修改现有开发环境配置。

容量不足返回 `node_storage_full`；无法确认用量返回 `node_storage_unavailable`，沿用项目冲突错误响应。先确认可安全清理的缓存或增加容量，再重试。不要通过删除未知占用记录绕过正在执行的写入。

## 验收

`node_storage_budget_smoke.py` 使用真实文件和跨进程占用，覆盖已有字节计量、分配前拒绝、进程退出后的残留字节、未知身份与损坏记录、独立磁盘余量检查、reader 失败及取消时 I/O 排空。磁盘剩余量不足用受控返回值注入验证，没有填满真实磁盘。

`--s3` 使用真实对象服务和隔离 HTTP API，覆盖普通来源下载、封存两份副本、失败封存恢复、独立节点重试恢复、发布结果恢复。专项 API 故意不运行原生作业；执行兼容由原 S3 作业套件证明。最终回执见 `../../tmp/mainline-node-storage-evidence/validation.json`。

首轮跨进程测试只终止了 Windows venv 启动器，真正 Python 写入进程仍存活，准入正确保留其占用。诊断确认启动器 PID 和所有者 PID 不同后，测试改为终止自有进程树。没有为了通过测试放宽进程身份核验。
