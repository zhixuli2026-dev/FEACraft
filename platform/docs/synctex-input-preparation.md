2026-11-22，N4-05 补齐 SyncTeX 启动前的读取路径。公开的 `POST /api/v1/cases/{case_id}/synctex:query` 在短事务内确认算例和选中发布。随后到有期限的读取池中准备 PDF 和 SyncTeX 索引。在启动原生查询前重新检查用户权限和选中版本。

## 查询结果的来源核验

原生定位结束后，接口先核验算例访问权限、发布身份和算例事件序号，再在数据库写锁之外分块核验归档和当前源文件。当前文件通过存储版本和 SHA-256 与归档对照，历史定位继续使用原发布的来源路径和摘要。认证 S3 的独立读取端直接核验归档对象，无需落地整套发布缓存。

返回前再核验权限、算例事件序号与发布绑定。核验期间通过算例 API 修改正文，原请求返回 `409 input_stale`。重新请求同一历史发布仍可定位，并显示当前源文件已变化。结果读取使用独立的请求期限，超时返回 504。接口保留旧版 PDF 和相邻索引的识别方式。

SQLite 搭配文件系统与认证 SeaweedFS 均通过实际 WSL 查询。重新定位 4,945,173 B 源文件时，两组都可提交同算例写入，并在写入后定位原发布第 7 行。文件系统对照复现了旧实现持有 SQLite 写锁。两组在结果核验停顿时返回 504，各仅产生一个原生查询记录，解除停顿后可重试。旧版入口用同一份实际编译的 PDF 和索引复验，错误 PDF 版本返回 409。模型调用 0。 [复验脚本](../../tmp/N4-05-synctex-result-20261122/check.py) · [阶段回执](../../tmp/N4-05-synctex-result-20261122/validation.json)
