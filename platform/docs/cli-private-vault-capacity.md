# CLI 私有脱敏缓存的写入峰值与可读性

2026-11-07，接续 [宿主运行期检查](cli-runtime-storage-observation.md)。`Secrets` 保存用户在原生交互中提交的秘密字段，用于后续输出脱敏；提供方凭据通过 ephemeral 路径参与脱敏，不因本改动自动写入该缓存。

## 实现

更新先合并去重并验证单条长度、128 个持久秘密值及实际加密结果的 1 MiB 上限。审批接口允许 64 个问题各 8 个答案，因此批量输入上限为 512，重复答案先去重后适用 128 个持久条目限制。完全未变化的合并不重写文件，也不申请新预留。

此前写入只检查条目数量，而读取拒绝超过 1 MiB 的密文，多字节字符可能造成写后不可读。现在在任何写盘前加密并检查实际密文长度，过大时保持旧缓存和密钥不变。

节点预留覆盖完整新密文和 44 字节 Fernet 密钥；宿主旧密文继续计入现有库存，因此替换期间的新旧文件峰值被计入。准入成功后再检查实际账户所在卷的剩余空间，再创建密钥、写入并 fsync 临时密文、原子替换，最后释放预留。替换失败清理该次临时文件，保留旧内容。读取从不创建密钥，已有密文丢失密钥时明确失败，不自动重新加密。

账户目录必须位于配置的宿主私有 users 根，或当前发行版已配置的 WSL 原生私有 users 根。路径、密钥及密文检查拒绝链接、重定向、硬链接与超大文件。跨 worker 的合并继续要求调用者持有既有用户行锁；本次没有把原子替换声称为无锁并发合并或任意断电持久性保证。

WSL 写入使用同一个宿主新增字节预留，并额外检查真实 UNC 目标卷可用空间；**WSL 已有原生目录总量尚未加入宿主库存**。这验证 WSL 缓存更新的新增峰值准入，不能代表完整 WSL 节点额度、用户配额或硬限制。WSL 原生测试目录均为本轮在 `/tmp/vibeflow-cli-vault-*` 下新建的隔离目录，未修改部署私有根。
