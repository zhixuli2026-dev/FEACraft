# 普通作业默认使用独立尝试目录

S3 更新：普通 shell、批次与显式文件选择已接入远端封存和私有输出，独立缓存 API 可读取历史并按原输入重试。下文初次验收中的 S3 staging 边界已由[S3 尝试对象](s3-attempt-objects.md)补充；专业发布与完整 S3 范围仍待交付。

2026-11-05 更新：本地通用 `/jobs` 的五种非 shell 类型已完成独立执行与结果发布，含 `run_dir` 求解证据；下文“旧非 shell 继续原行为”是本文件初次验收时的边界，已由[类型命令发布](typed-command-publication.md)补充。旧内部绝对路径 argv、S3 与完整工具链范围仍未完成。

本批继续N2-03，不关闭该大项。本地fs存储下，不指定`input_paths`/`input_publications`的普通shell Job、shell批次各项与非注册shell工作流步骤现在默认封存算例用户文件，在每次attempt自己的`inputs`与`run`目录执行。`.vibeflow`运行元数据、旧日志、历史attempt/bundle不会递归复制进新输入。复制前后核对根目录选择、文件哈希和目录清单，保留初始场、用户原件及空目录；输出只留在该attempt，不自动回写活动算例。

客户端显式选择输入和publication引用时继续原范围。执行清单的`source.selection_mode`记录`case`或`explicit`；普通失败作业的重试从原封存输入创建新目录，当前编辑不会暗中替换重试输入。请求幂等重放返回原Job/attempt，不再次封存或启动。批次中每项独立复制和输出，即使写入同名文件也不会互相覆盖。

Job详情的`attempt.workspace`/`attempt.outputs`提供输入与输出清单，原算例raw下载接口可读取拥有者的attempt文件；普通编辑、上传和删除不能修改封存或尝试目录。专用产物浏览界面仍按N2-07/N6交付。

默认隔离让普通作业也进入原有来源校验协议。如果算例中有终态历史作业缺少停止/排空证明，或前次发布未完成，新默认作业现在在提交阶段返回409 `recovery_required`，事务回滚且不启动进程；不先运行后卡在finalizing。该历史没有被自动认作安全、删除或伪造证明，需要既有恢复诊断与后续N5人工入口处理。新协议下完成的作业和从未领取的取消项不阻塞后续默认尝试。

明确边界：旧非shell类型的通用Job/批次、`run_dir`求解证据与11个未迁移专业执行器继续原行为，需连同其当前路径消费者一起迁移，不能只换cwd而让派生求解结果从旧消费者消失；显式封存的非shell作业仍支持原独立目录。S3继续现有staging同步，尚未支持默认封存；任意shell的操作系统级隔离由N4负责，独立cwd不能阻止绝对路径写入。所有工具链/外部依赖登记、旧专业入口迁移及原N2-03验收范围仍保留，不能把此批普通入口交付当作全范围完成。

当前专项使用真实Windows/WSL与SQLite/PostgreSQL验证默认并发、初始场保留、同名批次输出、幂等、原封存重试、显式选择、输出归属和旧无证明记录的提交前拒绝。旧执行夹具原来把迁移用的无停止证明Job放在正在执行的case：已验收基线中的显式工作区套件也会被该记录阻断，而原非隔离调度套件尚未触发这个校验。夹具现保留旧Job于独立历史case，不改原执行断言；新专项另直接断言同case旧无证明记录仍拒绝新执行。各次失败与最终结果分别保存。
