## 行为与证据约束

明确确认镜像清理时，先检查旧清理请求。仍活动或停止记录不完整的请求必须实际核验 API 所有者、已登记 Windows 启动进程和 Linux gate 的出生身份，全部返回 `exited` 才能继续。耗时进程查询在算例锁外执行，提交前重新授权并核对完整行指纹及原清理意图。

独立事件 `terminal.image_cleanup_abandoned` 使用请求 ID 派生的固定事件 ID，绑定核验前后行指纹、原字段值、清理意图和全部实际观察。事务中将旧请求设为失败或保留取消状态、递增版本，阻止其重新放行；不修改子进程日志、原生结果和退出码，不把独立退出证据冒充正常停止回执。重复对账校验同一事件，不重复创建。

重试使用新的已登记原生请求。原镜像已经删除时，新的回执如实返回 `deleted_this_request:false`；仍需实际核验旧进程退出、镜像缺失和保留快照。完成查询、重试、来源校验及管理准入都会校验旧请求的独立证明；证明损坏不能继续放行。

GET 只查询，不执行对账或删除。界面在发送 POST 前保存确认意图；请求断线后保持结果待确认，重开只 GET，用户明确点击重试才再次 POST。删除前说明不能再从原镜像创建快照，完成后说明保留快照仍可下载和写回。暂存清理成功文案不再假定原镜像永远保留。
